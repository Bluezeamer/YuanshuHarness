# 决策档流程

适用：命中"难逆"信号（数据形状、对外契约、鉴权、新外部依赖、与 ADR 冲突）。
这一档的人工闸门最多，因为难逆的错没有事后补救的机会。

## 步骤与闸门

1. **起草 intent**（[assets/intent.md](../assets/intent.md)），`Lane: decide`。写明触及了哪个难逆点，并列出**决策点清单**：逐条编号，标注难逆 / 易逆。
   **G1**：人确认 intent 与档位。
2. **逐条 ADR。** 每个难逆决策点：
   - 给出 2–3 个候选，各自说明代价与适用条件；能实测的用实测证据支撑（例如用最小实验复现某个方案的失效），不凭推断。
   - 等人拍板，再按 ADR 模板成文。人是唯一的决策者。
   - 定稿时，**同一次提交**更新 ARCHITECTURE / ROADMAP 里指向它的链接；取代旧决策时，新 ADR 头部写"取代"，旧 ADR 改为"已废弃"并回链。
   - 易逆的决策不在此处定，推迟到 spec。

   **G2**：每份 ADR 人明确说"定稿"。
3. **spec**（[assets/spec.md](../assets/spec.md)）。决策已在 ADR 里，spec 引用不复述。必须包含存量数据的**迁移与兼容策略**（例如读侧兼容旧形状、写侧升级）。
   **G3**：人审 spec。
4. **plan**（[assets/plan.md](../assets/plan.md)）。在 plan mode 里读代码，不改代码，工程师修正后提交。必须有 **Rollback** 一节——难逆变更的实现顺序与退路本身就需要被审。
   **G4**：代码生成之前。
5. **实现。** 如果同时命中"静默"信号（迁移几乎总是），读 [hardening.md](hardening.md) 并执行。
6. **评审。** 实现完成后，按 [review.md](review.md) 新开空上下文的 subagent 评审，每轮新开一个，直到没有阻塞级问题。
7. **MR。** 由 code owner（人）最终评审；变更触及的 ARCHITECTURE / ROADMAP 在同一个 MR 内更新。
8. **关闭。** `Status: closed`，整夹移入 `docs/intent/done/`。

## 为什么 plan 在这一档保留

标准档里 plan 是可选的，因为实现路径通常显而易见。难逆变更不同：迁移先后、双写窗口、回滚点都是决策的一部分，写代码之前让工程师审一遍，比事后在评审里发现便宜得多。
