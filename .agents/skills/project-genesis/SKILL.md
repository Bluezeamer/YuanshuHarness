# 项目创世（Stage 0）

将一个口头想法转化为一套宏观工件，并产出首个 intent.md，然后**退出**：此后一切变更由 aisdlc 技能接管。
本技能一个项目只跑一次，不占用日常变更的上下文。

## 全局纪律

1. 所有工件草稿**先以对话形式呈现给用户审阅**，用户明确确认后才写入文件并提交 git；
2. 每个阶段末尾有显式闸门，未通过闸门不得进入下一阶段；
3. VISION / ARCHITECTURE / ROADMAP / ADR 使用本技能 templates/ 目录下的模板，保持格式稳定；intent 使用 aisdlc 技能的模板（本技能需与 aisdlc 配套安装）；
4. 宏观工件要克制：只定难逆的决策，易逆的细节留给后续 intent 的 spec.md；
5. 不确定性与「不做什么」是最有价值的信息，必须显式记录；
6. **链接纪律**：工件之间必须显式互链，形成可追溯链条（见下节）。

## 目录结构约定

所有过程文档收拢在 `docs/` 下管理，不散落在仓库根目录。进入创世时就按下面的树把目录建好（空目录放 `.gitkeep` 才进得了 git），后续工件落进对应位置：

```
docs/
├── genesis/            # 宏观工件（慢变量）
│   ├── VISION.md       # 创世后冻结
│   ├── ARCHITECTURE.md # 快照：边界与选型，不记录行为
│   └── adr/            # ADR 序列，只增不改（取代，不改写）
├── ROADMAP.md          # 方向文档：能力演进序列，团队级，慢变量
├── intent/             # 变更循环（快变量），布局与规则见 aisdlc 技能
│   ├── inbox/          # 给人用的随手记：零散的想法先记在这里，时机合适时转换成intent
│   ├── active/<YYMMDD>-<slug>/   # 进行中，只需创建active
│   └── done/<YYMMDD>-<slug>/     # 已关闭，只需创建done
└── lanes/<lane>/       # 快车道，只需创建lanes
```

项目内沉淀的提示词资产（把阶段提示词封装成 skill）不是过程文档，不放在 `docs/` 下，而放在仓库根的 `.agents/skills/<名称>/SKILL.md`，随仓库版本化。
这是各 harness 通行的项目级技能位置，harness 靠它发现技能并注入提示词，放进 `docs/` 就不会生效。创世时一并建好这个目录。

链接一律用相对路径，不带开头斜杠。genesis 内部互链用同目录相对路径（快照→`adr/`，ADR→ADR）；ROADMAP 在 `docs/` 一级，指向 ADR 写 `genesis/adr/...`，ADR 回链 ROADMAP 写 `../../ROADMAP.md`；
intent 文件夹里指向宏观工件写 `../../../genesis/...`、`../../../ROADMAP.md`。`active/` 与 `done/` 同深度，所以归档时这些链接不会断。

## 宏观增补：创世期的新能力域

创世期（阶段 5 退出前）宏观设计本身的增补路径：

1. 回到阶段 1，仅就新维度补采集口述（体量、边界、隐私、验收方式等）；
2. 修订 VISION / ROADMAP 并同步链接，识别新决策点；
3. 新决策点按阶段 3 补 ADR（编号顺延，遵守难逆优先与定稿后重估）；
4. 同批更新 ARCHITECTURE 快照；
5. 重新走阶段 4 收尾（抽查一条新决策链即可）。

创世结束之后宏观文档怎么维护，不再由本技能管，见 aisdlc 技能（决策只追加 ADR，ARCHITECTURE 随触及它的变更在同一个 MR 里更新）。

## ROADMAP 是方向文档

ROADMAP（`templates/ROADMAP.md`）是团队级的方向：一串有序的能力块，每个是后续 intent 的种子。它变得慢，只在方向变了才改（规则见 aisdlc 技能）；
"做到哪了"不记在里面，由已关闭的变更推出。个人的待办或看板是个人约定，不入库。两条写法上的经验：

- 远期条目一行即可，**不提前展开**——后面的 intent 在前面的落地之前就写好，落地后多半要返工。
- 一个能力块通常对应**一个里程碑级 intent**；更细的拆分写进它的 spec 的 Requirements 和 plan，不预先拆成一串 intent。

## 链接纪律：工件链的流转规则

流转的是意图，载体是链接。规则如下：

1. **ADR 不是阅读入口**：VISION / ARCHITECTURE / ROADMAP 是阅读入口，adr/ 目录的文件永远由这三份文件的链接**衍生抵达**，不允许需要「扁平通读 adr/ 才能理解现状」的情况存在；
2. **快照 → 当前 ADR**：VISION / ARCHITECTURE / ROADMAP 中每一条由决策支撑的条目，必须链接到**当前有效**的那份 ADR；
3. **ADR → 前任 ADR**：每份取代旧决策的 ADR，必须在头部「取代」字段链接前任（可多份）；被取代的旧 ADR 状态改为「已废弃」并在「被取代」字段回链新 ADR；
4. **同步更新**：任何 ADR 定稿或废弃时，必须在同一次提交中更新所有指向它的快照文件，保证「快照永远指向当前有效版本」；
5. 检验标准：从任意一份快照文件的任意一条决策出发，能一路点击追溯到该决策的完整演化链（首次提议 → 每次变更及理由 → 当前版本），无断点。

## 阶段 1：采集口述

请用户用大白话描述项目，引导覆盖以下维度：

- 要做什么（一句话版本 + 展开描述）
- 痛点：现在的方式哪里烂
- 必须有的能力（核心功能清单）
- 不做什么（边界）
- 约束（技术栈偏好、部署环境、资源限制）
- 不确定的点（显式收集，列为待决问题）

规则：维度不全就追问；避免替用户做产品判断。

→ **闸门**：用户确认「口述完整」。

## 阶段 2：起草 VISION 与 ROADMAP

按模板起草 VISION.md 与 ROADMAP.md，并输出一份**决策点清单**：从口述中识别出所有需要拍板的技术/架构决策，逐条编号，标注「难逆/易逆」。
清单里必须有一条**交付形态**（难逆）：交付什么（服务、安装包、库、静态站点，或不交付）、交付到哪（服务器、托管、release、包仓库）、触发方式（合并主干、打 tag、手动）、环境数量。
只定形态，服务器地址、凭据等细节留给后续 intent。"不需要 CD"也要显式记成一条决策。
形态决定 CD 的时机，写进 ROADMAP：部署类服务在队首放"部署骨架"能力块，应用类与库用条件式条目，如"首次发布：用户确认有可用版本后"。

→ **闸门**：用户审阅两份草稿与决策点清单，确认通过。

## 阶段 3：逐条 ADR

对决策点清单中的每一项：

1. 给出 2-3 个候选方案，各自说明代价与适用条件；
2. 等待用户拍板（用户是唯一的决策者）；
3. 用户决定后按 ADR 模板成文；
4. 难逆决策（数据模型、鉴权方式、核心架构）优先处理；易逆决策可标记「推迟到对应 intent」，不强行现在定；
5. **每份 ADR 定稿后，立即重估剩余决策点**：已定稿决策可能收窄后续候选空间（如选定 CRDT 后后端栈基本锁定）、反向改写后续命题（如移动端形态决定后才暴露鉴权问题），剩余清单按新的约束重排优先级再继续；
6. 每份 ADR 定稿时，按链接纪律在相关快照文件中建立指向它的链接。

→ **闸门**：每份 ADR 用户明确说「定稿」。

## 阶段 4：收尾

- 汇总本次创世产出的文件清单；
- 校验链接纪律第 5 条：随机抽查两条决策链，确认可追溯、无断链；
- 用 aisdlc 技能的 intent 模板起草**第一个意图：项目骨架**。骨架是**空壳加护栏**，不含任何业务能力：目录结构、构建配置、lint/test/build 命令、CI 管道。
  护栏要同时带上 aisdlc 的机械校验：把 aisdlc 技能 `scripts/` 下 CI 要跑的两个脚本（`aisdlc_index.py`、`aisdlc_check_lane.py`）复制到仓库 `scripts/aisdlc/` 并接入 CI（做法见 aisdlc 的 `references/wiring.md`）。
  评审、评论命令、监控这些让 harness 介入循环的触点**不进骨架**，骨架合并后各自作为独立 intent 逐个接入；
- 骨架 intent 的"期望结果"里要写一条**合并后动作**：用户在平台上开启主干保护与"流水线必须成功"，并做负向验证（直推主干被拒）。这项没完成，骨架不算关闭。
  理由：交棒话术只存在于本次对话，新窗口里的 agent 看不到；写进 intent，提醒才随仓库走。缺了这一步不会有任何报错，CI 红了照样能合并；
- 骨架的 Lane 记为 `build`：它用到的依赖和部署形态应当已被 ADR 定过。起草时若发现有没定过的，说明创世漏了决策，回阶段 3 补 ADR，不另走决策档；
- 用户确认后提交全部文件。

→ **闸门**：用户确认骨架 intent.md。

## 阶段 5：退出（交棒）

创世的价值在于把难逆决策一次定清，之后宏观层应该很少被改动。退出就是把这件事固定下来，免得项目长大后反复回头修 genesis：

1. **打标签**：提交后打 tag `genesis-complete`。此后对 `docs/genesis/` 的任何改动都能 diff 到这个基线。
2. **冻结 VISION**：文件头加一行说明——创世后只在项目转向时修改，且必须在同一次提交里带一份 ADR 说明转向原因。
3. **瘦身 ARCHITECTURE**：只保留系统组成（模块边界）、技术选型（链接 ADR）、边界与约定；删去行为描述和「能力现状」一类会随开发过期的内容——这些由各变更 spec 的 Requirements 与测试承担。
4. **ROADMAP 收口为方向文档**：只保留有序的能力块与调整记录，不写进度。此后只在方向变化时修改，并记入调整记录（规则见 aisdlc）。
5. **接入 aisdlc**：把 aisdlc 技能的 `assets/agents-md-snippet.md` 并入项目 AGENTS.md，让此后的每个变更请求都先走 aisdlc 判档。
6. **交棒**：下一步由 aisdlc 接手，从骨架 intent 开始。骨架是循环的第 0 次迭代：基线分支上还没有 CI，骨架 MR 自己带来 CI，由人评审后合并。
   合并后用户要在平台上开启主干保护与"流水线必须成功"：这是平台设置，不在仓库里，已写进骨架 intent 的合并后动作，做法见 aisdlc 的 `references/wiring.md`。让 harness 介入循环的触点（MR 评审、评论命令、监控）排在这之后，各自作为独立 intent 按需接入，骨架关闭时 aisdlc 会提示一次。
   之后不要预先把 ROADMAP 拆成一串 intent，按需从队首取第一个能力块展开，其余仍是一行。第一个能力块最接近从零建、体量最大，可能要拆成几个有先后依赖的 intent，按依赖顺序逐个取，不一次写完。
7. **宣告退出**：本技能到此结束。此后不要为了「补全 genesis」回头改它；需要变更宏观决策时，追加 ADR 即可。

→ **闸门**：用户确认退出清单已执行。
