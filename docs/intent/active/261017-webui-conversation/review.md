## 第一轮
Reviewer: Codex
Date: 2026-10-18

### 阻塞
1. **P1 断线或切换会话时，未确认发送可能丢失。** 原文给了两个复现：(a) 会话 A 发送后不等 ack，切到 B 再切回 A，原文消失；(b) 运行中连续发送 A、B 后断线，恢复回调只把 A 放入草稿，B 因草稿已非空而丢失。
   - (a) **[已修]** 草稿上移到 `Shell` 按会话存；清理流时 `settleCommands` 先结算未确认命令，放回原会话草稿。新增 R14 四个用例。spec 要求的变异（切换时不结算，必须变红）本记录没有执行结果。
   - (b) **[已修]** 经人确认选“按发送顺序合并”：`settleCommands` 把所有未确认的发送用换行拼成一份，只调一次 `restoreDraft`。新增用例"R8 连发两条都未确认就断线：按发送顺序合并放回，一条不丢"，修前实测变红（输入框只有第一条），修后 102 个用例全过，`tsc` 退出码 0。草稿本来就非空时仍整体不写入，与 R8 的“不覆盖新输入”一致。

### 重要
2. **P2 重连期间已加载的历史被丢弃**（`history.ts`）。**[已修]** `afterTail` 改为在 index 衔接或重叠时合并。中间有缺口（断开期间新增超过一页）时仍改用新页，更早部分由"加载更早"补回，这个例外写在 spec R2。评审者指出它与"不得丢弃已加载消息"冲突。**[人已确认保留]** 缺口时用新页替换：保留旧块会在中间留下看不见的洞，顺序是错的。代价是用户翻出来的旧消息消失，需要重翻。
3. **P2 `error` 与 `close` 重复触发重连**（`stream.ts`）。**[已修]** `closing` 标志只放行第一次。用例"R10 握手失败时 error 加 close 只算一次关闭"。
4. **P2 加载更早时新消息造成滚动锚点偏移**（`Conversation.tsx`）。**[已修]** 位移增量改以上一次提交的高度为基准，而不是点击时的高度。用例"R13 请求期间新消息到达：位移只算历史块增加的高度"。
5. **P2 重复内容让过期历史页误对齐并漏消息**（`history.ts`）。原文：REST 返回后快照窗口前移一条，窗口内重复消息的角色和文本相同，校验通过后按旧起点截页，漏掉一条。**[已根治，见下]**
   - **[已核实，根治]** 窗口上限 50（`pool.ts` `WINDOW`），满后每条新消息挤掉最老一条，长度不变，内容按轮重复（如“继续”/“好”交替）时，取数期间滚动一轮仍通过比对，按旧起点截页会漏 2 条。先用“比较 `messages` 数组是否被换过”止血（有用例，修前变红），随后经人确认根治：快照新增 `startIndex`（窗口第一条的序位，与 REST `index` 同一套），服务端累计总数（`pool.ts` 的 `total`，恢复时由完整历史播种，`message.ended` 递增），前端 `loadOlder` 直接按 `startIndex` 截页，不再比对文本，也不再需要 `truncated` 与数组引用检测。ADR-0021 与事件流 spec R7 已补这个字段。服务端用例断言恢复后为 10、追加后为 12（共 60→62 条）；前端用例含内容重复、页接不上重取、快照缺 `startIndex` 提示失败。
   - 代价：`startIndex` 在服务端内存里累计，会话被压缩或改写历史时与文件序位错开且前端不会发现，已记入 spec Risks。
