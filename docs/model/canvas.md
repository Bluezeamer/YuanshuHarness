# 灵感画布

Author: bluezeamer
Status: 现行
Date: 2026-11-11
Verified: 2026-11-19（对着代码核对：`packages/server/src/canvas/`、`packages/server/src/api/canvas.ts`、`permission/extension.ts`、`store/defaults.ts`、`watch/hub.ts`，`packages/web/src/features/workspace/tabs/canvas/`）

一个单独的标签类型，用来随手收集想法、摆放笔记。**实质是文件夹里的一批文件**（标准 JSON Canvas 加 markdown），但入口与承载都不是文件浏览器和文件预览。起因：现有笔记软件与 agent 交互困难，「markdown + 画布」就够用，并且 agent 能直接读写。术语「目录」「工作区」见 [`workspace.md`](workspace.md)；本文的「文件夹」指磁盘上的文件夹，不是「目录」（主机 + 路径的登记项）。

## 1. 原则

- **CV1 画布是文件，不是数据库实体。** 真相在文件里：`.canvas`（标准 JSON Canvas 1.0，只存摆放：位置、连线、分组）加若干 `.md`。写回 `.canvas` 时只改自己关心的字段，**保留未知字段**，Obsidian 或其扩展存过的内容不会被吃掉。用标准格式，顺带兼容 Obsidian（只是成熟的参照，不依赖它）。
- **CV2 来源由路径决定，不加自定义字段。** 画布上每个节点都是 `file` 节点：路径落在这块画布自己的卡片文件夹（`<画布>.cards/`）里是**灵感卡**，落在别处是引用（**笔记**，或项目里的普通文件）。画布里收集的灵感与一篇正式的引用地位不对等，来源要能一眼区分。
- **CV3 单独的 `canvas` 标签。** 入口是新建标签菜单与标签内的树，不借文件浏览器；编辑不借预览标签。**人类直接动文件是约定、不强制**：界面里的新建、改名、移动、删除是唯一会机械地同步引用（画布节点、`[[链接]]`）的入口，所以按直觉都该在标签里做；文件浏览器照常能浏览与改 `.canvas/` 里的文件（前提是知道自己在做什么），不隐藏、不拦。
- **CV4 agent 写画布文件夹只经 `canvas_edit`，读不拦**：读保持现状，写的约束保证结构不会被意外破坏。用户也尽量在画布界面里操作，不直接改文件。
- **CV5 历史靠 git：每个画布文件夹一个独立仓库，** 排除在项目主仓库之外。
- **CV6 远程（ssh）目录的 `.canvas/` 在 Server 本机有一份权威副本，** 主机连不上时照常可读可写，改动连上后自动推到远端（§10「本地优先」）；不另做只读备份（§7）。

## 2. 存储布局

```
.canvas/                     每个目录一个画布文件夹，自带 git 仓库
  产品想法.canvas            画布：标准 JSON Canvas，只存摆放
  产品想法.cards/            这块画布的灵感卡
  产品想法.assets/           这块画布的资源：粘贴 / 拖进来的图片、视频、音频、任意文件（§10）
    _large/                  太大的资源（不进这个仓库的 git）
  设计原则.md                笔记：普通 markdown，不属于任何一块画布
  产品/                      自己建的子文件夹，里面同样是画布与笔记
    时间线.canvas
    用户研究.md
  index.md                   框架生成、只读（§5）
```

画布与笔记在同一棵树里平级混放，靠扩展名区分；**画布名就是相对 `.canvas/` 的路径、不带后缀**（`产品想法`、`产品/时间线`），卡片与资源文件夹跟在 `.canvas` 文件旁边。

- **位置**：每个目录一个，叫 `.canvas/`（隐藏，不污染项目视图）。全局画布尚未实现，设想见 §9。
- **路径一律相对画布文件夹**，写进 `file` 节点：灵感卡 `产品想法.cards/想法.md`，笔记 `产品/调研.md`，项目文件 `../docs/design.md`。把 `.canvas/` 当 vault 在 Obsidian 里打开时，引用的项目文件显示不出来，这是兼容的已知上限，接受。
- **版本控制**：创建画布文件夹时 `git init`，并在项目是 git 仓库时把 `.canvas/` 追加到项目主仓库的 `.git/info/exclude`（本地文件，不提交；**这是唯一写进用户仓库元数据的地方**）。主机上没有 git 或仓库没建立时，画布界面显示警告条，不阻断使用，也没有历史。**远程（ssh）目录的 `.canvas/` 在 Server 本机有一份权威副本，git 仓库建在副本里，远端目录只有文件、没有 `.git`**（§10「本地优先」）。
- **名字**：不另设标题，**卡片名 = 文件名**。中文直接用，只处理非法字符（`sanitizeName`），重名加 `(2)`；随手记默认以时间命名（`YYYYMMDD-HHmmss`）。

## 3. 三种来源

灵感卡不能跨画布引用，要用先升格。

| | 灵感卡 | 笔记 | 项目文件引用 |
|---|---|---|---|
| 位置 | 这块画布的 `.cards/` | `.canvas/` 树里的 `.md`（不在卡片与资源文件夹里） | 目录里任意位置（`../…`） |
| 归属 | 只属于这一块画布 | 独立，可上任意多块画布 | 项目的普通文件 |
| 谁写 | `canvas_edit` | `canvas_edit` | 普通 write / edit，走普通权限 |
| 历史 | 画布仓库 | 画布仓库 | 项目自己的 git |
| 从画布上移除 | 删文件（可从历史找回） | 只去掉节点 | 只去掉节点 |
| 重命名 | 只有本画布引用，改节点即可 | 更新所有画布与笔记里的引用 | 画布不处理，变成缺失卡片 |

- **升格**：灵感卡成熟后「升格为笔记」，即把文件移到树里的指定位置，节点留在画布上、改成引用（agent 用 `promote`）。不做反向的降格。
- **灵感卡不能被另一块画布引用**，要用先升格。这样来源区分才严格。
- **删除笔记**清掉所有画布上的引用（agent 的 `delete` 与界面树里的删除都会做；界面确认框写「有几块画布放着它、几篇笔记的 `[[链接]]` 指向它」，数据来自 `GET /refs`）。**删除画布**连带删它的资源文件夹，确认框写「N 张灵感卡」；笔记与项目文件不动。
- **缺失的引用显示为缺失卡片，不报错**；不靠哈希自动识别外部改名，猜错比不猜更糟。
- **反向索引**：只有笔记需要「被哪些画布引用」，生成 `index.md` 时扫描得到（`appears-in`、`linked-from`），删除前的确认框也是现扫（`CanvasRepo.referrers`）；不维护持久的反向索引，也不监视（见 §10「乐观更新」一条的取舍）。灵感卡只有一个引用者，不需要。

## 4. agent 的工具：`canvas_edit`

- **一个工具，一次收一批操作，整批全成或全不成。** 操作面：`create_canvas`、`create_card`（在某块画布上新建灵感卡）、`create_note`（可同时放上某块画布）、`update`（卡片与笔记，整体替换，或 old → new）、`rename`、`delete`、`place` / `unplace`（把项目文件 / 笔记放上画布或从画布移除）、`promote`（灵感卡升格为笔记）。参数里不写文件夹时，用会话的**逻辑 local 目录**（不随会话切换目录而变，见 §10）。
- **框架负责一切机械部分**：文件名、节点 id、新节点的位置、引用更新、git 提交。agent 不碰 id 与坐标。
- **不开放 `connect` / `group` / `move`**，连线与分组只由用户在界面里调（若以后开放，设想见 §9）。
- **护栏**：路径护栏（`permission/extension.ts` 的 `canvasGuard`）在任何档位下拦下 write / edit 对 `.canvas/` 的写入，并提示改用 `canvas_edit`；**读不拦**，`index.md` 与卡片仍用普通 `read`，它自带行偏移，渐进加载靠它。护栏防的是误操作，拦不住 `bash` 与外部工具，所以**文件仍是真相**：外部改动不会丢，下一次提交时（`canvas_edit` 开头、读历史时）工作区里没登记来源的改动照常记入历史、来源标「外部」；加载时容错（缺失节点、悬空连线都能显示）。
- **一个能力单元「画布」，整体开关**（`unit:canvas` → `canvas_edit`），不细分到单个操作；受模式的限定为 / 减少约束，与其他能力单元相同（[`prompt.md`](prompt.md) M1）；走占位通道尾部注入，不改声明（[`prompt-delivery.md`](prompt-delivery.md) §4）。

## 5. `index.md`

- 框架在每次保存后重写，**只读**，agent 不改它：画布结构由用户的拖动决定，让 agent 维护索引会造成结构漂移。放在画布文件夹根。
- **全部从文件内容推导，不要求卡片或笔记有标题或 frontmatter**；做成三段、全 ASCII 的骨架，agent 由粗到细逐层往下读：先看 `## tree` 与 `## boards`、`## notes` 的头部知道整体拓扑，锁定某块画布再看它的节点与连线，最后才读具体文件。

```
# index

generated - do not edit

## tree

想法.canvas
设计原则.md
产品/
  时间线.canvas
  用户研究.md

## boards

b1  产品/时间线.canvas  "时间线"
  linked-from: (none)
  nodes
    d04f1a92  note  设计原则.md  "设计原则"  2 kB
  edges
    (none)

b2  想法.canvas  "想法"
  linked-from: no1
  nodes
    a3f7c2d1  card  想法.cards/风险.md  "风险与布局"  412 B
    b1e490fa  note  设计原则.md  "设计原则"  2 kB
    c20d8b31  ref  ../docs/design.md  "design"  2 kB
    d0000001  ref  local:/data/logo.png  "logo"
    e0000001  link  https://x.dev
    f0000001  group  "风险"
  edges
    a3f7c2d1 -> b1e490fa  "依赖"
    a3f7c2d1 -> c20d8b31

## notes

no1  产品/用户研究.md  "用户访谈记录"  61 B
  appears-in: (none)
  links-to: [[想法.canvas]] [[设计原则.md]]
  linked-from: no2

no2  设计原则.md  "设计原则"  2 kB
  appears-in: b1 b2
  links-to: [[产品/用户研究.md]] [[不存在]](missing)
  linked-from: no1
```

- **`## tree`**：只有结构，没有内容；同一层先文件后子目录，文件夹带结尾 `/`；`.canvas` 是画布、`.md` 是笔记（卡片与资源不在树里，它们跟着各自的画布）。
- **`## boards`**：每块画布一段，`b1 b2…` 是序号；`nodes` 一行一个节点：`<id 前 8 位>  <种类>  <路径或地址>  "<标题>"  <大小>`，种类有 `card`（灵感卡）、`note`、`asset`（资源）、`ref`（项目文件与别的主机上的文件）、`link`、`text`、`group`；**节点 id 取原 id 的前 8 位**（稳定，agent 跨会话可引用，`edges` 也用它）；`edges` 写 `from -> to` 与可选的 `"标签"`，空的写 `(none)`；文件不在的行尾写 `missing`；路径相对 `.canvas/`，目录之外与别的主机上的写成 `主机名:绝对路径`、**生成时不去查远端**。`linked-from` 是链到这块画布的笔记。
- **`## notes`**：每篇笔记一段，`no1 no2…` 是序号；`appears-in` 是它出现在哪些画布上，`links-to` 是正文里 `[[…]]` 指向的画布与笔记（指不到的标 `(missing)`），`linked-from` 是链到它的笔记。大小用整数 `B` 或 `kB`。
- **标题**（引号里那段）：正文第一个非空行（去掉 frontmatter 与 `#` 标记），折成一行、最多 40 字；没有正文用文件名；画布用名字。索引不给正文开头与标题树：要内容就读文件。
- **wikilink**：笔记正文里写 `[[产品/用户研究]]` 或 `[[想法.canvas]]`，目标是相对 `.canvas/` 的路径；缺扩展名先当笔记（补 `.md`）、再当画布（补 `.canvas`）；`[[目标|别名]]` 与 `[[目标#标题]]` 只取目标；围栏与行内代码里的不算。反向引用靠生成索引时扫正文得到，不维护 frontmatter。
- `index.md` 自己、卡片、资源不算笔记；点开头的文件夹（`.git`）里的不算。

## 6. 并发与历史

- **读写沿用预览的基线机制**（mtime + sha256 判冲突）；写入先写临时文件再 rename。
- **冲突处理沿用预览现有的**：保留我的修改 / 加载磁盘版本 / diff 手动合并，合并编辑器里可直接取合并结果再手动处理冲突（就是预览的 `ConflictDialog`，画布保存时对冲突的卡片逐张弹出）；没有未保存改动时，外部变化直接热替换；有未保存改动时，磁盘版本并进来，没保存的布局与正文保住。
- **文件监视**：界面经会话 WS 的 `watch` 订阅画布路径（`.canvas/` 根、各子文件夹、当前画布的卡片目录），外部或 agent 改了就重取；监视由通用的 `watch/hub.ts` 做（本机 `fs.watch`，远程环境 2 秒轮询；按会话去抖，默认 300ms）。Server 不另设监视画布文件夹的后台任务。
- **提交节奏**：`canvas_edit` 每次调用一个提交，消息写来源（会话 id / 用户 / 外部）；用户在界面里的编辑等停顿（5 秒）后合成一次提交，不逐键提交。
- **回撤在框架层做**：画布与笔记各有历史列表，可看 diff、可恢复某个版本；恢复是新提交，不改写历史；可以撤销 agent 的上一次 `canvas_edit`。界面：工具条「历史」打开右侧面板（盖在主区上、不挤画布），只看当前打开的画布或笔记（面板跟着主区换）；每行写摘要、时间、来源（你 / agent / 恢复 / 撤销 / 外部改动），最新一条标「当前」，保存后自动重读；点一条开对话框看「恢复成这一版会变成什么样」——**笔记按行对比**（`−` 去掉、`+` 回来，复用冲突对话框的 `DiffLines`），**画布不列 JSON**、只列「恢复后会回来 / 会消失的节点、位置大小变回去的数量、连线增减」（`versions.ts` 的 `boardChanges`，且写明只恢复画布本身、卡片文字各有自己的版本）；恢复在服务端是一条新提交，成功后主区整个重读（画布 `discardAll`、笔记换 key）；有没保存的改动时对话框写明会丢掉；面板顶上「撤销 agent 的上一次修改」只在整个 `.canvas/` 最新一条是 agent 的提交时出现（接口是整个 `.canvas/` 的、不是只当前文件），确认后撤销。组件在 `packages/web/src/features/workspace/tabs/canvas/` 的 `VersionsPanel`、`VersionDialog`、`versions`；验收 `scripts/verify-versions.mjs`。

## 7. 备份与离线（不做）

决定：不另做只读备份镜像。理由：远程目录已是本地优先（§10），Server 本机的副本就是这份备份，主机连不上时照常可读可写、改动连上后自动推送；本机目录没有副本。再做一份只读镜像，就要多处理一遍两边同步。

## 8. 界面与标签

- **`canvas` 标签绑定（主机 + 目录 + 画布名）**：不随会话；`data` 档（带主机作数据地址，不参与窗格隔离，见 [`layout.md`](layout.md) §2），**跟着工作区主目录（逻辑 local）走，「+」里选画布不问主机**。标签类型的注册方式见 [`layout.md`](layout.md) §3。
- **标签内左边是树、主区显示一块画布或一篇笔记**（做法见 §10「树与笔记视图」）。工具条一行：后退 / 前进、当前画布或笔记的名字，右边画布有 新建卡片 / 保存 / 缩放，笔记有 预览·编辑 / 保存。用户在界面里拖动、缩放、连线、新建灵感卡、把项目文件与笔记拖进画布。
- 卡片在画布里**原地编辑**（见 §10），编辑器复用预览的 `CodeEditor`（加了紧凑模式），冲突对话框也是预览那套。
- 文件浏览器不为 `.canvas/` 做特殊处理（笔记也就是它里面的普通 `.md`，点开就是预览与编辑）；但这是「知道自己在做什么」的旁路，日常的新建、改名、移动、删除走标签里的树。

## 9. 未实现与未决

**已定方向、未做**
- **全局画布**：Server 持有所有远程主机画布的全量副本（§10「本地优先」），所以可以在 Server 端建一棵逻辑树 `root/{主机名}/{目录（项目）}.canvas/`；全局画布 / 笔记就是直接放在根下的画布与笔记文件，代表「全局状态」；本机也作为逻辑上的 Server 映射挂在这棵树里（`root/{Server 主机名}/…`），这样从全局笔记能方便地引用各个主机的笔记内容。搁置，等需求到了再做；还没定的：入口（新建标签菜单 / 左轨）、数据目录下的具体路径、`canvas_edit` 怎么指到它、逻辑树与现在 `<数据目录>/canvas/<环境 id>/<目录哈希>/` 副本布局的对应方式。
- **灵感卡自己的历史入口**：历史接口按路径能查，界面没给入口。
- **改名之前的历史**：按路径查，改名后断开。

**设想（没定）**
- 以后若开放 `connect` / `group` / `move`：仍由框架生成 id、按相对位置算坐标与连线朝向、按几何包含自动扩组，不接受绝对坐标。
- 按旧名查不到文件时，工具按重命名记录回答「已改名为 X」。
- 缺失卡片的「重新指定文件」；项目文件被改名后画布怎么得知（现在先不处理，显示为缺失卡片）。
- 拓扑图渲染（索引的结构稳定后再做，节点形式、悬停显示完整名字）、Obsidian 式全局图谱。
- 树里新建时自动选中并进入行内改名（现在是对话框）。
- `[[链接]]` 里没解析到的目标，在预览里与解析到的同样显示（没有「缺失」样式）。
- 灵感卡正在原地编辑时按选区「添加到对话」（只能引用整张卡片），文件预览标签里的同类入口。
- 本地优先的没做项：从远端拉取外部改动并进元枢、副本体积管理、远端旧 `.git` 历史的导入、「立即同步」按钮（见 §10「本地优先」）。
- PDF 内嵌查看、内嵌网页（很多站点禁止嵌入）、远端引用文件变化的实时监视（刷新时才重取）、远端引用的重新指定。

**决定不做 / 现状如此**
- 画布旧版本的只读预览：不做。
- 别处（如 Obsidian）建的内嵌文字节点：能显示和编辑，界面不新建。
- Server 抓取链接卡片信息时不拦内网地址（与 agent 能 curl 的范围一致）。

## 10. 设计取舍与实现要点

本节是 §1–§8 的展开：各部分的取舍、实现要点与边界。其他章节与代码注释里的 §10 引用指向这里的小标题。

### 设计参照

- index 做成「每页一条：链接加一行摘要，先读 index 再钻取」，参照 Karpathy 的 LLM wiki（约百份来源、几百页的规模够用）。
- agent 接口用语义操作加无坐标的结构视图，整文件读写是错的交互形状；并发先做文件级后写覆盖、原子写入、防抖，参照 canvai 的设计文档。
- 反例：kepano 的 obsidian-skills 把 id 与坐标交给 agent、靠自查校验；这里由框架包办。
- Obsidian 在内部移动文件时更新画布引用、外部移动不更新（论坛说明，非官方文档），对应 CV3「界面是唯一机械同步引用的入口」。

### 范围与数据流

- **范围**：灵感卡、笔记、项目文件引用、网页链接、媒体资源。**引用的文件可以在别的主机上、也可以在画布所在目录之外**（见「跨主机与目录之外的引用」）。
- **跟逻辑 local 目录走**：界面里的画布标签永远绑工作区主目录；`canvas_edit` 不写 `directory` 时也用会话的逻辑 local 目录，**不随会话切换目录而变**（否则会写进用户在界面里看不到的画布）；`directory` 参数仍可点名别的目录。
- **原地编辑、画布级保存**：双击卡片，卡内换成编辑器（字体字号与渲染态一致，没有行号），编辑器只负责编辑，不管保存。**画布是一份文档**：拖动、缩放、连线、卡片正文、新卡片都先攒在界面的 store 里（画布文件与卡片文件都不动），工具条一行放「未保存 · 还原 · 保存」，Ctrl+S 在画布任何位置都存全部；没保存的卡片上方标「未保存」。Esc 或点空白处收起不丢（也不再问），工具条「还原」放弃全部（先确认），切画布 / 新建 / 改画布名前有未保存的先确认，刷新或关闭页面有浏览器自带的提示。**动作不进攒着的改动、立即生效**：删卡、改名、把文件放上画布（本地立刻放上，同时单独把这一个节点写进磁盘版本，让服务端读到文件、预览信息马上回来；画布上其余没保存的改动不动）。攒着的改动放在组件外面的 store（`useCanvasStore`，按标签存；窗格只渲染当前标签，切走再回来组件会卸载，不能让改动跟着丢），没有标签在用且没有未保存的改动时才丢掉；所以关掉画布标签再重开，改动也还在（只要页面没刷新）。
- **新卡片可以是空的，也可以同时有很多张**：双击空白处（卡片中心落在鼠标位置）或点「新建卡片」（避开已有的卡片排开，不在视野里就把视野平移过去），在画布文档里加一个**普通节点**（有 id、位置、大小，能连线、能拖、能缩放），它的 `file` 是占位名 `::new:<节点 id>`；保存时服务端建出文件，把 `file` 换成真路径，节点 id 不变，所以连线、正在编辑的状态都不受影响。不写字也是一张卡片，保存时照样建出（空文件）；删掉没存过的新卡片就是从画布拿掉，它的正文一并作废，不请求服务端。
- **没保存的改动只在浏览器页面内存里，Server 不持有**（对话会话与布局才在 Server 上）。数据流：浏览器 store（内存）⇄ REST ⇄ Server 里每个目录一个 `CanvasRepo`（只有串行队列和 5 秒的 git 提交定时器，不存内容）⇄ 目标主机（本机走文件系统，远端经本机副本，见「本地优先」）上的 `.canvas/`；磁盘上的变化经会话 WS 的 `watch` 订阅通知浏览器去刷新。所以会丢没保存改动的只有浏览器这一侧（刷新、关页面、标签页崩溃）；**Server 突然挂了不丢它们**，只丢那个提交定时器（文件已写好，历史里晚一步记成「外部」改动）。
- **批量保存**：点保存只发一个请求 `POST /api/v1/canvas/:env/save`，带画布文档（改过或有新卡片才带）、改过的卡片（各带自己的基线）、新卡片（节点 id + 正文），服务端在串行队列里先查后写：文档基线不符整批拒绝（409，浏览器读回磁盘版本三方合并后重发）、卡片不存在整批拒绝（404），此时磁盘没动过；单张卡片基线不符只跳过它、结果里列出来（浏览器逐张弹冲突对话框）；写入顺序是改过的卡片 → 新卡片 → 文档最后写；只生成一次 `index.md`、一次 git 提交，一批新卡只 `mkdirp` 一次，提交是 `git add -A && git commit && git rev-parse` 一条命令；返回新基线与新卡片的路径，浏览器**不再回读**，用写进去的内容直接更新状态（预览、基线都在本地算）。多文件不是原子的（崩溃中途可能留下孤立的卡片文件，不会有引用它的残缺文档）。
- **浏览器本地镜像**：没保存的改动同步镜像进浏览器本地存储（键 `ys.canvas.unsaved:<环境>:<目录>:<画布名>`，同步写、没有定时器；干净了就删；超过 200 万字符不镜像（并删掉旧值）），刷新页面或误关标签后在同一个浏览器里重新打开这块画布就恢复，提示「已恢复上次没保存的改动」。镜像里带着当时服务端那一版文档与各卡片开编辑时的基线：磁盘上的画布变过就以它为底三方合并，卡片被改过则保存时照常走冲突对话框，已被删的卡片不恢复；离开这块画布（已确认放弃）与「还原」都会删它。只在同一个浏览器里有效，换浏览器或清了站点数据就没有。

### 渲染与媒体

- **渲染与标题**：卡片显示渲染好的 markdown（复用预览的 `MarkdownView`，轻量模式：mermaid 围栏只显示源码）；服务端预览取前 4000 字，更长的卡片底部渐隐，内容比卡片高时直接显示滚动条（见「内容溢出的滚动条」），滚轮要选中后才在卡里滚。卡片名在卡片上方用灰字标出；**随手记默认的时间名（`YYYYMMDD-HHmmss`）不显示**，改过名才显示。项目文件引用在卡片上方标 `主机:绝对路径`（目录部分放不下就在末尾省略，文件名完整），因为可能跨设备。
- **图片**：引用 png / jpg / gif / webp / svg 时显示图片。原图直显时十几张 4k 照片同屏的传输与浏览器内存开销都很大，所以由服务端缩图后再给：`GET /api/v1/canvas/:env/image`，最长边 2000、JPEG 质量 85、编码后上限 2MB（PNG 在上限内保持 PNG，不转 JPEG；2000px 以内且不超限的原样给出），磁盘缓存（键含路径、mtime、size、最长边、质量）。缩略图最长边、质量、GIF 原样上限、原图上限都**在设置里调**（「设置 · 默认值 · 输入与显示 · 灵感画布的图片与资源」，存在 `canvas_media`，每次请求现取，缓存键含最长边与质量，改了立刻生效，旧缓存不用清）。缩图用 pi 的 `resizeImage`（光子 WASM），它同步执行（一张 4k 图约一秒），所以放在 worker 线程里，不堵 Server 事件循环。gif 不超过「GIF 原样上限」（默认 8MB）就原样给出（保留动画），更大的取首帧；svg ≤512KB 原样（带 CSP sandbox），更大的不显示；源文件超过「原图上限」（默认 20MB）不显示（卡里提示「双击在预览里打开」）；`<img>` 靠会话 Cookie 鉴权，URL 带 mtime，浏览器长期缓存。缓存淘汰只有条数上限（3000），没有按大小淘汰。**图片地址带设置指纹**：`GET /board` 返回 `mediaRev`（缩略图最长边、质量、GIF 原样上限、原图上限的指纹），图片地址除了 `v`（mtime）再带 `r=mediaRev`；否则地址只带 mtime，浏览器按「长期缓存」留着旧图（例如 GIF 上限调大之后同一张图仍然不动）。指纹在载入与刷新时更新，所以改了设置之后再打开或刷新这块画布，图片地址就变了。**图片只能等比例缩放**（任意比例只会留出空白）：图片节点缩放时锁定宽高比；每张图片载入时都把节点对齐到图片本身的比例（宽度不变、高度跟着变，差 2px 以内不动），所以刚放进来的、被随意拉伸过的都一样——旧节点载入时会被校正一次，画布因此标「未保存」，保存后就固定了。普通卡片、分组仍可任意比例缩放。
- **视频与音频**：不自动播放，点击才播。引用 mp4 / m4v / webm / ogv / mov / mkv 与 mp3 / wav / m4a / aac / ogg / oga / opus / flac。视频卡平时只是一个「播放」按钮加文件名——**不预读、不请求**（远程主机上不花流量），点了才挂 `<video controls autoplay>`，并按视频本身的比例校正节点（和图片一样等比缩放）；音频带播放条但 `preload=none`。播放走 `GET /api/v1/canvas/:env/media`：按 Range 流式读（本机与 SSH 主机一样，每次响应最多 64MB），浏览器边下边播、能拖进度条；URL 带 mtime，浏览器可长期缓存。浏览器解不了的编码（如部分 mkv / mov）显示一行提示，双击仍可在预览里打开。
- **粘贴与拖入文件**：在画布里按 Ctrl+V（剪贴板里有文件，如截图、复制的图片 / 视频 / 文件；在编辑器与输入框里粘贴照旧），或从系统里把文件拖到画布上，文件传到**这块画布自己的资源文件夹** `.canvas/<画布>.assets/`，节点自动放上画布（拖入落在放下的位置，粘贴落在视野中心附近不压着现有节点、必要时平移视野）。剪贴板图片的名字都是 `image.png`，换成 `粘贴-年月日-时分秒.扩展名`；重名在扩展名前加 ` (2)`（含 `_large/` 里的）。图片上传前先读出宽高比再定节点高度，放上去就是对的，不会刚放就变「未保存」；视频默认 16:9。上传是**动作**，不进「未保存」的草稿：字节流式落盘（`PUT /api/v1/canvas/:env/asset`，大文件不进内存，本机与 SSH 一样），服务端传完直接把节点写进画布文档，浏览器再并回来；**不占画布的串行队列**（只有开头建文件夹、结尾落位置两小段在队列里），上传期间照常编辑与保存，工具条显示「上传中 n」。单个文件上限默认 500MB，可在设置里调；超限提示上限。
- **大资源不进 git**：画布自己有 git 历史，几十 MB 的视频会让它迅速膨胀。资源**超过「进历史的资源上限」（默认 5MB，设置里调）**就放进 `…assets/_large/`，仓库的 `info/exclude` 里有通配规则 `**/*.assets/_large/` 与 `**/.assets/*/_large/`（任意深度，画布与笔记改名、搬进子文件夹后仍然有效；已有仓库在启动时补）——历史里只记画布文档里有这个节点，文件本身不记。代价：**删了找不回**，所以删这类资源时确认框特别写明。边界：恰好等于上限算小的。上传先写进 `_large/` 里的临时文件（所以崩溃残留的也不会进历史），传完按大小决定最终位置。
- **删资源**：选中资源节点按 Backspace，或右键「删除文件」，先确认（说明文件会被删除，在 `_large/` 里的特别写找不回），确认后文件与节点（连边）一起没有；`DELETE /api/v1/canvas/:env/asset`。引用的项目文件只是从画布移除，不动文件。agent 的 `canvas_edit` 不改资源（报错说明是用户放进来的媒体文件）；`index.md` 里资源标 `asset`。
- **网页链接**：链接卡片，不内嵌网页。粘贴的文字每一行都是 http(s) 地址（至多 20 行）就各建一个 JSON Canvas 标准的 `link` 节点（`{type:"link", url}`，Obsidian 也认得；别处建的 link 节点同样显示）。卡片显示封面、标题、摘要、站点图标 + 站点名，**信息由 Server 抓**（`GET /api/v1/canvas/:env/link?url=`，不是浏览器、也不是目录所在的主机）：只读页面开头 512KB（看到 `</head>` 就停）、8 秒超时、跟随跳转、不带 cookie、只认 http / https、按响应头或 `<meta charset>` 解码；取 og / twitter / 普通 meta 与 `<title>`；内存缓存 6 小时、至多 500 条，抓失败（不缓存）也是 200 并带 `failed`，卡片退回只显示地址。封面与图标由浏览器直接按地址加载（`referrerpolicy=no-referrer`）。**信息不写进画布文件**，文件里只有地址。双击在新标签页打开。

### 交互

- **视觉**（参照 Obsidian 的画布）：卡片 2px 中灰框（`--icon` 与底色 7:3 调出）、8px 圆角，不带阴影；连线 `--icon` 色 2px、**不随缩放变细**、箭头固定尺寸，悬停变深、选中蓝；连接点的本体是 2px、贴在卡片边框内侧（xyflow 取连线锚点用的是点的外沿，线因此正好接在卡片的边上），32px 的感应区与悬停时画出的圈一样大（拖线时靠近的点也亮圈，吸附半径也是 16px），小圆点悬停或选中才露出且盖在卡片之上；线可以拖到卡片中间松手，存档时按落点换成最近的一条边。**缩放控件的感应区与连接点的感应圈一样大**：四个角点各 32px 的感应区，里面画 12px 的小圆点、悬停时画出同样大的圈；四条边是 32px 宽的感应带（中心线在卡片的边上，平时不画，悬停时中间一道强调线）；边的带盖过卡片本体、角点盖过边，中点处的连接点盖过边。
- **缩放无关**：箭头（10px）、连线的点击宽度（12px）、连线标签、卡片名与分组名、连接点与缩放柄及它们的感应区（32px）、吸附参考线（1px）都按**屏幕像素**画：缩放写成 `.cv-flow` 上的 CSS 变量 `--cv-z` / `--cv-iz`（倒数，直接改样式、不走 React），要保持大小的东西用 `calc(N px * var(--cv-iz))`；卡片名的宽度 = 卡片的屏幕宽度、字号不变，缩到 30% 以下不显示（分组名仍在）；拖线吸附半径也随缩放换算。卡片的正文、图片、边框仍随缩放。
- **手势**：**左键拖空白 = 框选**（与框相交的卡片、连线都选中；只框住一条线、不碰卡片也行；框住卡片时连在它们上面的线一并选中）；**平移**：空格 + 左键拖、鼠标中键拖、触控板双指滑动；右键拖不平移（右键留给菜单）。滚轮事件按一串里的第一个事件判断：小步长（< 30 像素）或带横向位移是触控板 → 平移，一格上百的物理滚轮 → 缩放，整串沿用这个判断；Ctrl+滚轮与捏合（浏览器给成 ctrl+滚轮）照旧缩放，卡片里可滚动的内容（`.nowheel`）自己滚。缩放范围 20% 到 **500%**。Ctrl+A 全选（编辑器与输入框里照旧）。已知局限：Mac 上的普通鼠标滚轮慢速滚动步长也很小，会被当成触控板而平移，用 Ctrl+滚轮缩放。
- **吸附对齐，卡片优先、其次网格**（类似 Obsidian）：拖动时被拖的卡片（多选时整体当一个外框）先贴齐其他卡片的边与中线（阈值 6 屏幕像素、不随缩放变），贴上出一条 1px 的强调色参考线；某个方向没贴上卡片就落到 8 单位网格。库自带的 `snapToGrid` 关了（它会在卡片吸附看到原始位置之前就把位置推走），网格由 `snapBox` 负责；松手那一帧的位置变化也吸，卡片停在参考线指的位置；**按住 Alt 两种吸附都关**。
- **编辑状态下也能缩放，缩放时同样吸附**：选中就有缩放柄（原地编辑时也有，编辑器跟着卡片变大）。规则同拖动——被拖的那条边先贴齐别的卡片的边与中线（6 屏幕像素内，出参考线），贴不上落到 8 单位网格，Alt 关；不动的那条边与不动的方向原样；吸完比最小尺寸（宽 160、高 72）还小就不吸。图片与视频只能等比例缩放：只在贴得上卡片时吸，吸完另一方向按比例跟，不吸网格。做法：`snap.ts` 的 `snapResize`（纯函数，单测），`CanvasFlow.onNodesChangeSnap` 里把库每一帧发来的 `dimensions`（+ 从左 / 上缩时的 `position`）整体吸一次再放行；要和**缩放开始时**的矩形比对哪条边动了（库每帧都按指针重算，不是在上一帧基础上改），所以开始时的矩形记在 `resizeStart`；缩放中的位置变化不能当成拖动去吸，否则从左 / 上缩时会错位。
- **拖拽落点只有一种样子**：2px 强调色描边 + 极浅蓝底（`--accent` / `--accent-bg`），树、文件管理器的行 / 面包屑 / 列表空白、侧栏、卡片库一致；不用「目标主机色铺底」（语义色不铺底）。同主机「移动」与跨主机「传输」只靠行尾标签的文字区分，幽灵条里的判定文字仍可带主机色（字，不描边不铺底）。
- **连线落点**：松在卡片范围内的任何位置都连到那张卡片，存档里的方向取离落点最近的边；拖线经过时目标卡片亮蓝框；松在连接点上的由 xyflow 自己连。（xyflow 按「离哪个连接点的中心最近且在 16px 内」判断，所以不能用铺满卡片的落点：它的中心就是卡片中心，只有正中央有效。）
- **连线盖在卡片上方**：连线自己画（`CanvasEdge`）分两层——透明的点击感应层（屏幕上 12px 宽）留在卡片之下，免得挡住卡片与连接点的点击和拖动；看得见的线、箭头与标签画在 edge-label 层里，层级高于所有卡片（含选中的，选中的卡片只排在别的卡片之上、仍在连线之下，所以不用库的 `elevateNodesOnSelect`）。框选连线时取感应层的路径做命中。
- **右键菜单**：空白处——新建卡片（落在点击处）/ 粘贴 / 全选 / 适应窗口；卡片——编辑 / 重命名 / 复制 / 删除卡片，还没保存的新卡片是 编辑 / 复制 / 从画布移除；引用——在预览里打开 / 复制 / 从画布移除，资源——另有删除文件（文件被几个节点共用时才有「从画布移除」）；链接——在新标签页打开 / 复制 / 从画布移除；选中多个——复制 N 个 / 删除 N 个；连线——反向 / 删除连线。点在没选中的节点上先只选它。菜单里「粘贴」尽量直接读系统剪贴板（浏览器会问一次权限），读不了就用页面里复制的卡片，再不行提示用 Ctrl+V。
- **复制粘贴**：Ctrl+C / Ctrl+V（在编辑器、输入框、选了文字时照旧）。复制选中的节点与它们之间的连线；系统剪贴板里同时放可读文字（卡片正文、链接地址、文件名），页面里另存一份带完整正文的剪贴内容，粘贴时系统剪贴板里还是那段文字才认它（中间复制过别的就不认）。粘贴：灵感卡变成**带正文的新卡片**（和新建的一样，保存时才建文件）、引用指向同一个文件的新节点、**资源指向同一个文件**（不复制文件），链接 / 文字 / 分组照搬；整体中心落在鼠标处，新节点被选中，不动鼠标连粘几次每次错开 24 个画布单位。项目文件引用只能粘回同一个目录，画布自己的资源只能粘回同一块画布（灵感卡哪里都行），放不进去的给提示。资源文件被几个节点共用时：Backspace 只拿掉这个节点，文件留着；最后一个节点才确认并删文件。
- **粘贴与拖入的落点**：鼠标在画布里就以鼠标处为中心（粘贴文件、粘贴链接、粘贴卡片、菜单里的粘贴都一样；拖入文件落在放下的位置也是中心），鼠标不在画布里（在工具条上等）就放到视野中心附近不压着现有节点的空位，必要时平移视野。
- **视频的拖动条**：播放中的 `<video>` 要自己接鼠标，整张卡片没处可抓；视频上沿有一条 20px 的拖动条（悬停或选中才显出来，没有 `nodrag`），抓它就能挪动卡片。
- **内容溢出的滚动条**：内容显示不下直接显示滚动条（不用先选中）。`NodeBody`（卡片、笔记、项目文件引用的内容块）`overflow-y: auto` 加自画的 `::-webkit-scrollbar`（8px，拇指用画布的中灰、悬停变深；全局的 `scrollbar-width / scrollbar-color` 会让它失效，所以放回 `auto`，这样 macOS 上也不是用时才显出的浮条）。**宽度用画布单位、不随缩放变**：滚动条占布局宽度，宽度随缩放变的话文字折行会跟着缩放档位变；代价是屏幕上的粗细随缩放变（缩小到 30% 约 2px）。**没选中（也没在编辑）时滚动条只是提示、不能交互**：否则中键拖画布时 Chrome 的中键自动滚动标识会在可滚动的内容上冒出来，一边拖画布一边滚内容。内容块自己 `pointer-events: none`，鼠标落到下面的卡片上（拖的是卡片、中键拖的是画布），里面本来要点的链接 / 按钮（视频的「播放」）/ `<video>` / `<audio>` 照旧接；**选中或编辑之后才能拖滚动条**，`NodeBody` 在冒泡前拦住按在滚动条上的 `mousedown`（按 `offsetWidth − clientWidth` 换成屏幕像素判断），所以拖的是滚动条、卡片不会被拖走；**中键按下一律 `preventDefault`** 去掉自动滚动标识（仍冒泡，画布照常被中键拖动）；选中后右边的缩放感应带原来骑在边上、里侧 16px 压着滚动条，内容溢出的节点（`NodeBody` 打 `data-scroll`）把带改成只留边外 16px + 边里 2px。滚轮规则不变（选中后才在卡里滚，没选中仍是缩放画布）。图片 / 视频的块、链接卡片、别处建的文字节点不加常显的滚动条。无头浏览器默认藏滚动条（`--hide-scrollbars`），验收这条要去掉该参数（`scripts/verify-canvas.mjs` 已去掉）。
- **拖进编辑器自动生成引用**：把树里的笔记 / 画布拖进笔记或灵感卡的编辑器，插入 `[[路径]]`（笔记去 `.md`、画布保留 `.canvas`，多个一行一条）；把文件管理器里的项目文件拖进来，插入标准 markdown 链接（图片用 `![名字](…)`），路径是相对**当前编辑的文件**（笔记所在文件夹、灵感卡所在的 `.cards`）的相对路径；文件不在画布所在的目录里（别的主机、目录之外）写 `[名字](file:主机:绝对路径)`，不写一路 `../` 出去的相对路径（挪个位置就断）。落点就是鼠标处。聊天输入框的拖拽不接这个；文件预览标签里的编辑器没接这个钩子（`mountEditor` 的可选项 `onDropText`）。
- **窄宽度的工具条**按**主区**的宽度（不是窗格：树栏占了位置）逐级收：640px 以下去掉缩放百分比与「新建卡片」的字 → 520px 以下「未保存」只剩琥珀点（`white-space: nowrap`、悬停有「未保存」提示，笔记视图一样）→ 440px 以下去掉缩小 / 放大按钮（滚轮照样能缩放）→ 360px 以下去掉「适应」与当前名字。图标按钮都带 `aria-label`。
- **添加到对话**：笔记视图的顶部条有「添加到对话」（预览态按渲染出来的选区、编辑态按编辑器选区，没选就是整篇），画布里卡片与笔记节点的右键菜单也有（引用整个文件，含没保存的改动，还没存成文件的新卡片没有）。内容进**标签借用的会话**（窗口里正在显示的第一个对话，`useAddToChat`；toast 写明是哪个对话，没有会话就提示先打开一个）的输入草稿，成为一条引用 chip，发送时拼成 `Quote <来源标签>` 加围栏块，所以 agent 看得到内容与出处。来源标签是 `主机展示名:.canvas 里的绝对路径:Lx-Ly`（`canvas/quote.ts` 的 `canvasFileLabel`）：编辑态的行号取自编辑器选区（`EditorHandle.selection()`），预览态把选区还原成 Markdown 原文（复用 `markdown/copySource.ts`）再到笔记原文里找行号，找不到（选区跨过了被渲染改写的写法）就只写路径；超过 `QUOTE_MAX` 的由 `makeQuote` 截断并注明。

### 笔记与树

- **笔记**：画布和笔记在同一棵树里平级，**笔记就是 `.canvas/` 树里的普通 `.md`**（与画布混放、可建子文件夹；没有 frontmatter 也没有特殊元数据，任何 markdown 工具都能读写）。**存储**：画布名是相对 `.canvas/` 的路径（§2），新画布建在 `.canvas/` 根、名字里写 `/` 就是子文件夹；`classify()` 有 `note` 种类；`_large` 的排除规则是通配的（任意深度）。**索引**：§5 的三段式（目录树 → 每块画布的节点与连线 → 每篇笔记在哪些画布上、链到谁）。**agent**：`canvas_edit` 的 `create_note`（路径逐段清洗、缺 `.md` 补上，已存在报错，可同时 `canvas` 放上某块画布）、`promote`（灵感卡 → 笔记，`to` 缺省是 `.canvas/<卡片名>.md`，节点留在画布上指向新路径）；`update` / `rename` / `delete` 也认笔记（改名只改最后一段、所有画布上引用它的节点跟着改，删除清掉所有画布上的引用；**所有笔记里指向它的 `[[…]]` 跟着改写**（写没写扩展名、别名、`#标题` 都照原样，代码里的不动；画布改名同理；删除不改写，那些链接在索引里显示成 `(missing)`）；同一批操作里改名之后，后面的操作看到的是改写之后的正文）；`place` / `unplace` 的 `file` 写 `.canvas/<相对路径>` 指一篇笔记。**界面**：画布上的笔记节点是单独的 `note` 种类，复用灵感卡的组件（渲染 markdown、双击原地编辑、画布级保存，读写走灵感卡同一套接口），上方一律标「笔记 · 路径」；它不属于这块画布，所以 Backspace / 菜单「从画布移除」只去掉节点、不删文件，复制粘贴出来仍指向同一篇笔记（只能粘回同一个目录），菜单里没有改名与删除；从文件管理器把 `.canvas/` 里的 `.md` 拖进画布，存成笔记路径（不是 `../.canvas/…` 的项目文件引用）；树里「新建」菜单的「新建笔记」（`POST /canvas/:env/notes`，路径可带文件夹）建出文件并在本标签的主区里打开；笔记里的 `[[画布]]` 与 `[[笔记]]` 在笔记视图的预览态里是可点的链接（画布卡片里的 markdown 不处理 wikilink；文件管理器里打开 `.canvas/` 下的笔记，预览标签里的链接也可点，开成画布标签或预览标签）。
- **树与笔记视图**：`.canvas/` 里的新建、改名、移动、删除都从标签里的树发起（CV3），因为只有这条路会机械地同步引用；agent 写仍只经 `canvas_edit`，读不拦，人类直接动文件只是约定。
  - **布局与两种模式**：左边树栏有**固定**与**悬浮**两种。固定：占位，右边缘可拖宽（160–480，默认 240，双击复位，记在浏览器里）。悬浮：树栏不占位，贴在窄栏右边盖在主区左侧、从顶上开始。**窄栏**（`CanvasRail`，40px）**永久驻留**，固定与悬浮两种模式下都在，底色是 `--surface`（同展开的树栏），右边一条线与主区分开，右边紧挨着树栏（固定的或悬浮的）时不画线、和树栏连成一体；悬浮的树栏**左边没有阴影、只有右边有**（`clip-path` 把阴影裁在左边与上下的盒边上：视觉上与窄栏连成一体、对右侧是个悬浮件）；**鼠标一移到窄栏上任何位置就立刻展开**悬浮树栏（没有展开延迟），移开 300ms 收回（悬停触发，不用点）；树栏里在做事（行内改名、菜单、拖拽、搜索框有焦点）时不收，做完而鼠标已在外面才开始计时。窄栏上的树按钮是手动开合：没开就手动展开，**悬停展开着时再点是改成手动（留着）**，手动展开的不因鼠标离开而收，Esc、再点按钮、点别处才收，手动展开后选了笔记或画布自动收。窄栏上还有两个快捷按钮「新建笔记」「新建画布」，点了直接弹出「位置 + 名字」确认框；**位置的优先级：树里选中的行（选中文件夹就在它里面，选中画布或笔记在它所在的文件夹）> 主区打开的东西所在的文件夹 > 根**，树里选中的行在树收起后由标签记着、再展开仍选中，主区换了东西就作废，头上的「新建」菜单同口径。以后的入口（比如关系图谱）也加在窄栏上。树栏头上的图钉按钮在固定与悬浮之间切换；**工具条上没有侧栏开关，树栏的入口只有窄栏上的树按钮**：固定着的树栏点它就是收起（改成悬浮），悬浮的是手动展开 / 收起；固定模式的「收起」就是改成悬浮（没有单独的「固定但收起」这个状态）。**标签窄到放不下「窄栏 + 树栏 + 320px 主区」时强制悬浮**（不改偏好，宽了回去），窄栏始终在。
  - **树**（通用组件 `ui/Tree`，见 skill `ys-ui-build` 的组件表）：画布、笔记、文件夹混排，同层文件夹在前、按名字排，没有手动排序；点文件夹展开收起，点画布或笔记在主区里打开；方向键 / Enter / F2 / Delete，Ctrl / Shift 多选，搜索；有没保存的改动的画布，行上有一个橙点；打开的东西在收起的文件夹里时自动展开上级；顶上「新建」菜单（笔记 / 画布 / 文件夹）与「全部展开 / 全部折叠」（一个按钮来回切换：有展开着的文件夹就「全部折叠」，一个都没展开就「全部展开」（含嵌套的），只展开了一部分时先全部折叠；没有文件夹时按钮禁用）；**新建对话框是「位置 + 名字」两栏**：位置是下拉（根与所有文件夹），默认是当前打开的东西所在的文件夹（从树里某个文件夹或条目的右键菜单进就是那个文件夹），可以改；名字只填最后一段，不手写「文件夹/名字」；画布的名字可以留空，在所选文件夹里用时间命名；点 `[[链接]]` 指不到时弹出的新建同样是这两栏（名字预填、位置是链接里的文件夹，不存在的文件夹标「新建」）。
  - **树栏记住浏览状态**：展开的文件夹与列表滚动位置按（环境 + 目录）存在浏览器里（`treeView.ts`，键 `ys.canvas.treeview:<环境>:<目录>`，经 `app/localState` 编码与防抖写），状态放在标签里（`useTreeView`）而不是树组件里——悬浮树栏收起时树组件会被卸载。刷新页面、关掉标签再开都还原。
  - **改名与挪动**：F2 或右键「重命名」是行内改名（只改最后一段、画布与笔记没写后缀就补上，撞名与非法字符当场报错），拖到文件夹行或树的空白处（= 根）是挪动，悬停在收起的文件夹上 600ms 自动展开，不能拖进自己的子孙；画布走 `PATCH /board` 的 `to`、笔记 `PATCH /note`、文件夹 `PATCH /folder`，**服务端一并改写所有画布上的节点路径与所有笔记里的 `[[…]]`**（见「笔记」一条）；画布改名时同名的卡片文件夹与资源文件夹同步改名；挪动的东西包含「当前有没保存的改动」的画布或笔记时拒绝，先保存或还原。
  - **删除**：右键或 Delete 先确认；只删一个笔记 / 画布时确认框写「有几块画布放着它、几篇笔记的 `[[链接]]` 指向它」（`GET /refs`），删文件夹时数里面有多少；服务端删笔记会去掉所有画布上的节点，删文件夹同理。
  - **主区与历史**：一块画布或一篇笔记，点树、点 `[[链接]]` 都压进历史，工具条有后退 / 前进；改名 / 挪动 / 删除后历史里的条目跟着改或去掉；指不到的 `[[链接]]` 点了弹出新建笔记（路径已填好）；打开的画布不是 store 里这块时才读进来（有没保存的改动先确认）。
  - **笔记视图**：读写走 `GET / PUT /card`（笔记与灵感卡同一套带基线的接口，写入记进画布仓库的历史），预览态渲染 markdown、`[[链接]]` 可点，编辑态是 CodeMirror，空笔记直接进编辑；Ctrl+S 保存；磁盘上的版本变了，没有未保存的改动就直接换成新的，有就提示；保存冲突沿用预览的 `ConflictDialog`；离开前有未保存的改动先确认。**树里拖笔记到画布**：dataTransfer 里放笔记路径（`application/x-yuanshu-canvas-notes`），画布的拖入处理认它、放一个笔记节点（已在画布上就提示）。画布上的笔记节点双击是原地编辑、右键「在预览里打开」是切到本标签的笔记视图。
  - **乐观更新**：树里的改名、挪动、删除先在界面上预演（树里立刻变，行内输入框立刻收起），请求在后台做；服务端出错就撤掉预演并弹提示（比如改名撞了同名）；做成之后只重取清单、不再重读没动的画布。`state.list` 是「服务端清单 + 还没确认的预演」，`state.confirmed` 是服务端确认过的清单：历史清理（清单里没有的笔记 / 画布从历史里去掉）与「当前画布没了就换到第一块」只看后者，否则在途的改名会把当前打开的东西误清掉。新建不预演（画布名可能被避让重名或用时间命名，要等服务端回话）。**不加持久的反向索引**：试过一版只读写真正引用它的笔记与放着它的画布的反向索引，本机上改名画布反而更慢（要先把全部笔记读一遍建索引，之后才省）；它与本地优先是同一个问题的两种解法，做了本地优先之后，「读全部文件找引用」发生在 Server 本机，只有真改了的几个文件才推远端，所以保持现状，等笔记量真成为瓶颈再说。
  - **笔记里的图片**：笔记预览里相对路径的图片按笔记所在文件夹解析、走画布 `/image`（读 Server 本机副本）；编辑区粘贴 / 从系统拖入图片 → `PUT /canvas/:env/note-asset`（`repo.startNoteAsset` / `finishNoteAsset`，与画布资源共用 `placeAsset`：重名 `(2)`、超过「进历史的资源上限」的放 `_large/`、不进 git），存进笔记所在文件夹的隐藏文件夹 **`.assets/<笔记名>/`**（`产品/访谈.md` → `产品/.assets/访谈/`，根目录的在 `.canvas/.assets/<笔记名>/`；笔记一多不能淹没文件夹），不是画布节点、不改任何画布文档；返回相对 `.canvas/` 的路径，界面写成相对笔记的标准链接 `![](./.assets/<名>/<文件>)`。**笔记改名**：资源夹改名、正文里指向它的相对链接改到新名（`assetLinks.ts`）；**挪到别的文件夹**：资源夹跟着走（目标已有同名资源夹报 `exists`）、链接不用改，原来的空 `.assets/` 收掉；**删除笔记**连资源夹一起删、删空的 `.assets/` 也收掉；挪 / 删整个文件夹本来就带着。`classify()` 有 `noteAsset` 一类（要先于画布资源的 `X.assets/` 规则判，否则 `产品/.assets/…` 会被当成画布「产品/」的资源；`/image`、`/media` 放行它，agent 的 `canvas_edit` 与画布资源一样不许改它）；画布自己的资源夹仍是 `<画布>.assets/`，与笔记的不是一个地方，同名也不冲突。
  - **画布标签的页面状态**：同一窗格可以开两个画布标签，各看各的：`useCanvasStore` 按**标签**（`tab.id`）各一份（不按「主机 + 目录」共用，否则同目录的两个标签会共用「当前画布」）；窗格只渲染当前标签，切走组件就卸载，所以浏览历史（`nav`，当前是画布还是笔记）存进标签记录的 `afx.cv`（`{stack: ["board:名" | "note:路径"], at}`，随布局保存、`persist.ts` 解析时校验），组件挂载时读回（`nav.ts` 的 `saveNav / loadNav`）。切走再切回、刷新页面，都回到原来看的那块画布或那篇笔记。

### 跨主机与目录之外的引用

引用节点可以指向别的主机、或本机上画布所在目录之外的文件。**存储**：`file` 存那台主机上的绝对路径，另加 `host` 字段（环境 id，Server 本机是 `local`）；JSON Canvas 保留未知字段，Obsidian 打开不受影响；目录之内的文件仍用 `../相对路径`、没有 host（画布跟着项目挪不失效）。文件信息表的键是 `host:file`（服务端 `refKey`、前端 `refKeyOf`），同一路径在不同主机上各是各的。**读取**：`GET /board` 的 `files` 里，远端引用由 Server 经那台主机的环境 stat、取预览；`/image`、`/media` 加 `host` 参数（`file` 必须是绝对路径），缩略图缓存键本来就含环境 id；**信任范围与文件管理器一样**（已登录就能读该环境上的绝对路径，不另加目录限制）。**主机连不上**（没激活、已删、读取中途断开）：FileInfo 带 `unreachable`，卡片显示「主机未连接，连上后刷新画布」而不是「文件缺失」；可用主机清单变化（连上或断开）时界面自己重取一次；这时 `/image` 等回 404。**入口**：从任意主机的文件管理器把文件拖进画布（目录之内用相对路径，其余存 host + 绝对路径）；双击在那台主机上开预览；标注是 `主机名:绝对路径`；复制粘贴时这类引用哪里都能粘。**agent**：`canvas_edit` 的 `place` / `unplace` 的 `file` 写成 `主机名:绝对路径`（主机名与会话地址簿同一份规则，但**相对画布所在的环境**：它叫 `local`，Server 本机不是它时叫 `server`，其余是连接名；也认环境 id，重名报错）；`directory` 参数写成 `<host>:<name>`，缺省是主目录，整批校验时探测文件在不在、主机连不连得上；`index.md` 里远端引用写成 `ref  主机名:绝对路径  "标题"`，**生成索引时不查远端**（每次保存都要生成，不为它们多跑网络往返）。

### 本地优先

远程目录的画布在 Server 本机有一份权威副本。

- **前提与对照**：只有**一个 Server 实例**，电脑、笔记本、手机都是它的客户端，远端只由 Server 写，所以**不存在多实例之间的同步冲突**；多个客户端同时改同一个文件，现有的「基线（mtime + sha256）不符就 409」已经挡着（`CanvasConflict`）。所以本地优先在这里是单写者的「写后台回写」：写落 Server 本地、推远端的动作排队后台做、失败重试且幂等，不需要三方比较、冲突副本与云端锁。对照过的做法：思源笔记（本地先写、后台周期同步、三方比较，冲突不合并而是把落败的整文件复制成新文档）、Obsidian Sync（Markdown 做文本三方合并，canvas 等其它类型一律最后修改者赢）、rclone bisync 与 Unison（两副本模型，上次状态当 base，mtime 只用来决定要不要重算哈希）；这里取最后一类最简化的形态。可选的三条路：以 git 为同步协议（JSON Canvas 合并必冲突且可能产出非法 JSON）、自建清单式同步、块级内容寻址（文件只有几十 KB，过度设计）；采用的是清单比对。推论：决定体验的不是传输算法，而是「谁有权写远端」——远端只由 Server 这一个同步 worker 写，清单比对推送就够；若远端还会被别的设备或人直接改，任何方案都得先定冲突策略。SFTP 没有 inotify，「远端变了什么」只能轮询 stat 目录树，所以本地优先是把全树 stat 挪到了后台，而不是消掉。
- **模型**：ssh 环境的 `.canvas/` 在 `<数据目录>/canvas/<环境 id>/<目录哈希>/.canvas` 有副本（旁边的 `mirror.json` 是清单），画布仓库的全部读写（含 git 历史、`index.md`、资源文件、缩略图）都落在副本上，**不再有网络往返**；远端是镜像，后台推。本机环境不做副本。
- **模块**（`packages/server/src/canvas/`）：`replica-env.ts` 的 `ReplicaEnv` 是个 `ExecEnv` 装饰器——`<目录>/.canvas/` 之内的路径转到本机副本（命令里 `quote` 过的 `.canvas` 路径与 cwd 一并换成本机的，副本里的 git 在本机跑），之外的（项目文件引用、别处的文件）照旧走远端，所以仓库、接口、缩略图都不用改；`mirror.ts` 的 `CanvasMirror` 管接入、推送与状态；`service.ts` 为每个 ssh 环境的目录建一对，并提供 `envFor / adopted / mirrorStatus / settle / close`。没配 `replicaDir`（只有测试）时 ssh 目录直接读写远端。
- **接入**：第一次用某个远程目录的画布时，把远端 `.canvas/`（除 `.git`）流式拉到副本（并发 8，只此一次），同时在远端把 `.canvas/` 排除出项目主仓库（只在接入时做）。**远端原有的 `.canvas/.git` 不再更新**（留在原处不动），**历史从接入起在副本里重新记**。接入之后接口不再为校验目录去 stat 远端。
- **推送**：不记操作队列，拿「清单」（上次推送成功时副本的样子：路径、大小、修改时间、sha256、远端文件的大小与修改时间）与副本现状比对，差异推到远端——新增、修改、删除、空目录，**内容相同的删加配成改名，远端 rename、不重传**；顺序是建目录 → 改名 → 写（并发 4，临时文件写完再 rename）→ 删文件 → 删空目录。重启、断线、重复触发天然幂等。最后一次改动后停 800ms 再推；失败按 2 / 5 / 15 / 60 秒退避重试；`.git` 与 `*.part` 不推；副本目录丢了报错、不会把远端清空。
- **远端被外部改过**（有人在远端直接改了 `.canvas/` 里的文件；约定上不该、但不拦）：推之前 stat 远端，戳与上次推的不一样且内容也不同，就先把它改名另存成同目录的 `<名>.remote-<时间>.<扩展名>`，再把元枢里的版本写到原位置；另存路径记进状态（最近 10 条，重启保留），工具条提示「远端有 N 份改动已另存」。**远端的改动不会并进元枢**（只在接入时拉一次）。
- **状态与界面**：`GET /canvas/:env/mirror?dir=` 返回 `{state: synced | pending | syncing | offline, pending, error, asides}`（本机环境为 `null`）；状态只反映「比对出了要推的东西」，碰了副本但内容没变不算待同步。工具条在非 synced 或有另存时露出一个小提示（转圈 / 琥珀点加文字，主区窄到 520px 以下只留点，悬停写原因与待推数），每 3 秒轮询，本机环境只问一次。
- **agent**：agent 读 `.canvas/` 走元枢：agent 的 read / grep / find / ls / bash 每次调用前先 `settle`，把还没推的推完（最多等 8 秒，远端不通就放行，那时 agent 对这台主机的工具本来也不通），所以它在远端读到的永远是新的 `index.md` 与卡片；`canvas_edit` 本来就写副本；写 `.canvas/` 仍被权限层拦。
- **退出**：Server 退出前先把还在去抖的提交冲掉，再尽量把没推的推完（最多 3 秒）；没推完的，下次该目录第一次被用到时接着推。
- **没做**：从远端拉取外部改动（要做就是同一份清单的三方比较）、副本体积管理（媒体全量落在 Server 上）、远端旧 `.git` 历史的导入、界面上的「立即同步」按钮。
- **验收**：单测 `mirror.test.ts` / `replica.test.ts` / `service.test.ts` / `tool.test.ts`；`scripts/verify-canvas.mjs`（真浏览器，含同步提示）、`scripts/verify-versions.mjs`（历史界面）。
