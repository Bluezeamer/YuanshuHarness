# 提示词送达：前缀、状态通知与占位工具

Author: bluezeamer
Status: 现行
Date: 2026-11-03
Verified: 2026-11-19（对着代码核对：`session/{takeover,frozen,state-map,delivery,call-tool,capabilities,tool-catalog,pool,environment}.ts`、`skills/runtime.ts`、`api/{sessions,studio}.ts`、`permission/extension.ts`，以及 web 端左轨会话菜单的「刷新上下文」入口）

回答一个问题：设置变了、会话回退或 fork 了，怎么让模型始终感知最新的「状态」，同时保护缓存前缀。能力、权限、模式、卡片本身的定义见 [`prompt.md`](prompt.md)。

## 1. 原则

1. **只承诺感知「状态」**：状态 = 我们生成的 system 通道各段（身份、规则、环境信息、隐私变量清单、目录清单、skill 清单……）+ 工具集合与调用方式 + 当前模式。**不承诺**感知上下文的变化。
2. **工作信息不是状态**：hook 回调、子代理后台结果、定时任务触发，作为 user 消息尾注，跟历史走，不清理。
3. **兼容性优先，接管而不是配合 pi**：不依赖供应商是否支持中途系统消息或工具增量，**统一一条路径**。
4. **前缀稳定是尽力而为，不是承诺**：进行中的会话保持前缀；fork 与回退逻辑上是一回事；缓存是否命中只取决于缓存有没有过期。
5. **自动注入的文本一律英文**：提示词设定、工具相关、通知、拦截 / 拒绝 / 错误原因，对齐模型训练语料；用户自己写的内容（预设、卡片、AGENTS.md）按原样发。

## 2. 总览

| 时刻 | 做什么 |
|---|---|
| 创建会话 | 写**冻结物**；有 user 段则写一条消息；不发通知 |
| 每次运行前 | 现算状态映射，与当前分支上最近的承载者（冻结物或通知）比较；有差异才写一条**状态通知**，附在本次请求里，不单独触发请求 |
| 回退 / fork / 树跳转 | 上面的比较自动覆盖，不挂入口；可执行工具集由服务端重设为当前配置；下一次运行多带一行当前目录 |
| 压缩 / `/reload` / 换模型 | **完整重建**：新冻结物 + user 段 + 新状态映射，旧通知随之失效 |
| 改 Agent 定义 / 切模式 / 增删工具 / 改 system 段 | 不写任何条目、不向会话扇出；下一次运行前的比较发现差异，才通知 |
| 改工具描述 / 描述覆盖 | 不通知、不生效，等重建 |
| 不进状态 | 两份 AGENTS.md 与全局附加提示词（只在重建时带上）、user 段、skill 动态加载、hook、子代理结果、定时任务、工具描述、当前目录 |

## 3. 机制

**3.1 接管。** 用 pi 的 `context_with_system` 事件（返回值原样发送，在 pi 恢复提示词与工具状态之后触发）：每次请求前把转录里 pi 写的全部 `role:"system"` 条目去掉，换成「当前分支上最近一份冻结物」渲染的开头系统消息，含工具声明。pi 自己的系统差异条目对模型不可见。
**可执行工具集与发给模型的声明相互独立**：可执行集由服务端每次运行前按当前配置设定（pi 回退时会按历史重置，不影响前缀）；冻结声明之外的工具 pi 照常执行。

**3.2 冻结物。** 会话文件里的 `custom` 条目 `yuanshu.head`，不进模型上下文，内容：渲染好的开头系统消息 + 工具声明 + 状态映射。分组条件的输入（`provider`、`model`）**不另存**，见下条与 `prompt.md` §5 S3。
- **重建 = 完整构建**：agent 定义组装出的系统提示词（身份、我们生成的各段、全局 AGENTS.md、全局附加提示词、项目 AGENTS.md；两份 AGENTS.md 是文件，此时重读，见 `prompt.md` S2）+ 工具 schema + user 通道的段（作为一条消息）。创建、压缩、`/reload`、换模型时执行。
- 条目跟着会话树走：fork / 回退自动沿用分叉点处那一份；重启读回。**取冻结物看整条路径上最近一份**（压缩折叠旧冻结物也要读得到）。
- `/reload`：等同完整重建，不另做清理；入口是输入框的 `/reload` 命令与左轨会话菜单的「刷新上下文」（同一个动作，`POST /api/v1/sessions/:id/reload`，运行中返回 409 `session_running`），菜单项旁标「缓存失效」，不弹确认框。
- 换模型：前缀本来就作废；每次运行前比较的是「按会话此刻的模型现渲染」的提示词文本与冻结物里的，不同就重建（换模型本身就破坏缓存；没有单独记条件输入）。

**3.3 状态映射与通知。** 状态 = 「槽位 → 值」。槽位：`tools`（启用的工具名集合，含框架工具）、`prompt.<段名>`（我们生成的 system 段，含内置的「环境信息」段 `prompt.environment`，见 `prompt.md` S4，**排除** `global_agentsmd` / `global_extra` / `project_agentsmd`）、`mode`（当前模式 id + 设定）、`skills`（会话此刻生效的技能：名字 → 描述；不记路径，路径随当前所在主机变，换目录不该触发通知）。
- **技能栏**：技能清单属于「状态」（§1 原则 1），所以映射有 `skills` 这一栏。每次运行前（`before_agent_start`，先于比较）看「全局 ∪ Agent 基线 ∪ 工作区勾选」的指纹（`SkillRuntime.signature`）变没变，变了就先把技能同步到会话当前所在环境（`SessionPool.refreshSkills`），再比较；新增的通知里给名字、描述（≤200 字）和 SKILL.md 在当前环境的路径，改了描述与移除各一句。冻结物里没有 skills 栏时，从冻结的开头消息里 `<available_skills>` 列过的名字还原（`skillsListedIn`），只对真正新增的技能通知。重建（压缩 / `/reload`）后 pi 重新渲染的技能段取会话**此刻**的技能（工厂的 `skills` 是函数），所以通知过的技能会进新的冻结物。同步失败 / 冲突的技能不进状态也不通知，看设置页的分发状态。
- 冻结物与状态通知（`custom_message` 条目 `yuanshu.state`）都带 `state` 字段存**完整映射**；通知正文只写与「分支上最近一份承载者」相比**有差异的槽**：`tools` 里新增且不在冻结声明里的给完整定义（经 `call_tool` 调用）、冻结声明里有的只列名字、移除给名字，`prompt` 段给文本 diff，`mode` 给进入 / 退出（含还原了什么）。正文写明「以最新一条为准」。
- 判据：每次运行前（`before_agent_start`）算「设置里应有的映射」，与**压缩后模型实际看到的条目**（`buildContextEntries()`，不是 `getBranch()`，后者含已被摘要折叠的）里最近的承载者比较；相同不发，不同才发。比较的是结构化状态（`sameState` 直接比各槽的值），不是通知文案，改文案不会被当成状态变化。
- 同一个判断覆盖：改设置、改 Agent 定义（会话是活引用，静默）、MCP 晚连接 / 断开、回退 / fork / 树跳转 / 重启 / 压缩后。**不做逐条求差**：反复增删工具时宁可偶尔重复。状态没变不重发。
- **模式不进冻结物**（冻结物的 `mode` 槽为空）：压缩重建后，比较发现「设置里有模式 X、冻结物里没有」，自动补发进入通知。

**3.4 当前所在目录。** 不进槽位。只在「上下文可能不连贯」的事件（fork、回退 / 树跳转、压缩重建、`/reload`）之后的下一次运行，在尾部带一行当前目录；触发取决于事件本身，不取决于状态比较有没有差异。这些事件都经过我们自己的入口，用一个待办标记；服务在事件与下一条消息之间重启会丢标记，后果只是模型暂时持旧目录，不防御。

**3.5 工具描述。** 只在重建前缀时变化；`tools` 槽的状态值只看工具名集合。覆盖在冻结时写进声明，不在请求层逐次改写（那会让前缀在会话中途变化）。

## 4. 占位工具

新增工具不能让模型直接调用（§5 P2：未声明直调 1/20），走**通用占位工具 `call_tool` + 尾部通知**。通知列出新增工具的签名与调用方式；重建前缀时，已用过的工具提升为正式声明。

- **形状**：`call_tool({ name: string, arguments?: object })`，社区应用层实现一致用 `name + arguments`。**不另设 search / describe**（那是为几十上百个工具设计的）；一次新增很多时通知退化为「名字 + 一行描述」，**等遇到这个规模再定**。这是我们通知的设计，**不是 pi 的行为**：pi 的 MCP 扩展不按数量切换暴露方式；本项目 MCP 工具只有 `direct`（直接声明给模型）与 `hidden`（不可达）两种暴露方式，没有 codemode 通道：会话开头连上的进冻结声明；重载后才新增的、或首轮没等到连上的，走占位通道通知。
- **实现**：pi 的 `model-only` 工具，`execute` 里调 `ctx.executeTool(name, args)`。pi 文档写明它走和模型直接调用**同样的校验、`tool_call` / `tool_result` 钩子与权限检查**，事件带 `parentToolCallId`，工具失败一律返回 `isError`；界面已有嵌套调用展示。已在冻结声明里的工具经占位调用也照常转发。
- **解析器由我们自己接管**（核心，纯函数便于单测），按序，每步失败就返回错误，不猜：
  1. 外层 `arguments` 声明为任意值，用 `prepareArguments` 预处理，校验交给我们（pi 的外层校验文案不带签名）；外层 JSON 本身畸形时 pi 在更早处抛错，拦不到，必要时用 `tool_result` 钩子补一句指引。
  2. **工具名**：去首尾空白与 `functions.` 之类前缀；大小写、`-` / `_` 差异在**唯一匹配**时接受；其余不近似接受，错误里给最接近的 1–3 个和当前全部可调用名。**不自动纠正模糊匹配**：工具有副作用，猜错比报错更糟。
  3. **arguments 归一**：省略 → `{}`；对象原样；字符串按 JSON 解析一次。失败只做两种确定性修复：去 markdown 围栏、去尾随逗号；**不用 json-repair 这类猜测式修复**（会静默改语义）。
  4. 顶层平铺（缺 `arguments` 但有别的键）→ 不自动搬，报错并给出改正后的完整调用。
  5. 按目标工具 schema 校验，复用 pi 导出的 `validateToolArguments`（保留其类型转换）；失败改写成三段式：哪里错（路径、期望、收到）→ 合法的是什么（签名、枚举）→ 怎么改（改正后的完整调用，字段拼错给 did-you-mean）。
  6. 执行；内层 `isError` 原样透传，不再包一层。
- **错误回报**：英文，`isError` 结果，三段式；解析 / 校验阶段明确写 "The tool was NOT executed"。依据：Anthropic 官方「写指令性错误：说明哪里错和下一步」。措辞对重试成功率**没有公开对照数据**，只能自己测。
- **权限与模式接线**：`call_tool` 自己权限放行、不出现在可勾选能力里（同 `ask_user` / `todo_write`，见 `permission/extension.ts` 的框架工具清单），审批发生在内层。`call_tool` 是框架工具（`prompt.md` E6），**不受任何模式拦截**。内层是否确实经过权限扩展的 `tool_call` 钩子，依据是 pi 文档，没有端到端验证（见 §7）。
- **模式限制靠钩子拦，被拦的工具必须留在可执行集**（§5 P5）：从可执行集去掉，模型只收到通用的 `Tool X not found`；留着由 `tool_call` 钩子拦，才收到我们写的英文原因（形如 "You are currently in plan mode; per its settings the tool bash is unavailable. This is a blocking error, nothing was executed."）。**不要用可执行集表达模式限制。**

## 5. 实测依据

均为离线 faux 模型（pi 的 `fauxProvider`）下的探针结论，除 P2 直连本地 vLLM 部署的开源模型（27B 级，并发 2）。探针脚本没有随仓库发布，下面只保留结论与成立条件。

| 编号 | 结论 |
|---|---|
| P0 | 回退（`navigateTree`）无条件把启用工具重置为回退点历史里的集合，pi 不补之后新增的；fork 我们传显式 `tools`，不从历史恢复；`setActiveToolsByName` 下一轮即生效，但只能在创建时白名单内切换 |
| P1 | 接管后，加工具、回退、回退后重设共 5 次请求，开头系统消息哈希完全一致；冻结声明之外的工具 pi 照常执行 |
| P2 | 每用例 20 次：正常声明 20/20；占位 `call_tool` + 尾部通知 20/20；不声明直调 1/20（模型回答「我只有 read 工具」）。局限：一个模型、一个工具、短历史、参数简单 |
| P3 | `custom` / `custom_message` 条目沿会话树走：回退丢掉之后的、fork 带走分叉点之前的、重启读回一致；通知出现在它所属用户消息之后 |
| P4 | 状态值比较：回退到 t2 补发 {A,B}；回到已有 {A,B} 通知的旧分支不补；设置改回 {A} 后回到旧分支补发 {A} |
| P5 | 从可执行集去掉 → `Tool bash not found`（pi 在钩子之前返回）；留着由钩子拦 → 我们写的原因 |

**读自源码、未实测**：①不支持中途系统消息的供应商，pi 把后来的系统消息折叠进开头，**请求里的 `tools` 取整段历史回放出的最终工具集，工具一变整段缓存失效**，只有两个标记都为 true（目前是 Anthropic 类）才用原生增量；②自定义消息 `display:false` 只影响 TUI，**模型照样看见**；③压缩丢掉保留区间里的系统条目，压缩条目自带「压缩时回放出的系统消息」；④`session.reload()` 会重新执行内联扩展工厂，闭包变量重置。

## 6. 实现要点

代码在 `packages/server/src/session/`。

1. **接管与冻结物**：`takeover.ts`（`context_with_system`）、`frozen.ts`。冻结物存 `yuanshu.head`，带渲染好的开头系统消息、工具声明与当时的状态映射；`yuanshu.rebuild` 标记使冻结物作废，下一次请求按那时 pi 回放出的状态重新冻结。作废触发：压缩成功、换模型、`reloadPrompt`（`/reload` 与左轨「刷新上下文」，二者同为 `SessionPool.refreshContext`，原地进行）。fork 读冻结物是自动成立的：分叉文件带走了分叉点之前的条目（有测试）。
2. **工具注册表装全 + 启用集合**：创建时让 pi 允许全部工具（`allowlist()`；MCP 一项只写通配 `mcp__*`，不写当时缓存里的具体工具名——pi 的白名单创建后改不了，见 `mcp.md` §12；**再加一个 `*` 放行包里的扩展注册的、名字不可预知的工具**，同时用 `excludeTools`（`EXCLUDED_TOOLS`）把 pi 自带但不归我们的 `powershell` 与三个 MCP 资源工具排除，见 `plugin.md` §3），每次运行前 `deliveryExtension` 把 pi 的启用工具设成「当前启用集合 ∪ 冻结声明里的」；声明里有而当前不启用的工具留在可执行集里，由 `tool_call` 钩子给出英文原因（模式点名模式，否则通用），不是 pi 的 `Tool X not found`。`pool.enabledTools(id)` 回答「现在启用了什么」（flows 清单用它）。
3. **能力求值** `capabilities.ts`（纯函数，顺序：基线 → 限定为 → 增加 → 减少 → 并框架工具）、**状态映射与通知** `state-map.ts` + `delivery.ts`：槽位 `tools`、`prompt`（身份与各段，含环境信息，不含 AGENTS.md 与全局附加提示词）、`mode`、`skills`；与最近一份承载者（冻结物、`yuanshu.state` 通知、`yuanshu.statemark`）比较，有差异才写通知；提示词段是**活引用**（每次运行现算，预设改了下一次运行就通知）。改会话能力（PATCH config）是下一轮生效 + 通知，`appliedAt: "next-run"`。
4. **占位工具** `call_tool` + 解析器 `call-tool.ts`（工具名容错、arguments 归一与两种确定性修复、顶层平铺报错、schema 校验三段式错误）；框架工具集中在 `delivery.ts` 的 `FRAMEWORK_ROOT`，权限扩展对 `call_tool` 自身放行（`switch_mode` 不放行：切换要人批，见 `subagent.md` §7）。
5. **模式送达**：会话存「可切换清单」（`modePresetIds`）与「当前模式」（`activeModeId`），模式的三种操作存在预设上（`capabilities` 对模式即限定为，另有 `capsAdd` / `capsRemove`，Studio API 可写）；进入 / 退出 / 切换由状态通知带上，user 通道文本并入；`switch_mode` 工具（模型自己切，结果里直接给通知，并记 `statemark` 免得下一轮重复）；`PUT /api/v1/sessions/:id/modes`；输入栏的**模式胶囊**（`prompt.md` M7）；创建面板里模式只进可切换清单，不取交集。子会话沿用父当前的模式，不能切换。内置模式 `plan` 限定为只读工具集，不带权限档（`prompt.md` M6）。
6. **工具描述覆盖读冻结物**：覆盖在冻结时写进声明，改覆盖等下一次重建才生效；保存后对新会话生效，已有会话要刷新上下文（重建前缀）才换上。Studio「工具」页显示的是模型实际收到的描述：会话创建 / 恢复时 `SessionPool.noteToolOriginals` 把目录里内置工具的原始描述（`session.getAllTools()`，不含覆盖）记进 `meta` 表（`ToolDescriptionStore.recordOriginals`，内容没变不写），页面读 `GET /studio/tool-descriptions` 的 `originals`；没有会话跑过时没有原文，页面如实说明、不给调优入口。
7. **自动注入文本是英文**：变量清单、目录切换 / 清单变化通知、目录提示段与附件区说明、两个 directory 工具的描述、中断通知、子代理通知（标记统一为 `[System notice]`）；`prompts/base/*.md` 是 pi 的英文原文。`ask_user`、`transfer_files` 与子代理 / 后台任务工具的描述也是英文。
8. **测试**：`takeover.test`（冻结 / 重启读回 / fork）、`delivery.test`（stub 模型端到端：前缀不变、进入退出模式、被拦原因、`call_tool` 转发、`switch_mode`）、`capabilities.test`、`state-map.test`、`call-tool.test`；真实模型冒烟 `test/live/agent-defs.live.test.ts`（激活只读模式后写文件被拒、没有模式时能写）。§5 里 P1、P3、P4、P5 的结论都由上面的测试覆盖。
9. **环境信息段**（`prompt.md` S4）：创建时间、各主机的系统事实与「被用户断开」状态，走状态映射的 `prompt.environment` 槽；git 分支有意不放。
