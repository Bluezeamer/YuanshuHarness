# agent 浏览器

Author: bluezeamer
Status: 现行（页面内容的清洗与交付见 browser-content.md；未实现的在 §9）
Date: 2026-11-14
Verified: 2026-11-19（对着代码核对：`packages/server/src/browser/`、`api/browser*.ts`、`store/baseline.ts`、`Dockerfile`、`scripts/check.sh`）

agent 做出来的东西（HTML 单页、起的服务）能在应用里立刻被用户看到、点到；用户和 agent 都不用关心它跑在哪台机器上。**Server 持有一个 Chromium（`playwright-core` 驱动），每个工作区一个浏览器上下文，里面多个页面**；agent 用工具操作，用户在「浏览器」标签里旁观、接管。代码在 `packages/server/src/browser/`、`api/browser*.ts`，前端在 `features/workspace/{browser,tabs/web}/`。

## 2. 页面与操作权

- **页面归工作区**，这样各 agent 之间可以交接；同一工作区的页面共用一个浏览器上下文（登录注入见 §5），跨工作区隔离；没有工作区的会话用只属于它的临时上下文。
- **只有两种状态**：agent 用 / 用户手动操作（`controller`），页面上一键切换「手动操作 | 交还 agent」。手动期间 agent 的输入类工具直接得到「用户正在操作」，不排队；只读工具照常。**不提供「指派给某个会话」的界面**。用户自己开的页面一开始就是手动态，点「交给 agent」后 agent 才能用。
- **所有会话能只读观察工作区的全部页面**（快照、截图、控制台）；**动手**只有在用的会话可以。别的会话要操作时：没人在用或在用的会话此刻没在跑一轮 → 自动认领，否则返回「页面正被会话 X 使用」。
- **引用计数**：页面记着「用过它的会话」（以根会话计，子代理并入父会话）。根会话**归档或删除**时从各页面去掉自己，集合空了就直接关闭（不是休眠）；用户页不参与计数，始终留在「我的」组；agent 页此刻正被用户手动操作时，会话没了就转成用户页。
- **休眠，只限制激活数**：每工作区最多 12 个、全局 30 个真页面，超限把最久没用、且不在被观看 / 接管 / 等交还的休眠（关真页面，留标题、地址、缩略图，点一下重新加载）；休眠记录每工作区最多 100 条。Server 重启与浏览器崩溃都等同于全部休眠，走同一条恢复路径。
- **`browser_handoff(页面, 原因)`**：默认阻塞，像 `ask_user`，聊天里出提问卡片、浏览器标签顶部出横幅，先答先得；可用 `job_start` 放后台。**方向按页面此刻的操作者自动定**：agent 的页面 → 请用户操作（登录、验证码），用户点「我已操作完成」；用户的页面 → agent 请求使用它，用户点「交给 agent」才切操作权（agent 不能自行夺取，同意也不放行高敏感站点的逐动作确认）。完成时给交还后的页面内容（与交出前的状态比，登录后地址变了走完整路径），拒绝原样回理由。聊天卡片上的提问是统一的弹窗模型（见 `chat-tab.md` §6）：选项「我已操作完成 / 拒绝」加始终在的文字框，写了字再点选项 = 带一句补充（完成时附在页面内容后），只写文字不点选项 = 拒绝并回话；页面横幅走自己的接口（`/handoff`，拒绝可写理由），两边先到先得。**`browser_show(页面, 说明?)`** 是另一回事：不阻塞地向用户展示一个页面，Server 向该工作区在线的界面广播一条提示（`show` 事件，不重放），用户点「查看」才切过去；结果如实写送达几个界面（0 个就说没送达），不通知 agent 用户看没看，要反馈用 `ask_user`。
- **agent 页上的文件页跟着文件刷新**（`pages/reload.ts`）：agent 控制、激活着的页面，若地址是文件页（`<环境>.files.localhost/<路径>`），就用 `WatchHub` 监听文件**所在的目录**（不递归、不按扩展名过滤，所以同目录的 css / js / 图片变了也刷新），变化（去抖 300ms）后 `reload`。监听的 key 带 `browser:` 前缀，与会话用的 key 互不串；只在页面状态变化时登记 / 退订，页面离开 agent 控制、休眠、换成别的地址或被移除都会退订。**用户正在操作的页面不自动刷新**，免得冲掉填了一半的表单。局限：目录里任何文件变化（比如 agent 往同目录写日志）都会触发刷新。

## 3. agent 工具

26 个工具，除 `browser_open`、`browser_pages` 外都带 `pageId`。**页面**：`browser_open`（网址 / 文件路径 / `主机名:端口`）、`pages`、`close`。**读**：`snapshot`、`screenshot`、`console`。**资源**：`assets`（列页面已加载的资源 / 按地址存进附件区）。**查**：`dom`、`network`（只读，给快照查漏补缺，见下）。**动**：`click`（目标 ref / 视口坐标 / 当前鼠标位置，`count` 1–3，左 / 右键）、`type`、`press`、`dialog`、`move`、`scroll`、`drag`、`nav`（back / forward / reload）、`upload`。**开发调试**（默认关闭的能力组，见下）：`exec`、`storage`、`request`、`route`、`emulate`、`cdp`（与 `network` 同组）。**人**：`handoff`、`show`。元素编号（`aria-ref`）来自 `ariaSnapshot({mode:"ai"})`，动作前先短超时探测，失效立刻报「编号已失效」，不干等 30 秒。

- **返回页面内容的工具共用一套机制**（open、snapshot、click、type、press、dialog、move、scroll、drag、nav、upload、handoff）：都带可选 `intent`，按「基线 + 元素级 diff + 完整路径」返回，规则与输出外壳见 [`browser-content.md`](browser-content.md)。动作的一行说明在 `ACTION:` 行（`click e12 ×2`、`type 5 chars into e12, per-key, Enter`）。
- **逐动作确认**：高敏感站点（`access.ts` 的名单）上 click / type / press / drag 每次都要用户确认（完全允许档不问，摘要里不放输入的文字）；move / scroll / nav 与纯观察不确认，但仍过租约（用户操作的页面一律拒）并写审计与回放；upload 沿用每次审批。
- **click / type**：`count` 2 是双击、3 是三击（选中一整段，所以不需要拖拽选字）；右键只对网站自己实现的菜单有意义（原生右键菜单无头模式下读不到）。`type` 缺省整段插入（快），页面依赖按键事件时用 `perKey: true` 逐键（慢，≤200 字符）；带 ref 仍是替换内容。不给目标的 click 点**当前鼠标位置**，没有位置报错并提示先 `move`。
- **鼠标位置**是页面级的持续状态：click ref 后记为元素中心，整页导航后清空。`move` 不用 `locator.hover()`（它改 Playwright 内部的鼠标位置，会和我们跟踪的不一致）。`drag` 是真实鼠标事件的按下 / 移动 / 松开（原生拖放与滑块都行），验证码类的拖动校验会检测轨迹，**不承诺成功**，这类页面请 `handoff`。`scroll` 只剩三个用途：触发懒加载、滚内部容器、截图前定位；读页面不需要滚（快照含全页）。**滚动后内容（元素树 / 文字）常常没变，所以 ACTION 行把页面位置作为事实写出来**：`(page y 0 → 800 of 8748)`，没动写 `did not move`（页面里的滚动容器吃掉滚轮时就是这样），到底 / 到顶加 `, at bottom` / `, at top`（agent 只看到 `NO CHANGES` 会误以为滚动没生效；懒加载本身在内置浏览器里会被滚轮触发，用 IntersectionObserver 页面验过）。**滚动后有限地等内容变化**（`engine/content-wait.ts`）：先固定等 300ms 让滚动事件跑完，再每 100ms 看一次两个信号——页面里新增的元素 / 非空文字（挂在页面里的 `MutationObserver`，只数 `childList` 的新增，不数属性与文字改写，状态挂在 `Symbol.for` 键上，页面脚本枚举不到）、滚动之后新发出且还没结束的请求（WebSocket / EventSource / ping 不算）。一个信号都没有，从滚动开始算满 800ms 就返回（没东西可加载只多等不到 1 秒）；有过信号就等「没有在飞的请求、且距最近一次新增 ≥200ms」，最多到 2500ms。加载快的页面不被强制多等。已知漏的：800ms 之后才发请求的站点（长防抖）、永不结束的普通 fetch（会等满 2.5 秒）；这时返回 `NO CHANGES`，agent 再滚一次即可（工具描述里写了）。实测（真 Chromium、本地夹具、加载延迟 700ms）：滚动事件触发与哨兵触发的无限滚动新内容都在同一次返回里（约 1.0 秒，此前是晚一拍的 `NO CHANGES`），加载 100ms 约 0.44 秒，到底没东西可加载约 0.85 秒，永不结束的请求约 2.57 秒且不抛错。
- **不做等待工具**：动作后的「稳定」只等 load 事件（`scroll` 例外，见上：它会有限地等内容变化），异步加载的内容常在点击之后才到，会看到「没变化」，agent 要再取一次（实测过 load + 网络空闲、DOM 静默都抓不全，只有「等某段文字」可靠；真有需要再给 snapshot 加 `waitFor`）。
- **截图**四种形态：视口（缺省，JPEG 1280×800，**绕过图片压缩设置**，图上像素位置就是 `x, y`）、`ref` 元素（PNG）、**区域**（`fromX/fromY/toX/toY` 两个视口坐标框一块矩形，PNG；跨元素、半个元素、大元素里的一段都行，与 click 同一坐标系，图上位置加上左上角偏移就是视口坐标；因为 ref 截图的粒度锁死在 DOM 边界而加）、`fullPage`（JPEG，高度上限 30000px，超出声明）；`ref` / 区域 / `fullPage` 三者互斥。元素与整页的说明文字写「这不是视口截图、坐标不能用于点击」，区域被缩小过时写「位置要按比例换算」，并都声明原图尺寸与**实际交给模型的尺寸**。`read: false` 只存附件、不给图。
- **控制台**：缓冲写入时把相同的消息（类别、级别、文字、地址一致）折成一组（`×n`），每页 500 **组**，挤出先挤最久没再出现的；`console` 输出按首次出现排列，每条 ≤500 字符、总量 ≤6000，`level` 取 `warn` / `error`；有省略（单条截断、超预算、缓冲挤掉过）时把全文存成附件并给 `FULL LOG:` 行。页面异常带栈首帧位置。带数字变化的消息（`retry 3/10`）不折叠，折叠要丢中间的值，属于有损。
- **DOM（`browser_dom`）**：快照是无障碍树，**设计上只含角色、名字、状态与 link 的 `/url`**（Playwright 的快照生成器只硬编码了 `url` 与 `placeholder` 两个元素属性）：图片 / 视频 / iframe 的地址、`data-src` 这类懒加载属性、form 的 action、`<area>` 热区、无标签的 video、`download` 属性都读不到。分工是「树负责高效导航，DOM 查漏补缺」。`browser_dom` 是**确定性读取，不带 `intent`、不经任何模型**（agent 用 `selector` 或 `ref` 自己圈范围；资源地址必须逐字准确，与「模型只给指针、事实只来自原树」一致）：`selector`（CSS，穿透 open shadow DOM，**每个 iframe 里各查一遍**，每个 frame 最多 200 个命中）、`ref`（快照编号，读该元素的子树）、都不给 = 整个文档（不进 iframe 内容）。输出一个元素一行、带全部属性（不预设「资源标签清单」，免得漏掉 `data-original` 一类写法），缩进表示层级；规整全部声明在头里（注释丢掉、script / style 正文、svg 内部与 template 只给长度说明、属性值 >300 字符与 `data:` 地址缩短、open shadow root 展开、隐藏元素**包含**）；根元素带浏览器算出来的值：`@box`（视口坐标，可直接当 click 的 x、y，iframe 里是框内坐标）、`@natural`（图片自然尺寸，`1x1` / `0x0` 多半是占位图）、`@src`（`currentSrc` 与 src 属性不同时）。内容 >12000 字符时只留前 6000 字符的整行，**全文（先过变量遮罩）存成 `dom-<页面>.txt` 附件**并给 `FULL DOM:` 行，后续分析用现有的读文件与搜索。不动清洗层的基线、不写审计与回放。页面里序列化成 JSON 串再带回（Playwright 自己的序列化器嵌套超约 60 层就抛 `object reference chain is too long`）。**为什么单设这个工具**：agent 要做资源整理与分析，而快照读不到资源地址，所以补一个确定性的 DOM 读取，不去改快照。**
- **网络（`browser_network`；属于默认关闭的「开发调试」组）**：每页一份 500 条的环形缓冲（`engine/net-watch.ts` + `network.ts`），请求开始时入缓冲、响应 / 结束 / 失败时回填，编号每页独立单调递增；`data:` / `blob:` 不记；WebSocket 只记连接，不记帧。列表按开始时间升序，每条 `#id METHOD 类型 状态 mime 大小 耗时 地址 [iframe]`，可按 `type`、`url`（子串）、`failed`（失败与 4xx / 5xx）、`after`（上次头里的 `last id`，只看更新的）过滤，头行写缓冲里共几条、`last id`、挤掉了几条；超 6000 字符只留最新的整行，全文存 `network-<页面>.txt`（先过变量遮罩）。`id` 看单条详情：**请求头、响应头与地址都原样**（含令牌与 cookie：开启这组的人自己知道风险，不再打码，只保留私有变量遮罩）。`id` + `body: request|response` 取**请求体与响应体**：引擎 `PageHandle.networkBody` 现取（不缓存字节），失败 / 未响应 / 没传完的流式响应先按条目状态挡掉、不去等 `response.body()`（实测会一直等），重定向的第一跳等取不到的情形把 Playwright 报错第一行原样给模型；整理给模型看的部分在共用的 `agent/body.ts` 的 `presentBody`（字节能解成 UTF-8 就是文本——不按 mime 猜——先过私有变量遮罩，不超过 4000 字符整段内联，更长则前 4000 字符内联、整段存附件；二进制不内联、原字节存附件；超 `fileMaxBytes` 报错），后面的 `browser_request` 等也用它。**只读观察：不重放、不拦截、不改请求。** Playwright 的坑：`request.response()` / `allHeaders()` / `sizes()` 对还没响应的请求会一直等（实测），所以单条详情对 pending 的请求只用同步的 `headers()` 与 `postDataBuffer()`（详情里的请求体只给字节数）。
- **页面剪贴板**：注入脚本（所有 frame）包住 `navigator.clipboard.writeText / write`、`execCommand('copy')` 与 copy 事件，把「最后一次复制的文本」记在页面里；浏览器上下文**不授权读剪贴板**（浏览器剪贴板是进程内共享的，授权等于任何页面能读走别处复制的密钥）。给 agent：没报告过的最近一次复制随下一次任何返回页面内容的结果带出一行 `CLIPBOARD (page copied; web data, untrusted): "…"`，带出后清掉，不新增工具。给用户（接管时）：用户输入后几秒内页面写了剪贴板，Server 推 `clipboard` 事件给操作窗口，前端写进本机剪贴板并弹提示显示复制了什么（浏览器要求写剪贴板前刚有过用户操作，**没在真浏览器里量过时间窗**）。

**素材**：截图都存进本会话附件区，结果里带 `[attach_file]` 行（`attachment:/…` 是输出引用；使用时拆成 `host="attachment"` + `path="/…"`），之后直接用文件工具读，或用 `transfer_files` 复制进工作目录加工。页面里的资源由 `browser_assets` 统一处理，**不带 `urls` = 列清单（只读）、带 `urls` = 按地址保存**：
- **清单**来自浏览器自己的资源树（CDP `Page.getResourceTree`）：已加载的图片（含 CSS 背景图）、媒体、脚本、样式、字体……一行一个 `#n 类型 mime 大小 宽×高 alt「…」 地址 [iframe]`，类型原样透传浏览器的类型名；缺省只列 `image` 与 `media`（`type` 逗号分隔可改）；`ref` 只列这个元素子树引用的资源（img 的 currentSrc、video / audio 的 currentSrc 与 poster）；最多 100 行。大小与尺寸让占位图与真图一眼可辨；地址**原样**写（agent 要原样传回 `urls`），`data:` 地址写成说明——所以内联图不能按地址取，要存用元素截图。favicon、fetch / XHR 不在资源树里（看网络请求是调试组的事）。
- **保存**逐个地址串行处理、取到就立刻落附件（不攒缓冲）：先从浏览器缓存取（`Page.getResourceContent`，不发新请求、与页面同一身份），取不到（媒体、已回收、从没加载过）再用本上下文的 `APIRequestContext` 发一次新请求（带 cookie、自定的 Referer、走本上下文代理，所以浏览器流量仍只有一个出口；响应头 `X-Yuanshu-Deny` 写成网络层的拒绝原因）；响应体读完即 `dispose`（Playwright 把它留在上下文里直到释放）。**清单内的地址免审批；清单外的地址只允许 http(s)，且与 `browser_open` 走同一套站点授权**（`resolveTarget` + `decideOpen` + `approveOpen`）。一次最多 30 个地址、单个上限沿用 `fileMaxBytes`；结果逐个列出（成功行带 mime、大小、`(new request)` 标记，失败行 `FAILED 地址: 原因`）；有新请求才写审计（只写 host）。**局限**：`APIRequestContext` 把整个响应读进内存、没有流式，对不支持 Range 的服务器上的大文件会整份进内存再按上限丢弃；资源树里没有的缓存取不到时 `data:` / `blob:` 无处可取。
- 页面里的**原生下拉框**不新增工具：`browser_type` 的 `ref` 指到 `<select>`（快照里是 combobox）时，`text` 就是要选的选项——先按 label 再按 value 精确匹配，`<select multiple>` 用换行分隔多项；没有匹配项时**不**调 `selectOption`（它会等到超时），直接报错并列出可选项（≤30 个）；禁用的选项报原因；ACTION 行写 `select "北京" in e12`。

**下载（agent 触发）**：`acceptDownloads` 开着，页面里的下载由 `engine/page.ts` 包成 `PageDownload` 交给订阅者，由 `downloads/windows.ts` 的**下载窗口**决定归谁：agent 的点击 / 按键 / 回车输入 / `browser_open` 期间（加 400ms 宽限）这个页面上开始的下载收进窗口，最多 3 个；窗口外的一律取消并在该页控制台留一条原因；用户操作的页面上的下载不进窗口，见下一段。收进来的逐个**审批**（卡片写文件名、来源页面与文件地址，可执行类扩展名加警示，**只有通过 / 拒绝、没有「记住」**；完全允许档不问，两种都写审计），通过后流式存进本会话附件区（`AttachmentDirectories.saveFrom`），结果里带 `[attach_file]`；大小上限沿用设置里的单个文件上限，超限丢弃并说明。`browser_open` 打开的地址若是文件下载（`page.goto` 抛 `Download is starting`），新开的页面会被关掉，结果说明「是文件下载，不是网页」。**局限**：Playwright 不能暂停下载，审批期间文件已在浏览器临时目录里下着（取消或存完都会删）；窗口只覆盖动作期间，服务端生成导出文件这类要等好几秒的下载会被当成「没有 agent 动作在等」而取消；每次动作在没触发下载时多等 400ms。

**下载（用户接管时）**：用户操作的页面（`controller === "user"`）上开始的下载，`downloads/windows.ts` 的 `dispatch` 交给 `downloads/pending.ts` **挂起**（每页最多 3 个、最长 10 分钟，超了取消），清单随 `PageView.pendingDownloads` 经现有的页面状态事件推给前端，前端弹「保存下载的文件」：**保存到本机**（浏览器请求 `GET …/pages/:pid/downloads/:did`，Server 暂存后流给用户自己的浏览器存盘，整个响应发完才结算；Server 与用户可能不在同一台机器）、**放进工作区目录**（`POST …/save`，写到所选 directory 的根下，重名自动加 ` (1)`，写入走该目录的环境、可能是 ssh 远端，`downloads/deliver.ts`）、**丢弃**（`DELETE`）。暂存文件在数据目录 `browser-downloads/`（0700），结算、页面关闭、超时都会删，Server 启动时清残留；单个文件上限沿用设置里的值，超限这一项在 Server 里作废（弹窗随之关掉，原因用提示条给）。**不**对可执行类文件加警示（那是 agent 下载才要的，这里是用户自己点的）。**局限**：同 agent 下载，Playwright 不能暂停下载，文件在挂起期间已在浏览器临时目录里下着；挂起项不跨 Server 重启，页面休眠会让没存的下载失败。

**上传（用户接管时）**：用户操作的页面里点「选择文件」，引擎的 `filechooser` 事件经 `PageHandle.onFileChooser` 交给 `uploads/pending.ts`**挂起**（每页只留最近一个，新的顶掉旧的，最长 10 分钟），随 `PageView.pendingUpload` 推给前端，前端弹「选择要上传的文件」让用户选**本机文件**，一次 `multipart/form-data`（字段 `files`）`POST …/uploads/:uid` 交给 Server，Server 校验后以**缓冲形式**交给页面（同 agent 上传，不交路径）；取消走 `DELETE`，什么都不交、页面保持原样。**校验**：只收一个文件的入口给了多个、单个文件超过设置里的上限、合计 ≥50 MB（`uploads/limits.ts`，agent 上传共用这一份）都拒绝，**这一项仍留着**，用户可以改选再来；请求体本身超过上限在流上就中止（413）。校验通过就先把这一项取走再交给页面，所以双击「上传」只会交一次。用户自己选自己的文件，不走审批卡片、不写审计。**局限**：挂起项不跨 Server 重启；页面导航后旧选择器失效，交文件会报错、这一项作废。

**页面脚本（`browser_exec`，开发调试组）**：`script` 是 async 函数体（可 `await`、用 `return` 给结果），在页面自己的 JS 环境里跑；给 `ref` 时多一个变量 `el`。执行走 CDP 的字符串求值，**不用 `new Function`**（带 CSP、没有 `unsafe-eval` 的页面里它会抛 EvalError）：表达式字符串要扮成函数的 `toString` 交给 Playwright，这样既不受 CSP 约束又能把元素当参数交进去（`engine/exec.ts` 的 `asFunction`）。结果在**页面里**序列化成 JSON（Playwright 自己的序列化有约 60 层的深度上限）：函数写 `[Function 名]`、DOM 节点写 `[Element <标签#id.类名>]`、环写 `[Circular]`、Map / Set / Error / bigint / NaN 各有固定写法，序列化抛错写 `[unserializable: …]`；脚本抛的异常写成 `THREW:` 加栈的前几行，工具本身不失败；30 秒超时（脚本仍可能在页面里跑，必要时关页重开）；对话框被脚本弹出时包进 `interrupted` 立刻返回说明。超过 12000 字符按整行留前 6000 字符并存附件 `exec-<页面>.json`（预算与 `browser_dom`、`browser_storage` 共用 `agent/budget.ts`）。动作类骨架：租约、高敏感站点逐动作确认（摘要只写长度）、审计与回放。

**Cookie 与 Web 存储（`browser_storage`，开发调试组）**：`kind` 选 `cookies` / `local` / `session`，`op` 缺省 `get`（还有 `set` / `delete` / `clear`）。Cookie 走浏览器上下文（页面脚本读不到的 HttpOnly 也读得到，带 `Secure`、`SameSite`、过期时间），`scope` 缺省 `page`（当前页面地址会带上的），`all` 是整个工作区浏览器里的；值**原样**返回（含会话令牌，开启这组的人自己知道风险）。Web 存储读写主 frame 当前源，按键名升序（Chromium 自己的顺序不是升序）。`get` 走 `observe`（用户正在操作页面时也能读）、不确认不审计；写操作走动作骨架，摘要只有名字不含值。坑：`sameSite: None` 不带 `secure` 时 Playwright 不报错、浏览器直接不存这个 Cookie；只给 `path` 不给 `domain` 时要转成 `domain + path` 形式（Playwright 不许 `url` 与 `path` 同给）。IndexedDB 与 Cache Storage 用 `browser_exec` 读。

**以页面的身份发请求（`browser_request`，开发调试组）**：用页面所在浏览器上下文自己发一次 HTTP 请求（`engine/request.ts` 的 `RequestJars`，每个浏览器上下文一份）：带这个上下文的 cookie 罐与代理出口，响应的 `Set-Cookie` 写回页面的罐；agent 的 bash 没有页面的 cookie 与出口，这是它的价值。**不自动加任何头**（要 `Referer`、`Origin`、`Content-Type` 自己给；实测 agent 自己给 `Cookie` 头时它**替换**而不是合并罐里的）。Playwright 的 `maxRedirects: 0` 会**返回** 3xx 响应（状态码与 `location` 头都在），所以缺省不跟随、3xx 原样给；`follow: true` 时由工具层逐跳跟随（最多 10 跳，301 / 302 / 303 把 POST 改成 GET 并去掉 body，307 / 308 保持），**每一跳都过站点授权**，被拒就停在那一跳并在 `REDIRECTS:` 里写 `(stopped: …)`。**站点授权收成 `kit.authorize`**：`browser_open`、`browser_assets`、`browser_request` 共用同一处（`decideOpen` 加 `approveOpen`），所有出网的浏览器工具都要守，不是调试组的围栏。非 GET / HEAD / OPTIONS 的方法在高敏感站点逐次确认（`kit.confirmAction` 的 `host` 参数按**请求目标**判断；跟随到别的主机时在新主机上再确认一次），摘要只有方法与主机。**命名身份**（`identity`，测越权用的「第二个用户」）：与页面完全隔离的 cookie 罐（自己的 `APIRequestContext`，同一个代理与 UA——`request.newContext` 默认 UA 是 `Playwright/…`，必须显式传），响应的 `Set-Cookie` 存进这个罐并被同名身份的后续请求带上，页面的罐与别的身份不受影响；只在内存，跟上下文同寿，每个上下文最多 8 个；结果末尾的 `JAR` 行只写 cookie 名字不写值。响应体走 `agent/body.ts` 的 `presentBody`（文本内联前 4000 字符，更长或二进制存附件 `request-<页面>…`；超限只写 `BODY: not saved — …`，状态与头照给）；`ctx.request` 的网络错误是 Node 层的（`socket hang up` 之类），不是浏览器的 `net::ERR_*`。工具只 `observe` 借上下文、不碰页面线程，对话框挂着也能发。

**拦截与改写请求（`browser_route`，开发调试组）**：规则挂在**单个页面**上（`engine/route.ts` 的 `RouteTable`，每条规则单独 `page.route`，删除时成对 `unroute`），页面关闭或休眠后唤醒就没了，不持久化；每页最多 20 条。`op` 缺省 `list`（带每条的命中次数），`add` / `remove` / `clear`。按 URL glob（`**` 跨路径、`*` 不跨 `/`；**query 也算在 URL 里**，`**/*.png` 不匹配 `a.png?x=1`）匹配，可再按 `method`、资源类型限定，`delayMs`（0–10000）造慢响应；**多条规则后加的先匹配**，命中并处理就不再往下传。四种动作：`block`（`route.abort`，errorCode 缺省 `failed`）、`mock`（不发请求直接 `fulfill`）、`modify`（`route.continue` 改方法 / 地址 / 请求体 / 头，头值 `null` 表示删；`continue({ headers })` 是**全量替换**，所以以 `request.headers()` 为底合并——拦截时请求还没发出，`allHeaders()` 会一直等，合并后头名全小写）、`patch`（`route.fetch()` 拿真实响应，状态码 / 头可改，`replace` 只对能解成 UTF-8 的文本体做字面量替换，替换过才删 `content-length` 让 Playwright 重算）。处理过程中任何一步抛错都吞掉并 `fallback()` 交回网络，事件处理里不外抛。**局限**：开着规则期间 Chromium 对这个页面的 HTTP 缓存失效（Playwright 的限制）；`Cookie`、`Host` 这类浏览器自己管的头 `continue` 改不动（实测删不掉），改 Cookie 用 `browser_storage`；`modify` 的 `url` 必须与原请求同协议，不同协议 Playwright 抛错、规则登记成功但对该请求不生效。**站点授权**：`modify` 给了 `url` 就在 `add` 时过 `kit.authorize`（请求会发到别处），其余动作不出网、不需要；高敏感站点的 `add` / `remove` / `clear` 逐动作确认，摘要只有动作与 pattern，不含 body 与头的值。

**环境模拟与 CDP（`browser_emulate` / `browser_cdp`，开发调试组）**：两者共用每页一个**懒建、长存**的页面级 CDP 会话（`engine/cdp.ts` 的 `PageCdp`，页面关闭才丢）——`Emulation` / `Network` 域的覆盖**跟着会话走**，会话一 detach 覆盖就失效，所以不能用完就丢；实测整页导航之后覆盖仍然生效。`browser_emulate`（`engine/emulate.ts` 的 `Emulation`）：离线与弱网合并成一条 `Network.emulateNetworkConditions`（kbit/s 换算成字节每秒，没限写 -1，任一项变了都带上另一项的当前值）、CPU 变慢、深色模式与减少动效（`emulateMedia` 没给的项会被重置，所以两项都带当前值）、UA 与语言（`setUserAgentOverride` 必须带 UA，所以第一次碰 UA / 语言时先读并记住原始 UA，撤销时发回；空 `acceptLanguage` 保持浏览器默认）、时区、关缓存。**只改给了的项**，`reset: true` 先撤销全部；什么都不给就是只读当前状态（走 `observe`，不确认不审计）；某项失败时之前成功的项保留、失败项不进状态。**视口固定 1280×800 不能改**（全项目的坐标约定）：要模拟设备尺寸自己用 `browser_cdp` 发 `Emulation.setDeviceMetricsOverride`（坐标会错位，用完要撤销；`clearDeviceMetricsOverride` 会把 Playwright 自己设的视口一起清掉，不要在要继续用的页面上做）。覆盖只在这个页面存活，休眠后唤醒就没了。`browser_cdp`：`method` 写成 `Domain.method`、`params` 对象（序列化后 ≤ 100000 字符），30 秒超时，**只发命令、收不到事件**；结果按 `browser_exec` 同一套预算（`agent/budget.ts`，超 12000 字符存附件 `cdp-<页面>.json`，先过变量遮罩）；报错取第一行（保留 Playwright 的 `Protocol error (…)` 前缀）；摘要只有方法名，不含 params。两者都走动作骨架（租约、高敏感站点逐动作确认、审计与回放）。

**开发调试组的取舍**：组默认关闭，开启即表示知道风险，所以组内工具不打码、不加白名单，只保留项目通用的两件事（高敏感站点的逐动作确认、私有变量遮罩）和**站点授权**（出网的浏览器工具都要守，`kit.authorize` 一处）。已知边界：`browser_exec` / `browser_cdp` 在页面里能 `fetch` 或跳转到任意地址，不会弹站点授权卡片，只受出口代理的硬限制——这是「脚本能做的事与页面自己的脚本一样多」的直接后果；要让授权覆盖到它们，得在代理层按工作区的授权状态拦，那是另一个设计。

**JS 对话框（`browser_dialog`）**：Playwright 在页面没有 `dialog` 监听时自动关掉所有 alert / confirm / prompt / beforeunload（confirm 被当成取消），agent 既看不到也答不了；有监听时它把对话框挂着、**页面主线程被阻塞**，快照、截图、点击都会一直等。设计是「引擎挂起、人来答、没人答就超时」：`engine/dialog.ts` 的 `watchDialogs` 是唯一碰 `dialog` 事件的地方，挂着一个（同时只留一个，新来的直接取消）、`120 秒`没人回答自动取消；`PageHandle.dialog() / answerDialog() / onDialog()`；会下发输入或触发导航的引擎方法都包进 `interrupted(...)`——**动作被对话框打断时立刻返回**（动作的后半截在对话框被回答后自己收尾，结果不要了）。agent 侧：`kit.content` 在对话框挂着时不取快照、不调清洗器，返回固定外壳 `BLOCKED BY DIALOG: <type> "<原文>"` + 怎么答；`registry.use` 是**唯一的守卫**，对话框挂着时拒绝一切会碰页面线程的工具（`dialog_pending`，文字直接给模型看），只放行纯内存读取（`browser_console`、`browser_network`）与接管相关（`allowDialog: true`）；`browser_pages` 每行末尾括号里的状态标志带 `DIALOG: <type>`。`browser_dialog { pageId, accept, text? }` 回答（prompt 不给 `text` 用页面的默认值），高敏感站点照例逐动作确认、摘要不带输入。**用户侧先答先得**：`PageView.dialog` 随页面状态事件推给前端，界面弹「页面提示 / 页面请求确认 / 页面请求输入 / 要离开这个页面吗」（`DialogPrompt`，关闭等同取消，不用原生弹窗），经 `POST …/pages/:pid/dialog { accept, text? }` 回答；已被别处答了回 409 `no_dialog`，agent 随后的 `browser_dialog` 同样得到「没有等待回答的对话框」。回放：对话框挂着时 `acted` 不记这一步（回放要截图，会挂 30 秒）。**局限**：对话框不跨页面休眠与重启；同页多个 frame 同时弹时只留第一个。

**动作后告知新开的标签页**：点 `target=_blank` 的链接、页面 `window.open` 都会开出新页面，登记表把它登记成新页面（`registry.adoptPopup`，继承来源页面的归属）；为了不让 agent 自己列页面才知道，`registry` 为每个工作区记一份弹窗日志（`popupSeq` / `popupsSince`，最近 50 条），`kit.content` 把「本会话用过的页面新开的、还没报告过的」写成一行 notes：`NEW PAGE: <页面> "<标题>" <地址> (opened by <来源>) — pass this pageId to work with it`，与剪贴板提示同一处带出；游标按工作区、第一次遇到只定游标。**已知**：页面数到上限时弹窗会被直接关掉（`adoptPopup` 不为它休眠别的页面），这种情况没有提示。

**上传（agent 触发）**：`browser_upload(pageId, ref, files)`，一次 1–5 个文件。**来源硬边界**（`agent/upload.ts`，不随审批档位变，越界直接拒绝、不弹卡片）：文件必须在本会话可见的 directory 之内（工作区目录或附件区，与 `transfer_files` 同一范围；`host` 参数对 `files` 整体生效，写法同文件工具），`realpath` 跟随符号链接之后仍在其内，不在敏感名单里，是普通文件；工作区之外的文件先用 `transfer_files` 复制进来（那一步自己有审批）。通过后**每次审批**：卡片写文件（名字、大小、来源）与**目标站点（取页面此刻真实地址的 origin，不用模型自己写的）**，**只有通过 / 拒绝、没有「记住」**；完全允许档或工具规则放行时不问，两种都写审计。审批在交出文件之前。`ref` 指到 `<input type=file>` 本身就直接设文件（隐藏、被盖住的也行），指到别的元素（自绘的上传按钮）就点它并接住弹出的选择框。文件**以内容形式**交给浏览器（读进内存），不交路径：浏览器是等页面真正读文件时才读的，交路径再删源文件会让页面读到 `NotFoundError`、表单提交上去是空字节。**上限**：单文件沿用设置里的单个文件上限，且所有文件合计 <50 MB（Playwright 对内容形式负载的界限），超限在弹卡片前就报错。**局限**：卡片里的目标站点是页面地址，页面里的表单可能把文件提交到别的站点，不解析表单；页面一收到文件就可能自己上传，所以审批必须在交出之前。

## 4. 网络与授权

- **自由 URL，默认拒绝**回环、内网、链路本地、元数据地址与 Tailscale 网段；公网目标先自己解析、校验全部结果、再连已校验的 IP 字面量（防 DNS 重绑定；遇到 fake-ip 解析时忽略被拦的结果）。代理用 Basic 认证，用户名是上下文令牌，据此知道请求属于哪个工作区，也拒绝本机别的进程借用。**下载不在代理层拒绝**：上下文开着 `acceptDownloads`，页面里的下载由下载窗口收集，agent 触发的逐个审批后存进附件区，用户接管时由用户决定存到哪，窗口外的一律取消（见 §3「下载」两段）。
- **`browser_open` 的放行**（工具层，`SELF_GATED`；档位 full 或工具规则放行则直接开）：本工作区文件免审批；外部站点首次出审批卡片，批准的来源按**工作区**记在内存（重启重批）；`主机名:端口` 的服务：端口在「见过的」里或来源已批准才放行，否则出「允许 agent 访问这个服务？」卡片。邮箱、云控制台、支付、代码托管这类高敏感站点每个动作都确认（档位 full 下跳过）。
- **端口发现**（`ports/`）：在 bash 输出这一层（前台与后台任务都经过，遮罩之内）认 `localhost / 127.0.0.1 / 0.0.0.0 / [::1] / [::]` 加端口，记成这个工作区在这个环境上「见过的端口」（`PortBook`，内存、每工作区 64 条）；环境 id 在命令**启动时**取，不是输出到达时。`GET .../browser/ports` 只列见过**且此刻真在监听**的（经 `openTcp` 连一下，800ms），页面列表里据此有「在监听的端口」栏。
- **代理层只按环境放行，不按端口收窄**：它分不清请求出自哪个页面，收窄会误伤「5173 的前端直接调 8000 的后端」；唯一例外是本机环境上 **Server 自己的端口一律拒**。**已知并接受**：输出是 agent 能影响的（`echo localhost:5432`），「见过」不是强授权，与 bash 本身已能 `curl` 同一类端口相比没有新增能力，不为此做进程归属检测。
- 远端环境的端口走 `openTcp` 的 ssh 隧道（`proxy.ssh.test.ts` 用回环上的真 sshd 测过整条链：HTTP、CONNECT 双向字节、端口没服务、sshd 禁止转发；后两种在页面上给出人话原因）。这条隧道没有本地监听；给用户自己的浏览器用的转发由服务转发承担，见 [`forward.md`](forward.md)。

## 5. 登录态

**全局、一个站点一份**（站点 = 注册域，`tldts`；`server.localhost` 这类环境别名算站点，纯 `localhost`、IP、单标签主机名不算）。存 `storageState` 里属于该站点（含子域）的 cookie 与 localStorage / IndexedDB（不含 sessionStorage），整段 JSON 用密码库同一把主密钥 AES-256-GCM 加密落库（表 `browser_logins`，`store/seal.ts` 共用）。**授权式注入**：保存即授权，默认启用，设置页「浏览器」每个站点有「允许 agent 使用」开关，新建工作区上下文时注入已启用站点；**保存或重新启用一个站点的那一刻**，把该站点的 cookie 与 localStorage 补进此刻已开着、且里面这个站点还什么都没有的上下文（`LoginService.spread` → `BrowserCtx.seed`：cookie 直接加，localStorage 靠每个源一个临时页写，临时页不出网、不被当成弹窗收养；已有该站点任何状态的上下文不覆盖，IndexedDB 补不进已存在的上下文所以不补；关着开关时保存、删除、关闭开关都不动已开着的上下文）。已经停在该站点的页面不会自己刷新，agent 下一次导航或刷新才生效。一个读不出的站点（换过主密钥）跳过，不能拖垮所有工作区。**什么时候问**：页面 `controller` 从 user 回到 agent 时，前端查 `GET .../pages/:pid/login`，站点状态与已保存的指纹（cookie 的 domain / path / name / value + localStorage 的 key）不同才提示；触发点是页面事件流里的这次变化，工具条、接管横幅、聊天卡片三条路都落到这一处。手动态工具条另有「保存登录」。清除分单个站点（点两下确认）与清空全部（确认弹窗）。审计只记站点与动作，不记内容；接管期间的画面不落盘、不进审计。

## 6. 画面流、输入与回放

- **画面**：原生 CDP `Page.startScreencast`，固定 1280×800（不推 2 倍帧：体积约 3 倍、慢链路更卡，高分屏上偏糊是已知取舍；视口不跟窗格走：会让页面按窄屏重排），`everyNthFrame: 1`，最高 30fps；多个窗口共用一路画面，新窗口补发最后一帧。**流控**：客户端每收一帧回 `ack`，连接层 `FrameWindow`（128KB）限制已发出未确认的字节，满了只留最新一帧，最后一帧不丢。推流启动失败（比如启动期间页面刚被关）会给观看的窗口一条警告条，不静默；启动期间句柄已被换掉的旧推流失败不报。
- **输入**：`input`（鼠标、滚轮、按键、整段文字）、`nav`、`copy`、`take`、`ack`（`ack` 与回前台探活用的 `ping` 由连接层直接处理，`ping` 回 `pong`，不进中枢）；只在页面由用户操作、且该连接是操作窗口时被接受（四道门禁，坐标越界拒绝不夹取）。**同连接的消息按序处理**（否则点输入框后马上打字会丢首字），排队中相邻的鼠标移动只留最后位置、滚轮位移相加（`mergeInput`），否则每秒几十条 move 把点击排到几秒后。**中文**在前端一个看不见的 textarea 里组词（焦点在普通 div 上浏览器不启动输入法），结束后一次 `insertText`。**剪贴板**：Ctrl+V 把本机剪贴板文字一次插进页面；Ctrl+C 经 `copy` 消息取页面里选中的文字（只认焦点所在的文档，旧文档里残留的选区不算），回给发起的窗口由前端写剪贴板；没选中就不动；右键、剪切不开放。
- **回放**：agent 的动作类工具（`open`、`click`、`type`、`press`、`scroll`、`nav`、`upload`、`handoff`，以及开发调试组里会动页面的那些）完成后，在写审计的同一处（`kit.acted`）截一张当前画面（页面上挂着对话框时跳过这一步），存 `browser_steps` 行 + `<数据目录>/browser-replay/<会话>/<步>.jpg`，按根会话记，输入的文字只记字数，每会话留最近 300 步；会话**删除**时清，归档不清。画面是页面当时的样子：明文输入框里打的字会在图里（密码框浏览器自己遮），图只存在本机数据目录。界面见 §7。

## 7. 前端

- **标签 = 工作区级的「虚拟浏览器窗口」**：页面由 Server 持有，标签只记当前显示哪一页；同工作区的所有 web 标签共用 `features/workspace/browser/` 的 store 与一条事件流（`WS .../browser/events`），关标签不关页面。要同时看两个页面就在列表行上点「在新标签打开」。
- **自动出标签**：agent 用浏览器工具时，没有任何窗格持有浏览器标签 → 新开窗格；有但在后台 → 切过去并显示新页面；已在前台 → 只出「有新页面」小条。不抢输入焦点。
- **单行工具条两态**：观察态（agent 在用）= 页面入口 + 只读地址 + 控制台 / 回放 + 「手动操作」，画面区吞掉鼠标键盘；手动态 = 后退 / 前进 / 刷新 + 可编辑地址栏 + 控制台 / 回放 / 保存登录 + 「交还 agent」，画面区外一圈强调色描边。窄窗格按容器宽度分四档降级、最后收进「…」菜单，见 [`layout.md`](layout.md)。
- **页面列表**（悬浮面板）：「我的」置顶，其余按最后使用的会话分组（组头按会话状态画点：执行中脉动、待处理琥珀、待命不画，与左轨会话行同一套），休眠灰显，底部是「在监听的端口」栏与「打开地址」。**控制台抽屉**默认隐藏，与 agent 的 `browser_console` 读同一份缓冲（只在内存、不记请求响应正文、地址里的令牌参数打码）。**回放视图**：会话下拉、上一步 / 播放 / 下一步、滑块、当前步说明，开回放时实时画面流断开。引擎状态（安装进度、失败原因）与**沙箱降级的醒目警告**在浏览器标签与设置页「浏览器」里都有。
- 文件预览里的 HTML：「预览」态内嵌运行（自包含单页，沙箱不给同源），工具条上另有「在浏览器中打开」，把文件页交给这里的浏览器标签（相对路径资源只在这条路上有效）；见 [`files.md`](files.md) §1。

## 8. 部署、隔离与镜像

- **安装**：跟 Server 装的只有 `playwright-core`；Chromium 本体第一次有人用浏览器时由它自带的 CLI（`install chromium --no-shell`）下载到数据目录 `browser/`，标签里显示进度，agent 的调用等装完再继续。`YUANSHU_BROWSER` 指向自备可执行文件（优先级最高，跳过安装），`YUANSHU_BROWSER_AUTO_INSTALL=0` 关闭自动下载。**下载镜像**：设置页「浏览器」里填（存在全局默认值的 `browserMirror`，每次安装现读，优先），留空时认环境变量 `PLAYWRIGHT_DOWNLOAD_HOST`；下载失败的提示里写明下载源与这两条换法。**系统运行库不自动装**（要 root）：缺了就在界面与工具报错里给 `npx playwright-core install-deps chromium`。
- **尽力隔离，不是硬边界**：浏览器进程与 Server 是同一个系统用户。分层做的：①**显式开 Chromium 沙箱**（Playwright 默认关），起不来就**降级无沙箱并醒目警告**（写明原因、风险、修法）；root 下沙箱根本起不来，直接降级；②**清洗环境变量**，浏览器只看见 `PATH`、可写的 `HOME`（数据目录下 `browser/home`）、`LANG`，Server 的令牌与模型密钥读不到；③流量全走代理（约束沙箱内的页面，被攻破的主进程可绕过）；④一次性配置目录、权限一律拒绝、关扩展与非代理 UDP / QUIC；UA 去掉 `Headless`、关 `AutomationControlled`，不做验证码求解与指纹伪造。**做不到的**：沙箱被突破后，浏览器主进程能读 Server 用户可读的一切（含数据目录里的主密钥、`~/.ssh`）。**所以默认是尽力，推荐浏览器单独起一个容器。**
- **emoji 显示成方块是 Server 所在机器的问题，不是浏览器自己缺字体**：页面画面是 Server 本机的 Chromium 渲染的，Chromium 与 Playwright 都不带字体，彩色 emoji 全靠系统（fontconfig）里有没有 Noto Color Emoji 这类字体；没有时退到 DejaVu 里零星的黑白字形，其余是方块。**两种修法**：装系统包（Debian / Ubuntu：`apt install fonts-noto-color-emoji`，装完重启 Server）；没有 root 权限就把 `NotoColorEmoji.ttf` 放进数据目录下的 `browser/home/.local/share/fonts/`——浏览器的 `HOME` 就是 `browser/home`（见上面的环境清洗），Chromium 经 fontconfig 默认会扫 `$HOME/.local/share/fonts`，已实测放进去就能出彩色。**自动探测**：引擎启动后在探针页里把 😀 画到画布上查有没有彩色像素（`engine/launch.ts` 的 `EMOJI_PROBE`），结果放进 `EngineState.emojiFont`；缺字体时浏览器标签顶部有一条警告写明两种修法（`WebTab`，同沙箱降级那条）。探针出错按「有」处理，不吓人。不自动下载字体：几 MB 的二进制要配镜像与校验。
- **Docker 镜像**（`Dockerfile`）：Debian slim 底座 + Playwright 的 21 个运行库 + 中文字体与彩色 emoji 字体（`fonts-noto-color-emoji`；页面画面是 Server 这台机器上的 Chromium 渲染的，机器上没有 emoji 字体页面里的表情就是方框，**不用 Docker 直接在主机上跑时要自己装一份**，Debian / Ubuntu 是 `apt install fonts-noto-color-emoji`）+ 构建期装好的 Chromium（版本取自 `packages/server/package.json` 里 `playwright-core` 的版本，所以与 Server 一致；放 `/opt/browsers`，`YUANSHU_BROWSER` 指过去，因为引擎会把 `PLAYWRIGHT_BROWSERS_PATH` 改指数据目录），非 root（uid 1000）；整个镜像压缩后约 350MB（解压 950MB，其中 Chromium 约 270MB），不装 Xvfb、mesa。国内构建用 `--build-arg` 换源：`DEBIAN_MIRROR`、`PLAYWRIGHT_DOWNLOAD_HOST`、`npm_config_registry`。
- **跑容器时要带的**：非 root 下默认 seccomp 禁用用户命名空间，沙箱起不来（实测报 `Chromium sandboxing failed!`），所以用 Playwright 的 seccomp 配置（`config/docker/seccomp_profile.json`，原样取自 microsoft/playwright，见 `NOTICE`）；`--shm-size=1g` 代替 `--ipc=host`。不用 `--privileged`，不挂 `docker.sock`，不挂数据目录以外的主机目录，保持 Docker / runc 更新：
  ```bash
  docker run -d --name yuanshu -p 7420:7420 -e YUANSHU_TOKEN -v yuanshu-data:/data \
    --security-opt seccomp=config/docker/seccomp_profile.json --shm-size=1g yuanshu
  ```
  不带 seccomp 配置也能用，只是沙箱降级（浏览器标签里有警告）。**Ubuntu 24.04 宿主的 AppArmor 限制非特权用户命名空间，没测到**；不选 Alpine（Playwright 1.65 配 Alpine 的 Chromium 能启动但 `newPage()` 不返回）。
- **验收**：`scripts/smoke-image.sh` 含浏览器用例（容器里真开一个页面、沙箱要开着）；`scripts/verify-browser*.mjs` 真浏览器脚本由 `scripts/check.sh` 串着跑，各自覆盖的内容见 skill `ys-delivery`。

- 用户接管时的上传，「从工作区文件里选」：现在只能选用户本机的文件，从工作区目录里挑文件交给页面还没做。
- 远端浏览器（Playwright `connect`）：引擎层对外只暴露 `engine/types.ts` 的类型、上层不碰 Playwright，但没有远端实现。

**明确不做**
- 用户页本地渲染与「分享给 agent」；让用户在自己的浏览器里用环境里的服务由服务转发承担，见 [`forward.md`](forward.md)。
- Host 白名单（防 DNS 重绑定）：合法主机名无从预知，不做。已有的防线是校验请求的 `Origin`（`auth.ts` 的 `originAllowed`，HTTP 与 WebSocket 都查，细则见 `docs/deployment.md`）：Cookie 认证去不掉，画布的图片与音视频是裸 `<img src>` / `<video src>`，只能靠它。

**已知局限（接受）**
- 下载窗口的 400ms 宽限：agent 点下载后响应头来得更慢的下载会被当成窗口外取消（控制台留原因），慢站点要重试。
- agent 无法「声明我起了 :3000」，输出里没打印端口的服务只能走审批卡片；页面内未提交的状态（表单、滚动位置）休眠时丢；用户页的剪切与右键菜单不开放；每上下文代理只在 Linux 验证过。
