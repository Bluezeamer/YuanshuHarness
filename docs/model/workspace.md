# 工作区模型

Author: bluezeamer
Status: 现行
Date: 2026-11-05
Verified: 2026-11-19（对着代码核对：`store/{baseline,directories,workspace-directories,sessions}.ts`、`session/{address,attachments,directory-resolver,library,transfer-tool}.ts`、`permission/extension.ts`、`api/{workspaces,session-library,library-stream}.ts`、`features/workspace/{sidebar,dialogs,library,store}/`）

本文是现行设计，也是该领域的事实来源；实现与本文不一致时，先改本文或改代码，不要让两者长期分叉。

术语：**目录**是主机 + 固定路径（`directories` 表、`/api/v1/directories`、工具 `switch_directory` / `list_directories`、`directoryId`）；**工作区**是顶层概念（下面的实体）。前端 `features/workspace/` 是工作区外壳：`library/` 放工作区与会话数据，`sidebar/` 是左轨，`store/layoutStore.ts` 按工作区存布局。

## 1. 实体

```
目录 dir（主机 + 路径，全局唯一）
  ├─ 记住的权限规则
  └─ hooks
  （目录里的 AGENTS.md 是项目自己的文件，框架只读，不记录；见 prompt.md S2）

工作区 workspace
  ├─ 名称 · 描述 · 分组 · 归档
  ├─ 目录清单：1 个主目录（逻辑 local）+ 0..11 个附加目录
  ├─ 新会话默认配置（稀疏覆盖全局默认）
  ├─ 启用的隐私变量（默认全不开；会话只看得到所属工作区启用的，见 variables.md §3）
  ├─ 勾选的技能与 MCP（全局的每个会话都带，不用勾；其余只在勾了的工作区里生效，见 skills.md §1、mcp.md §9）
  ├─ 布局：窗口 → 窗格树 → 标签
  ├─ 终端（按主机）
  └─ 隐藏附件区（虚拟主机 attachment，对 agent 只读；不在目录清单里，删工作区时一并清掉）

会话 session（属于某个工作区）
  ├─ Agent 定义 · 模式 · 模型 · 能力选用 · 权限矩阵
  ├─ 对话树（pi JSONL）
  └─ 当前所在目录（初始 = 主目录）
```

- **目录**独立登记，工作区只引用它。同一目录可被多个工作区引用，但**至多是一个工作区的主目录**；再选同一目录作为主目录，等于打开原工作区。
- **目录随引用存亡**：没有任何工作区引用某目录时，连同它上面的规则、hooks 一并删除。确认框写明连带删除的条数。不另设「目录」管理页。
- **工作区**只描述「在哪看」：名称、描述（只给人看，不进提示词）、目录挂载、分组、归档、布局、终端。不带任何 agent 语义。
- **会话**描述「谁来干、怎么干」。切会话不改变工作区的布局、终端与目录。

## 2. 不变式

| # | 不变式 |
|---|---|
| W1 | 环境归工作区、对话归会话：目录与终端属于工作区，对话树与模型配置属于会话。 |
| W2 | 工作区配置里不出现 agent 语义；同一目录下要同时开 coder 与 reviewer，靠同一工作区里的两个会话。 |
| W3 | 默认配置只在新会话创建时套用并拷贝进会话；之后工作区默认变化不影响已有会话（提示词前缀稳定）。 |
| W4 | 一个窗格只属一台主机。 |
| W5 | 删除父会话不删除派生会话；派生关系自己落库，不依赖 pi 的文件头字段。 |

## 3. 分层与默认值

| 层 | 管什么 | 挂在它上面的 |
|---|---|---|
| 目录 | 这里有什么、这里允许什么 | 记住的规则、hooks |
| 工作区 | 在哪看 | 名称、描述、目录清单、分组、归档、布局、终端、新会话默认配置、勾选的技能与 MCP、审核要求 |
| 会话 | 谁来干、怎么干 | Agent 定义、模式、模型、能力选用、权限矩阵、对话树、当前所在目录 |

- **默认配置两层**：全局默认（设置页「默认值设置」）→ 工作区稀疏覆盖（每字段「跟随全局 / 覆盖」）。只在创建新对话时套用。
- 凡是「跟随上一层、可覆盖」的项，界面显示值从哪来，并提供「恢复跟随」（交互标准 X02）。
- 目录上不带默认权限档：权限覆盖是工作区「新会话默认配置」里的一个字段（`prompt.md` F4：稀疏、建会话时拷贝进会话，不是活的一层）。
- **多目录下的工具语义**（「位置模型 v2」）：
  - **三个词，不引入第四个**：**主机**（一台机器：`local` = 工作区主目录所在的主机，固定；连接名；`server` = Server 物理机的别名；虚拟的 `collab` 与 `attachment`）、**目录**（主机上登记的一个项目文件夹，写作 `<host>:<name>`，**只能从会话里已登记的目录里选**）、**当前目录**（`switch_directory` 改它；会话从主目录出发）。模型可见文字里不出现 workspace 这个词，也不出现目录 id。
  - **位置不放进路径字符串，是独立的 `host` 参数，`path` 永远只是路径**（不用 `<host>:<绝对路径>` 这种字符串地址：靠嗅探区分有洞，`dev1:src/a.ts` 会被当相对文件名，`write` 能悄悄建出叫 `dev1:src` 的目录；bash 也不认）。适用六个文件工具（read / write / edit / ls / find / grep）、`transfer_files`（两端各自 `from` + `from_host`、`to` + `to_host`）、`browser_upload`、bash。`host` 三形态：
    | `host` | 缺省 `path` | 相对路径 | 绝对路径与 `~` |
    |---|---|---|---|
    | 不写 | 当前目录本身 | 从当前目录起 | 在**当前目录所在的主机**上 |
    | `dev1`（裸主机） | 拒绝 | 拒绝（报错同时给出 `/…` 与 `dev1:<目录>` 两种写法） | 在 dev1 上，`~` 在 dev1 上展开 |
    | `dev1:train` | 该目录本身 | 从该目录起 | 在 dev1 上（目录只决定相对路径的起点与归属） |

    `host` 按第一个冒号切（目录名里可以再有冒号），冒号后面只许已登记的目录名、不许写路径。**bash 只收 `host:目录` 一种，不接受裸主机**：命令的工作目录必须是一个确定的、登记过的目录，起点才不会漂移、不会在不知情的地方留下垃圾文件；不写就是当前目录。`path` 以「已知主机名 + 冒号」开头一律拒绝并提示放进 `host`（只拒不解析）。命令打印出来的路径属于它运行的那台主机，在别处用要带上那台主机（全局卡里强调）。
  - **解析只在 `session/address.ts`**（`createAddressBook`：`locate(host, path)`、`directory(ref)`、`refOf(d)`）；池里 `addressBookOf(sessionId)` 是**唯一的实例化处**（扩展、权限、传输、上传、子代理派发、画布都经它），`switch_directory`、`spawn_subagent` 的 `directory`、`canvas_edit` 的 `directory`、bash 的 `host` 都走 `directory(ref)`。权限层与工具层拿到同一个 `Located`（主机名、展示形式、环境、绝对路径、**归属目录**）。
  - **主机名**：工作区主目录所在的主机一律叫 `local`（给模型的心智暗示：这是项目主目录，主目录在 ssh 上时也叫 `local`；**按工作区定，不按会话**：子代理里它指的仍是工作区主目录所在的主机，派发时记进 `spec.primaryDirectoryId`）；Server 所在物理机不是主目录时叫 `server`（是主目录时也接受，作 `local` 的别名）；其余是连接名（大小写不敏感；含空白、冒号、斜杠的退回环境 id）。界面与模型可见文字里不出现「本机」「附件」这类中文主机名。
  - **两个虚拟主机**，不暴露真实路径、只按 `/` 开头的路径寻址（`~` 等价于 `/`，`..` 越界在解析处报错）、不是目录（`directory("attachment:x")` 被拒；`collab` 不登记进 `directories` 表，附件区首次上传时才建一行隐藏的记录，不在目录清单里）：**`attachment`**（附件区，**工作区级**、对 agent 只读：根会话、子代理、工作流 agent、团队成员读到的是同一块；`[attach_file]` 标记行仍是 `attachment:/…` 输出引用，保持原样，使用时拆成 `host="attachment"` + `path`；`write` / `edit` / `transfer_files` 的目标端任何档位都拒，要改先复制进某个目录）与 **`collab`**（协作区，**树级**：同一棵会话树里的会话都能读，子代理只写自己的子目录，根会话不写，见 [`subagent.md`](subagent.md)；主目录在 ssh 上时也可读）。
  - **目录名按 (环境, 名字) 唯一**（`directories_name` 部分唯一索引，附件区行除外）：`host:name` 是 agent 的标识符。默认名（路径末段）自动去重（`app`、`app-2`，在登记那一刻去重，同一批里两个同名文件夹也各得其所）；用户手填或重命名成同主机上的重名返回 409 `name_exists`。
  - **权限按目标的归属目录判**（`permission/extension.ts` 的 `judgeTarget`，文件工具与 `transfer_files` 两端共用）：归属目录 = 该主机上包含这条路径的最深一个已登记目录，没有就取点名的目录 / 当前目录（同主机）/ 该主机的第一个；内 / 外以它的 cwd 为准、规则与「通过并记住」落在它身上。**bash 按 `host` 点名的目录判**（不写就是当前目录）：`PermissionDeps` 里命令类工具经 `directoryCtx(host)` 取判定上下文（cwd、规则、档位、记住落点），sudo 探测、端口发现、审计的 `environmentId`、隐私变量引用记录都跟目标环境，不再跟会话当前目录。虚拟主机的护栏在 `full` 放行之前判、不看档位：附件区只读，协作区按会话所在那棵树判读写。读目录会带走整棵树的场景（不带选择器的 grep / find、传输源端）才扫树找敏感名条目。写任一已登记目录的 `<目录>/.canvas/` 被拦（`canvas_edit` 专管，读不拦）。
  - **`transfer_files`**（`session/transfer-tool.ts`）：源端按「读」、目标端按「写」，**各按各自的归属目录判定**，任一端被拒就拒；需审批时合并成一个弹窗；自动审核档需审批时一律交人工；无人值守的子会话一律拒绝。
  - **子代理只在一个目录里工作、不能切换**：`spawn_subagent` 的 `directory`（`<host>:<name>`，缺省调用方当前目录）；子会话不注册 `switch_directory`、保留 `list_directories`（`host` 参数描述指向它）；它的 `<cwd>` 段写它自己的目录。要同时在本地和远程调试就派两个子代理。
  - **`<cwd>` 段**由我们接管（pi 无条件产出裸路径）：写主目录的引用（`The session starts in its main directory local:proj (…)`），不随切换变（切换由尾部通知负责，变了会让状态通知重复）。技能的 `<location>` 仍是 pi 的裸绝对路径：不写 `host` 的绝对路径按当前目录所在主机解析，而技能本来就按当前目录的环境同步，所以可直接 `read`。
  - MCP 只按主目录（local）装载，stdio 进程起在该目录所在的主机，`switch_directory` 不迁移，见 [`plugin.md`](plugin.md) §6；全局卡里写明「MCP 跑在 local」。

## 4. 会话操作

| 动作 | 历史 | 配置 | 产出 |
|---|---|---|---|
| 新对话 | 空 | 工作区默认（未覆盖字段跟随全局） | 并列的新会话 |
| 刷新上下文 | **原地：历史、配置、模式都不动** | 两份 AGENTS.md 重新读、技能重新同步、MCP 重连、主机登录环境重抓 | 同一个会话，重建前缀（缓存失效），一键、不弹选择、不跳转；运行中不动；输入框的 `/reload` 是同一件事。想要「同配置的空会话」用菜单里的「以此配置新建…」 |
| fork | 到分叉点为止 | 沿用当前会话 | 新会话，记录派生关系 |
| 回退 | 同一会话内换分支（pi 会话树） | 不变 | 不产生新会话 |

- **命名**：显示名 = 手动名 ?? 首条用户消息前 48 字（去掉附件行与多余空白）?? 「新对话」。fork 的初始名是「父名 · 分支N」，N = 该父会话已有派生数 + 1，由结构算出，不用标题正则。不调模型起标题。`sessions` 表有 `preview` 列缓存首条消息的标题种子；刷新上下文是 `POST /api/v1/sessions/:id/refresh-context`。
- **子代理会话**（[`subagent.md`](subagent.md)）不是列表里的会话：不进左轨、不计入会话数。
- **派生**：左轨只显示会话之间的派生（孩子缩进挂在父会话下，副标题「↳ 从某一轮分出」）；会话内回退分支不进左轨，留在历史浮层（双 Esc）。落库字段：`parent_session_id`、`fork_entry_id`。
- **删除**：会话运行中拒绝删除；删除确认框写明「它有 N 个派生会话，不会被删除」。删除父会话后，子会话升为顶层行并标注「派生自已删除的会话」。
- **归档**：会话归档后收进工作区底部的「已归档 (N)」，对话输入栏只读；运行中不能归档。工作区归档是纯显示属性，不动其下会话、布局与终端；有会话运行中不能归档。
- **删除工作区**：连带关闭它的终端（终止其中的进程），确认框写明终端数量，与目录连带删除用同一个确认框。
- **分组**：只在工作区层（名称、颜色、折叠、删组只解散）。工作区内的会话平铺，只有 fork 的缩进。
- **置顶**：会话与工作区都能置顶（右键 / 行内「…」里的「置顶 / 取消置顶」，库里是 `pinned`）。置顶的排在同级之前：会话在所在工作区里，工作区在所在分组里（分组之间的顺序不变）；其余保持原顺序，已归档的不能置顶；行上有一枚小图钉。与「固定标签」（双击会话行，`pinSession`）不是一回事。
- **行内归档**：会话行悬停时，「刷新上下文」旁多一个「归档」图标按钮，点一下直接归档这一个会话（运行中仍被拒，给提示）；已归档的行没有这两个按钮。
- **工作区拖拽落点**：拖着工作区时，放在分组头上 = 放进该组并**排到最后**；每个展开的分组（含未分组）末尾有一块落点，放在最后一个工作区之后同样是排到最后；放在另一个工作区头上 = 插到它前面。
- **批量**：两层都支持 ctrl / ⌘ / shift 多选；**没有底栏操作条**（底栏离列表远，正常使用不会去看）。批量操作都在**选中行上右键**（或行内「…」）：菜单就是对整个选择的批量版，数量写在字上——会话「归档 N 个会话 / 恢复 N 个会话 / 删除 N 个会话…」（刷新、改名、设置这些只对一个会话有意义的项不出现），工作区「移入分组… / 新建分组并移入… / 移出分组 / 归档 N 个工作区 / 恢复 N 个工作区 / 删除 N 个工作区…」；选中里有已归档的才出现「恢复」。**在没选中的行上右键**先清掉原来的选择、菜单只管这一行。删除会话是一个确认框，删除多个工作区仍是逐个确认（每个有自己的影响范围，`askRemoveWorkspaces`）。**普通点击打开的那个也算选中**（否则 ctrl / ⌘ 点别的行时，当前打开的那个不在选择里，不符合直觉）：没有选择时第一次 ctrl / ⌘ 点别的，选择是「当前打开的 + 新点的」（`toggleIn` 的 seed；工作区同理，当前工作区算进去）；ctrl 点当前这个自己只选它；shift 点没有起点时从当前打开的算起。代码 `sidebar/menus.ts` 的 `batchIds`，验收 `menus.test.ts`、`useSidebarController.test.tsx`。

## 5. 状态与未读

- **状态（互斥）**：待处理（有审批或提问）> 执行中 > 待命 / 已归档。**执行中 = 模型这一轮在跑，或名下有后台子代理在跑**；后台命令（如 dev server）不算，否则不会自己结束的命令会让状态点永远脉动。
- **标记（叠加，看过即清）**：新结果（一轮正常结束而你不在看）、出错（一轮失败结束而你不在看）。
- 「在看」= 有对话标签在前后台窗口里显示该会话；标签所在窗口不在前台、或标签在别的窗口里，都不算。
- 工作区行取名下最紧急的状态聚合成一枚状态点，折叠时也亮；各状态的计数（执行中、等你处理、已归档）在悬停卡片里。
- 标记存服务端，多端一致（手机看过，电脑不再亮）。客户端在对话标签订阅时上报「我在看」。
- 列表级推送通道（`/api/v1/library/stream`）实时下发状态、标记、改名与增删，左轨不轮询。

## 6. 布局

- **一屏显示一个工作区**。同时看两个项目交给浏览器多页签或独立窗口，本产品不内建。
- 工作区内：若干窗口 → 每个窗口一棵窗格树 → 标签。
- `chat` / `sub` 标签显式绑定会话；`term` / `files` / `preview` / `web` 绑定工作区（`web` 是工作区级的虚拟浏览器窗口，只记当前页面 id），不随会话切换变化。
- 标签移动的边界从「同一会话容器内」改为「同一工作区内」。
- 布局每个工作区各存一份（服务端）；「当前看哪个工作区」存浏览器本地，多窗口互不覆盖。
- 打开工作区时恢复上次的布局，即恢复其中的对话标签；没有对话标签或会话已被删/归档时，回落到最新的 active 会话；一个都没有就显示空状态与「+ 新对话」。

## 7. 左轨与交互

```
搜索 · 新建工作区
[-] Yuanshu                     3 个会话 · 1 个待处理
    /home/user/yuanshu
    ● 修登录 bug                        2 分钟前
      └ 追 500 错误                     5 分钟前      ← fork 缩进
    ○ 重构布局                          昨天
    + 新对话
[+] test project                1 个会话
```

- 工作区卡片：点主体切换并展开，点箭头只展开/收起；允许多个同时展开；当前工作区始终展开。
- 会话行：单击替换当前对话标签，双击在新标签里固定打开，拖拽进窗格即并排，右键菜单见下面「其余入口」。
- 对话标签内另有会话下拉，与左轨等价。
- 左轨收到 62px 时只剩工作区首字母与状态点，悬停浮出该工作区的会话列表。窗口 ≤1120px 时默认收起，≤900px 时横过来做顶部条（用户点过之后以用户的为准）。
- **拖拽与分组的取舍**：拖拽只有两种——会话行拖进窗格（落点处放它的固定对话标签，只接受当前工作区的会话），工作区头拖到分组头（入组）、「未分组」标签（出组）或另一个工作区头（插到它前面，跨组时顺带改分组）；分组靠第一个成员「长出来」，没有成员的分组不显示；删除工作区前先取影响预览，有会话在跑时点确认才报错。
- **其余入口**：分组头的「…」菜单有「编辑分组…」（名称 + 七色之一）与「解散分组…」（里面的工作区回到未分组，确认框写明个数）；工作区菜单有「新对话（带配置）…」「编辑工作区…」；「+ 新对话」行悬停出一个滑块键 = 带配置新建；会话菜单有「以此配置新建…」「会话设置…」；命令面板有「新建会话（带配置）…」「新建工作区…」，⌘N 仍是按当前工作区默认配置直建。会话菜单里没有「历史树」「在节点 fork」（要对话标签上下文，从标签里进）。

交互标准里的 X01、X02 是**产品行为**，定义在这里；X03 起是写界面的方式，在 skill `ys-ui-design` 的 interaction 里。

- **X01** 单击 = 临时查看，双击 = 固定新开，拖拽 = 明确的空间操作。
- **X02** 跟随/覆盖类的设置显示值来源，并提供「恢复跟随」。

## 8. 创建 / 编辑工作区

同一个弹窗（`features/workspace/dialogs/WorkspaceDialog.tsx`）：
- 直接露出：**主目录**（主机 + 绝对路径，点输入框或箭头开目录浏览器）、名称（新建时留空取目录名）、描述（只给人看，不进提示词）。下面是折叠成摘要行的三项，点进去换成二级页：**附加目录**（可在别的主机上，上限 12 含主目录）、**新会话默认配置**（Agent、模型、权限、可切换模式，每项跟随全局或覆盖，覆盖了才有「恢复跟随」，「全部跟随」一键清回；写进服务端的是稀疏对象，只含覆盖的项）、**审核要求**（只在编辑时有：「模型」档下审批模型的判别准则，对这个工作区「追加」到全局后面或「覆盖」全局，文字留空 = 跟随全局，有内容时有「跟随全局」一键清空；PATCH 里的 `reviewPolicy: {mode, text}`，见 [`prompt.md`](prompt.md) P5′）、**隐私变量**（这个工作区启用哪些变量，按变量组三态勾选，见 [`variables.md`](variables.md) §3、§8）（这一项有覆盖时也有「全部关闭」）、**技能与 MCP**（勾选给这个工作区的项：全局的显示成已勾选、不可改，其余可勾；摘要行备注「另有 N 项全局」；有勾选时有「全部取消」；保存时勾选变了才 `PUT /workspaces/:id/capabilities`，新建时先创建再写）。**新建时还多一行「项目 AGENTS.md」**：从「提示词与能力 · 项目 AGENTS.md」里存的模板中选一个（默认不使用），创建成功后写进主目录的 `AGENTS.md`；主目录里已经有这个文件时，创建完再问「追加到末尾 / 覆盖 / 不写入」，由用户选择（`POST /workspaces/:id/agents-md`，见 [`prompt.md`](prompt.md) S2′）。编辑工作区没有这一行：写进去以后文件归项目自己。
- 主目录已是某工作区的主目录：提示并把「创建」换成「打开」，直接切过去，不新建。非 git 目录给一条不拦人的提示。建好后自动创建并打开一个新对话。
- 编辑：主目录不可改；改附加目录时先让服务端预览会连带删掉什么（规则 / hooks），列给用户看，确认后才提交；名称、描述、默认配置、审核要求只提交有变化的；启用的隐私变量清单变了才 `PUT`，新建时先创建再写。
- **项目 AGENTS.md 只有创建时的起点**：模板写进主目录后，这个文件是项目自己的，框架之后只读它、不再回写（`prompt.md` S2′）。

会话的两个入口与设置（`SessionDialog.tsx`）：「+ 新对话」与 ⌘N **直建**（按工作区默认配置，不弹窗）；「带配置新建」打开弹窗，名称、Agent 直接露出，模型 / 权限 / 能力 / 模式折成摘要行点进去改，打开时已按工作区默认预填。同一个弹窗兼作「会话设置」（Agent 不可换，只提交有变化的分区，带着载入时的版本号，409 时让用户选覆盖或采用服务端版本）和「以此配置新建」（只借配置，不复制对话）。

## 10. 取舍与理由

- **为什么一屏只显示一个工作区**：会话不再是布局容器，工作区之间并排没有着落；保留它会把「并排」这件事做成两套机制（工作区并排、窗格并排会话）。去掉后左轨拖拽只剩一种含义。
- **为什么不把 Agent 定义挂工作区**：一个目录只能是一个工作区的主目录，挂工作区就无法在同一项目里同时开不同角色的会话；会话级配置（含模式、能力）挂在会话上，刷新上下文原地做、不动它们，才不必把配置挂到别处。
- **为什么 fork 关系自己落库**：pi 只在文件头写父文件绝对路径，不记分叉点，父文件被删或目录搬家就断；`createBranchedSession` 只带走根到分叉点的直线路径，新文件是独立的树。
- **为什么目录不给权限上限**：目录只保存记住的规则，不设档位或上限，权限保持「全局默认 → 会话」两层（`prompt.md` §3，工作区与 Agent 都不带权限）；会话选「通过」档就是自己承担风险，以后真有需要保护的目录再加。
- **为什么会话文件按工作区分目录**：`<数据目录>/sessions/<工作区 id>/`。工作区以主目录（逻辑 local）为单位，会话都是围绕它展开的；会话不在工作区之间移动，fork 与子代理会话与父会话同属一个工作区，`findSessionFile` 按 id 在各工作区目录里找。
