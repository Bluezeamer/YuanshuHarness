# 动态工作流

Author: bluezeamer
Status: 现行
Date: 2026-11-03
Verified: 2026-11-19（对着代码核对：`workflow/{runtime,sandbox,tools,named}.ts` 的限额、钩子选项、命名流程格式与工具描述，`permission/extension.ts` 的 `workflowGate`，`api/flows.ts`，`config.ts` 的 `YS_HOME`，`subagent/limits.ts`）

用脚本把「先做什么再做什么」写死，agent 只是脚本里被调用的函数：**流程确定、不漂移、可复用**，同时能一次调度几十到几百个 agent 而不把中间结果塞进任何一个会话的上下文。子代理与后台任务见 [`subagent.md`](subagent.md)，团队见 [`team.md`](team.md)（另一件事：成员之间通信），本文是第三种编排方式。

## 1. 什么时候用，什么时候不用

| 适合 | 不适合 |
|---|---|
| 步骤固定、可重复：数据清洗、批量迁移、多来源核验、固定格式的评审流水线 | 需要边做边判断：技术选型、方案调研、架构讨论（用主 agent 或团队） |
| 规模大：几十到几百个 agent，数量要看数据才知道 | 几个并行任务（一条消息里并发几个 `spawn_subagent` 就够） |
| 要复用：同一条流程以后换参数再跑 | 一次性的小事 |

主流实现的共识：脚本适合「宽而不深」的活；编码任务可并行的部分比想象的少。

## 2. 原则

- **W1 一套引擎，两种来源**：脚本可以由模型当场写（针对一次大活），也可以由用户预先写好存成命名流程（主要用途，可复用、可带参数）。引擎、沙箱、钩子相同。
- **W2 脚本是 JS，跑在 quickjs-wasi 沙箱里**（`quickjs-wasi` 是 server 包的直接依赖，只有工作流脚本用它；卡片条件不用沙箱，见 `prompt.md` S3）：没有文件、网络、定时器、`process`、`require`、动态 `import()`；有内存与时间上限；**用 `Date.now`、`Math.random`、无参 `new Date()` 直接报错**，这是将来按重放恢复的前提。脚本本身没有任何权限，**权限全在它调用的 agent 上**。
  - **沙箱探针结论**（离线）：宿主异步函数可以被脚本 `await`；`parallel` 5 个，宿主同时看到 5 个在飞；失败项为 `null`、其余照常；循环、分支正常；上述禁用项都被拦住；死循环被中断；吃内存报内存超限，不影响宿主。
  - **超时按每一段同步执行计，不按脚本总时间**：脚本在 `await` 子代理时是空闲的，几分钟的等待不该触发超时（限额见 §9）。
  - 沙箱的隔离强度：WASM 有独立的线性内存，比 `node:vm` 强（DeepSeek 自己写明 `vm` 不是安全边界，真正的防线在进程级）。
- **W5 脚本是纯编排，不执行任何有副作用的动作**：它决定谁、什么时候、做什么，以及怎么汇总（切批、过滤、统计、对失败的重试）；读文件、跑命令、联网一律经 `agent()`，权限跟着子代理走。这与 Claude Code、DeepSeek 一致。**确定性的活（如数据清洗）不放进工作流**：让 agent 写一个脚本文件、用 `bash` 跑，脚本文件本身就是可复用的流水线；工作流只用于需要大量 agent 做判断的活。曾考虑加一个 `tool()` 钩子直接执行工具、不经 LLM，不加；混合场景（先格式化再复审）可由 agent 事先跑好，或写进同一个 agent 的任务，真遇到再议，它走现有权限管线，成本低。
- **W3 agent 是被调用的函数**：脚本里的每次 `agent()` 就是派发一个子代理，沿用 [`subagent.md`](subagent.md) 的会话、权限、没有审批通道、协作区、链式停止。
- **W4 不为将来的可视化编辑器削减设计**：workflow 在很多场景是节点编排的更快更简便的替代，不因要不要画成图而限制写法。要画图靠运行时轨迹与脚本里声明的阶段，见 §6。

## 3. 钩子与脚本

最小集，取自 Claude Code 与 DeepSeek 两家一致的设计：

```js
agent(prompt, { label?, phase?, schema?, agent?, model?, remind_after? })   // → 子代理的最终文本；有 schema 则为校验后的对象；失败为 null
parallel([() => ..., () => ...])      // 并发，全部完成才返回（有序数组）；其中一项失败为 null
pipeline(items, stage1, stage2, ...)  // 每个 item 独立穿过各阶段，没有阶段间的等待（多阶段首选）
phase(title)                          // 进度分组
log(message)                          // 一行说明
args                                  // 调用参数，纯 JSON，原样透传
```

- `agent` 的返回值是**交付的 `summary`**（`subagent.md` §5）；需要长产物时脚本拿到路径，由后续步骤或最终返回值带出去。
- 脚本最后 `return` 一个 JSON 值，作为这次运行的结果；必须是纯 JSON（拒绝函数、环、`undefined` 嵌套）。结果过大时落协作区文件，只回传路径与摘要。
- 脚本没有文件、shell 权限，要读文件或跑命令就派一个 agent 去做。
- **元数据**（名称、描述、阶段名）是**与脚本分开的纯 JSON**，不是脚本里的 `export`：宿主取元数据时不能求值模型写的文本。

## 4. 错误纪律

直接采用 DeepSeek 的分法，是调研里最干净的一段：

- **用错钩子（参数错、未知选项、不支持的 schema、超上限）→ 整个脚本失败**，而不是让这一项变成 `null`：写错的配置不能被当成一次普通的子代理失败。
- **子代理失败（异常退出、被停止、未交付）→ 该项为 `null`**，脚本自己决定怎么处理（`.filter(Boolean)`）。
- **运行时本身的故障（沙箱崩溃、引擎错误）不算子代理失败**，整个运行失败并记录原因。
- 超过 `maxItemsPerCall`（建议 4096）直接报错，不静默截断。
- 失败信息英文、写明哪一步、什么原因，同「调用失败要正确提示」的原则。

## 5. 运行：它是一种后台任务

- **启动**：`workflow_run({ name | script, args })`，阻塞调用，结果就是脚本的返回值；`job_start(workflow_run ...)` 就是后台运行。**它就是一个任务**，用现有的 `job_*`：任务清单里一行，`job_stop` 链式停掉整次运行（名下所有子代理一并停），到提醒时间、完成、异常退出的回调都复用 [`subagent.md`](subagent.md) §3。
- **限额**（决定：工作流的 agent 走自己的资源路径，不进总约束）：脚本本身和它的 agent **都不占「最大存活 50」名额**；引擎自己排队，同时在跑的子代理数限制在一个并发数上（默认 10，脚本可调，最多 50），其余等位。agent 名下再派的子代理是普通子代理，照常计入存活上限。底下仍受供应商「最大并发请求数」约束（排队）。
- **总数与确认**：单次运行启动的子代理总数设上限（1000，防跑飞的循环），超了整次运行失败；这是工作流自己的上限，不是全局累计上限（没有全局累计上限）。**每次运行开始前都要用户批准**（不按数量阈值：一次运行会启动多少个 agent 常由脚本里的循环、或上一阶段 agent 的返回结果决定，事前数不出来，所以只能让人看脚本；设置 · 工具与能力页可把 `workflow_run` 改成放行，见 `prompt.md` 工具规则）；通过档不弹，自动审核档不送审，无人值守的会话拒绝。
- **运行中不接收人工输入**：要在阶段之间让人确认，把每个阶段拆成独立的运行（Claude Code 同样放弃了这条）。
- **缓存**：同一批并发的子代理前缀相同，第一个把前缀写进缓存之后其余再启动；引擎对同一批的后续 agent 错开启动（建议最多 5 秒，同 Claude Code）。（未实现，见 §8。）
- **审计**：每个子代理的请求照常按「一次模型请求」记录，运行是一个新的审计层级，成员是子代理会话；运行记录写进根会话（开始、每个 agent 的开始与结束、结束），第一次写入失败就整体停写，日志只会是空或合法的连续前缀。（运行记录写进根会话未实现，见 §8。）
- **服务重启**：运行中的工作流视为中断（同后台任务）。按重放恢复留作以后：脚本已禁用不确定的函数，第一个 prompt 与上次不同的 agent 及其之后全部重跑。

## 6. 命名流程与可视化

- **保存**：用户手写，或模型用 `write` 工具把脚本写成文件；**不设专门的保存工具**（保存走现有权限：项目 `.ys/` 在目录内，全局 `~/.ys` 在目录外要审批；每次运行前仍要批，见 §5）。
- **文件形态**：一个文件一个流程，`<名称>.js`，**名称就是文件名**（小写字母、数字、`-`、`_`，最长 64），复制或重命名文件就是改名，不会有名字写在两处不一致。文件开头是一段 `/* @workflow { JSON } */` 注释，块内纯 JSON，**宿主只做定位与 `JSON.parse`，绝不求值**；块后全部是脚本。元数据字段：`description`（必填）、`params`（可选，名称 → `{type, description?, default?, required?}`，`type` 取 string / number / integer / boolean / array / object）、`phases`（可选，阶段名，给界面画大纲）；未知字段报错。**解析失败报错拒载**，不静默消失：清单里仍列出它并写明原因，按名运行时返回同一条原因。依据：业界没有一家为取元数据而执行脚本，文本类流程都是单文件加元数据头；Claude Code 把 `export const meta` 放脚本首句要求字面量（写成变量就悄悄从补全里消失），DeepSeek 明确拒绝这种做法，因为取元数据就得在宿主上执行模型写的文本。
- **两层**：全局 `~/.ys/workflows/`（Server 所在机器，`YS_HOME` 可改根目录）、项目 `<会话当前目录>/.ys/workflows/`（经环境读取，本机与 SSH 都行；`switch_directory` 后跟着变）；**同名时项目覆盖全局**，清单只列生效的。不缓存，每次现读。
- **调用**：`workflow_run({ name, args })`（与 `script` 二选一）与 `workflow_list`（清单）；`/名字 参数` 斜杠命令留给界面（§8）。声明了 `params` 的流程，`args` 要是对象，按声明补默认值并检查类型，声明之外的键、缺少的必填项、类型不符一次列全报错；没声明 `params` 的流程 `args` 原样透传。
- **运行视图**：钩子本身产生事件（阶段、每个 agent 的开始与结束与结果），所以可以画成「运行 → 阶段 → agent」的树，点开一个 agent 就是它的子代理会话。右栏现有「工作流」块，按运行与阶段汇总个数（§9）；完整的树与事先的大纲、节点编辑器见 §8。

## 7. 与现有机制的关系

| | 用什么 |
|---|---|
| 并行几个 agent，结果都要读 | 一条消息里并发几个 `spawn_subagent` |
| 一批很多个、结果只要汇总 | 工作流 |
| 步骤固定、要复用 | 命名工作流 |
| 成员之间要讨论、边做边协调 | 团队 |
| 需要判断与决策 | 主 agent |

## 8. 未实现与未决

- **斜杠命令与 REST**：`/名字 参数` 斜杠命令与命名流程的 REST 接口没有做（随输入栏界面）。
- **运行视图**：完整的「运行 → 阶段 → agent」树没有做（右栏现有「工作流」块只按运行与阶段汇总个数，§9）；命名流程声明了、还没执行到的阶段不显示「未开始」（声明的阶段名没有带进运行）；运行视图里不显示「来自哪个命名流程」（批准后运行侧只认标签）。事先的大纲（元数据里声明阶段名，运行前画成一条阶段线）随之未做。
- **同批 agent 的错峰启动**（缓存优化，§5）与**运行记录写进根会话 / 审计**（§5）没有做。
- **按重放恢复**没有做，只保留了确定性禁令；命名流程的版本同样先不做。
- **`~/.ys/` 与远程主机**（要专门讨论）：全局配置（全局 AGENTS.md 是 `~/.ys/AGENTS.md`，见 `prompt.md` S2；命名流程、以后的全局插件等）放 Server 所在机器的 `~/.ys/`，因为提示词在 Server 端拼装、脚本在 Server 沙箱里跑；项目 `.ys/` 在目录所在主机上，经环境读取。没理清的是用户连着远程 Server、本机也想有一份时是否要镜像（「改全局 AGENTS.md」改哪一份已定：Server 上的 `~/.ys/AGENTS.md`）。
- 模型存下来命名流程之后，「要不要再让用户确认」没有单独处理（保存走 `write` 的权限，运行前有批准，够用，不够再加）。
- 并发数、总数的默认值是建议值。
- 脚本需不需要一个 `confirm(question)` 钩子让用户确认：Claude Code 说运行中不接收输入，先不做。
- **可视化的节点编辑器**：后面的事，不影响现在的设计。需要的话要么加一种受限写法（钩子的固定组合）以便可靠地解析成图，要么让编辑器直接生成脚本；任意 JS 里的循环与分支没法可靠地画成图。
- **沙箱在主线程跑**：一段死循环会卡住整个服务到按段超时（§9），放进 Worker 才是根治，留作以后。
- **已知限制**：脚本里 `agent()` 返回的是交付的 summary（最多 2000 字符），要传大产物让 agent 写文件、脚本拿路径；工具描述里写死 `~/.ys`，设了 `YS_HOME` 时不准。

## 9. 实现要点

服务端在 `workflow/`：`sandbox.ts`（quickjs-wasi 引擎，不认识子代理）、`runtime.ts`（`agent()` 接到子代理、并发队列、总数上限、任务与停止、结果）、`tools.ts`（`workflow_run`、`workflow_list`）、`named.ts`（命名流程）、`view.ts`（任务清单里隐藏 agent）。`quickjs-wasi`（3.6.2）是 server 包的直接依赖。要点：

- **工具**：`workflow_run({ name?, script?, args?, concurrency?, label? })`（`name` 与 `script` 二选一），一个普通内置工具（不是能力单元，只有一个工具；Studio 能力页里按单个工具勾选），agent 继承调用方的模式。工具描述就是脚本 API 手册（钩子、确定性限制、错误规则、示例），「子代理与模式」内置段里只补一句何时该用。
- **钩子**：`agent / parallel / pipeline / phase / log / args` 如 §3。补充约定：`parallel` 里抛错的项与 `pipeline` 里某阶段抛错的条目为 `null`（`pipeline` 的阶段签名是 `(prev, item, index)`，第一阶段的 `prev` 就是条目）；返回 `undefined` 当 `null`；`console.log / info / warn / error` 当 `log`（模型写脚本的习惯）。`agent()` 的选项只有 `label`、`phase`、`schema`、`agent`（Agent 定义）、`model`、`remind_after`，没有 `mode`：模式沿用脚本所在会话的激活模式（继承规则见 `subagent.md` §7）。`agent()` 的返回值是交付的 `summary`，交付带 `report` 时末尾加一行「Full report file: 路径」（带 `schema` 时不加）；子代理失败、被停止、没交付都是 `null`。`schema` 用 zod 的 `fromJSONSchema` 校验（不支持的类型直接是用错钩子），任务末尾自动附一段「summary 必须是符合该 schema 的一个 JSON」；交付的 summary 不是合法 JSON 或不符合 schema 就是 `null`。`remind_after` 接受但不起作用（脚本里的 agent 没有人需要被提醒）。
- **沙箱**：没有 `require / process / fetch / 定时器 / performance`（QuickJS 本来没有，`performance` 内置显式去掉）；动态 `import()` 失败；`Math.random`、`Date.now`、`Date()`、无参 `new Date()` 报错，**这些和其他用错钩子一样让整个运行失败**（脚本把它 catch 掉也一样，沙箱记下第一个致命问题）；有参 `new Date(x)` 照常可用。**没有禁 `eval` / `new Function`**：沙箱里没有任何能力可逃。限额：脚本每一段连续同步计算 2 秒（等 agent 时不计；沙箱跑在主线程上，一段死循环会卡住整个服务到这个时间，所以取小）、内存 64 MB、`parallel` / `pipeline` 一次最多 4096 条、一次运行最多启动 1000 个 agent、脚本源码 10 万字符、`args` 100 万字符。返回值必须是纯 JSON（函数、环、非有限数被拒）；超过 2 万字符的结果落协作区 `<根会话>/<运行任务 id>/result.json`（模型看到的地址是 `host="collab"` 下的虚拟路径），只回传路径与开头。
- **运行是一个任务**：`workflow_run` 阻塞调用，到提醒时间（设置 · 默认值里的后台任务提醒）返回「仍在运行，任务 #n」并转后台，完成时回调（正文以 `[Workflow <id> finished|failed|was stopped]` 开头）；`job_start` 包着它就是立即后台。任务日志（`job_list { id }`）按行记：`== 阶段`、`#n [阶段] started: 标签`、`#n done` / `#n failed: 原因`、`log: …`。`job_stop` 停整次运行：脚本立刻结束，还在跑的子代理一并停；调用被中止（用户停了调用方）时运行继续留在后台，同 `spawn_subagent`。重启时运行中的工作流记为中断（它是任务，`agent()` 派的子代理是子代理，都走现有的重启中断）。
- **agent 的登记**：`agent()` 派出的是真正的子代理（`launch(..., { kind: "workflow" })`：会话、权限、没有审批通道、协作区、链式停止、深度全部沿用），登记成挂在调用方名下的 `workflow_agent` 任务，**inline**（结果交给脚本，不回调调用方），在 `job_list` 里隐藏，对它们 `job_stop` / `job_remind` 被拒并指向 `workflow_run` 那一行。**它们不占存活名额**（`subagents.counted = 0`，启动时跳过存活检查与预留；`runningCount` / `aliveInTree` 不数它们，但数它们名下的普通子代理）：运行的并发数 = min(请求值，缺省 10，`concurrencyMax` 50)，超过 50 静默按 50 取。`SubagentError`（不存在的 Agent / 模型）是用错钩子，整个运行失败。深度已满的会话直接不能跑工作流（运行开始前就报错），单个 agent 的提示词（含 schema）超过 2 万字符也是用错钩子。重启时被打断的 `workflow_agent` 不各发一条通知，整次运行那一行代为说明。
- **运行与阶段的归属**：`subagents` 表有两列 `run_id`（工作流任务 id）与 `phase`（阶段名，没调 `phase()` 为空），`launch` 的 `{ kind: "workflow", label, runId, phase }` 在建会话时写入，所以重启后也认得。阶段按 **`agent()` 被调用那一刻**的 `phase()` 算（排队等名额期间脚本换了阶段，这个 agent 仍属于调用它的那一阶段）。**排队的**还没有子代理行，引擎在内存里记 `运行 → 阶段 → 个数`（`WorkflowRuntime.queued(runId)`），运行结束即清空，重启不保留。`/flows` 有 `workflow: WorkflowRun[]`：按运行聚合这棵树里出现过 agent 的运行，每个阶段 `运行中 / 已完成 / 失败 / 排队` 的个数，加上已启动数与单次上限（取自 `WORKFLOW_LIMITS.totalMax`）；运行的状态、标签与起止取自它的任务行。**计数按子代理会话的状态归并**：异常结束与被停止算失败；「交付了但不符合 schema」「没交付」在会话上是正常结束，**算已完成**，与任务日志里的 `failed: …` 行不完全一致。
- **运行前人工批准**（`permission/extension.ts` 的 `workflowGate`）：弹窗列标签、并发数、args（超 300 字符截断），详情里是完整脚本加 args；脚本加 args 超过展示上限就拒绝，不让批看不全的东西；只有「通过 / 拒绝」，没有「记住」；`job_start` 包着的内层调用同样经过它。被拒时工具结果告诉模型别原样重试。通过档不弹，自动审核档不送审，无人值守的会话拒绝（§5）。
- **命名流程**：`workflow/named.ts`（纯逻辑：`parseNamedWorkflow`、`checkArgs`、`NamedWorkflows.list / resolve / resolveRun`，读两层目录，依赖由构造函数传入）；`workflow_run` 有 `name` 参数，只读工具 `workflow_list`（与 `workflow_run` 同在 `workflow/tools.ts`）列出清单。**`name` 在权限扩展的 `tool_call` 阶段（`workflowGate`）就解析成脚本与填好默认值的 `args`，并原地改写 `event.input`**（pi 允许改写，且不再校验），所以弹窗里看到的、`execute` 拿到的是同一份文本，文件只读一次，`job_start` 包着时也一样（有测试：弹窗等待期间改写文件，运行的仍是批准时的文本）；解析失败在 gate 里直接拦下，通过档也要解析。`ysHome` 是配置项（`YS_HOME`，缺省 `~/.ys`，没有命令行参数）。弹窗多一行「命名流程：名称（global | project）」，标签缺省取名称。`workflow_list` 只读、不弹审批、不能放进后台。
