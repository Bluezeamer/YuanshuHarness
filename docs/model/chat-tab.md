对话标签 = 对话流 + 停靠区（排队条 → 输入卡，输入卡里有工具行）+ 页脚 + 右栏（上下文状态，§3）。没有单独的对话头：会话标题在标签与左轨，「审计 N」入口在窗格头（`tab/AuditToggle.tsx`，对话里是「审计 N」，审计里换成「← 对话」）。审计视图见 [`audit.md`](audit.md)，模型输出的渲染（代码块、mermaid、图片）见 [`chat-render.md`](chat-render.md)。术语「目录」「工作区」见 [`workspace.md`](workspace.md)。

## 1. 结构与数据流

- **标签的构成**（`tab/ChatView.tsx`）：对话视图 = 连接断开条 + 对话流（`Stream`）+ 停靠区（`Dock`）+ 页脚（`StatusFoot`），右栏（`rail`）与主栏并列；审计视图只留审计页（`AuditPane`）与页脚，没有停靠区与右栏。整块对话视图是文件拖入区：系统文件拖入是上传，文件管理器拖来的是 `file:` 引用（§5）。
- **连接**：连接断开时流上方出现提示条：`reconnecting` 每 3 秒重试，连续失败 5 次停在 `closed`，点「重新连接」以新快照恢复（`store/sessionStore.ts`）。
- **一个会话一份状态**：一条 WebSocket、一份消息 / 目标 / 计划 / 弹窗 / 排队状态，开几个对话标签都订阅同一份；草稿也共用（`store/hub.ts`）。
- **归档会话**：输入卡换成「已归档 · 只读」条（`tab/ArchivedBar.tsx`），页脚保留。恢复在左轨右键菜单「恢复」，直接回到 active。
- **不在消息历史里的东西**（压缩回执、弹窗落定）：服务端只给当前快照，前端观察快照的变化，按「当时已有多少条消息」锚定插进流里（`tab/flowLog.ts`）。**刷新后只能从快照重建一份基线**：当前压缩的回执、待答弹窗会重建；已答复的弹窗卡不会回来。目标与后台任务回调的卡片不在此列：它们是服务端记进会话的 notice，历史接口按 `afterIndex` 给，刷新后原样回来（见 [`goal.md`](goal.md) §5、[`subagent.md`](subagent.md) §9）。

## 2. 消息流

- **用户消息**（`tab/Messages.tsx` 的 `UserBubble`）：右对齐的气泡：附件卡片 → 引用 chip → 正文（纯文本样式的 Markdown）。没有头像、名字、时间、「接入端」标记。引用块由正文里的「`Quote <标签>` + 围栏块」还原（`tab/format.ts` 的 `splitQuotes`，与 `model/draft.ts` 的 `withQuotes` 互逆）。
- **agent 消息**（`AgentMessage`）：按块的先后交错渲染思考、工具链、文本。没有 agent 名与头像。思考默认折成一行「思考」，点开看全文（`tab/Think.tsx`）。
- **工具链与工具组**（`tab/ToolGroups.tsx`、`toolGroups.ts`、`toolRows.ts`）：连续的工具块并成一串，串里相邻同类的折成一组，一组一行摘要：「读取了 N 个文件」「搜索了 N 次」「运行了 N 条命令」「编辑了 N 个文件」「派发了 N 个子代理」，其余按工具名写「调用了 X N 次」，后面跟耗时合计。收起时标题后带第一行的命令 / 路径预览（组里不止一行补 `+N`）；有失败行的组默认展开。组里每行：状态点（运行中脉动、失败红）、工具名、一行参数摘要、元信息（write 的行数；edit 的 +增 −删与耗时；read 的行数；其余耗时）；有输出的行点一下看输出，失败的行默认就露出红字输出。write 的内容与 edit 的改动用代码块渲染。嵌套调用（`call_tool` 转发的）挂在父行里面。
- **运行态的一行预览**（`tab/LiveLine.tsx`、`liveLine.ts`）：还在进行的那一步只露一行淡色预览（类型标签 + 最新一行内容，随流式刷新；同时还有别的工具在跑时尾部写 `+N`）。优先级：正在生成参数的工具 > 正在执行的工具 > 思考（正文已经开始流出时，思考不再是当前这一步）。点开看目前的全部内容并跟到底，用户往上翻了就不再抢回去；这一步结束就并回折叠的工具组 / 思考行。
- **复制给 Markdown 原文**（`features/markdown/copySource.ts`）：对话正文与文件预览里选中渲染内容复制，剪贴板里是原文而不是渲染后的纯文字——选区碰到的块（标题、段落、列表项、代码围栏、表格……）整块取原文，两头只选了一部分的那段仍是纯文字，选区整个落在一个块内部（选一句话）不接管。块级元素在渲染时带上它在原文里的起止偏移（rehype 插件 `rehypeSourceRange`，`data-md-s/e`），所以原文必须与交给 react-markdown 的是同一份；画布笔记的 wikilink 会先改写原文，不接管。
- **轮末操作行**（`tab/TurnFooter.tsx`）：每轮最后一条 agent 消息下有「原文 / 渲染」（只影响这条的文字块）、分叉入口（运行中或压缩中禁用；规则见 [`workspace.md`](workspace.md) §4）、消息时间 `YYYY-MM-DD HH:mm`。**消息时间只在这里出现。**
- **流式**：正文在 `Partial` 里增量出现并带光标；思考与参数还在生成的工具在它们是当前这一步时由上面的一行预览负责，否则折成「思考」行与工具组；运行中且还没有任何输出时是 typing 占位。增量按动画帧合并后才进状态（`store/sessionStore.ts`），避免每个 token 重渲染整棵流。
- **插进流里的卡片**
  - 系统回执（状态点 + 文案 + 时间 + 徽标）：压缩完成「上下文已压缩 · 节省 N%」，徽标 `/compact`；目标的每次变化与续跑也用这个样式（徽标 `/goal` 等，续跑是更淡的一行「目标 · 第 n 轮」），数据来自服务端 notice，见 [`goal.md`](goal.md) §5。
  - 压缩边界卡（`tab/Compaction.tsx`）：来自历史接口的压缩锚点，默认折叠，展开看摘要、压缩前 token 与时间；与上面的回执是两套数据。
  - 后台任务 / 子代理的回调卡（`tab/JobNotice.tsx`）：终态回调在流里是一行卡片，按 `afterIndex` 锚在消息之间、不进消息下标，点开去任务标签 / 执行体标签；提醒不出卡片。设计与数据流见 [`subagent.md`](subagent.md) §9。
  - 「本轮改动」卡（`tab/TurnChangesCard.tsx`）：折成一行「本轮改动 N 个文件」加增删行数，点开是文件清单，点文件名开 diff 标签。服务端落库晚于 `run.ended`：前端先在空闲时拉一次，拉空就按 700ms 间隔最多重试 5 次，服务端落库后推的 `turn.changes` 也会触发重取（`Stream.tsx`）。
  - 审批卡、提问卡：见 §6。
- **导航**：贴底自动跟随（输入框被撑高、容器变矮仍跟随；本端发送后无论在哪都回到底部；点开 / 收起工具组、工具行、思考行时位置留给用户，不被顶走，运行态那一行例外），上翻后出现「回到底部」，滚到顶自动加载更早的消息（`tab/scroll.ts`）。
  - **左缘导航**（`tab/NavTicks.tsx`）：每条用户指令一格横线，当前位置的线与字是深色，少于 2 条不出现；鼠标移上去，这一块向右展开成一张可滚动的小卡，悬停某一条再浮出完整内容与时间，点击定位。展开的是一整块区域，鼠标要完全离开才收起（交互标准 X08）。
  - **历史节点浮层**（`tab/HistoryNodes.tsx`）：输入为空、会话空闲时 500ms 内连按两次 Esc 打开。两个视图：「指令」（当前分支的用户输入，点击直接回退）与「树」（完整会话树，分叉点可折叠，选中后「回到这里」）。回退走 `POST /sessions/:id/navigate`，成功后关闭浮层、提示原分支保留，服务端返回的 `editor`（文字与附件）回填输入框草稿。

## 3. 右栏（上下文状态）与目标（`status/StatusPanel.tsx`）

- 对话标签右侧的**只读执行面**，不是配置入口：由 `ChatTab` 作为 `rail` 交给 `ChatView`，与主栏并列，审计视图下不出现。块依次是：**目标**（有未完成的目标）、**计划**（有 todo）、**团队**（有团队成员）、**工作流**（有最近的运行）、**子代理**（有模型自己派发的子代理）、**后台任务**（有在跑的任务）、**已加载能力**（会话生效的技能与 MCP）。有内容才出现，一块都没有整栏不渲染、不占位。
- **两种形态按对话标签的真实宽度定**：宽度 ≥ 1000px（`WIDE_AT`）时常驻，各块依次排开；更窄时收成一列竖排的文字标签（每个带一枚小点，有东西在动才脉动），鼠标移到标签上（或聚焦）向左展开那一块；展开的整块区域（标签列 + 卡片）都算「在里面」，鼠标要完全离开才收起（X08），Esc 也收起；正在编辑目标时卡片不因鼠标移开而收走。
- **各块**
  - 目标：正文（双击进入编辑）、谁设的（你 / 模型）、自何时起、状态与原因、已用轮数；暂停 / 继续、编辑、删除（二次确认）。编辑框是 `RichInput`，能带附件，可改轮数上限。完成的目标不再占右栏（结果看对话流里的卡片），暂停与受阻的一直显示。设定、续跑与终止规则、`/goal` 命令全部见 [`goal.md`](goal.md)。**暂停时若会话正在运行，走与「停止」同一条路径**（`pool.ts` 的 `stop()`，见 §4）：目标先置为暂停，再撤销待答弹窗、清掉排队消息、中断本轮。
  - 计划：模型自己的待办（`todo_write`），已完成打勾、进行中的一项脉动，标题旁写 `完成 / 总数`。
  - 团队：名册（成员一直全显，不走折叠，点一行开成员的会话标签）+ 公告板一行（悬停最近 3 条，点开用预览标签看文件）+ 团队改动一行（点开列出文件，点文件用对比标签看逐行差异）。没有公告、没有改动的行不画。见 [`team.md`](team.md)。
  - 工作流：每次运行一段，每个阶段一行「名字 + 计数」（已完成、运行中、排队、失败），不逐个列 agent；在跑的运行与结束不满 10 分钟的才显示。见 [`workflow.md`](workflow.md)。
  - 子代理：只放模型自己派发的执行体（团队成员与工作流 agent 各有自己的块）；树形，结束满 10 分钟的折起来（没看过的失败不折），可切到「全部」；点一行开执行体标签。折叠与展开状态存在标签的 `afx`（`subAll`、`subOpen`、`subSeen`）。见 [`subagent.md`](subagent.md) §9。
  - 后台任务：只列在跑的（不含子代理与工作流的任务），一结束就消失（结果在对话流的回调卡里）；一行一个：状态点、简述、已用时，悬停出「停止」（二次确认），点开去任务标签。
  - 已加载能力：技能与 MCP 一行一个，悬停看来源（路径或失败原因）。

## 4. 排队与停止

- 会话运行中再发送不会打断：消息以 steer 排在队里，「当前步骤结束后送达」（`pool.ts` 的 `send`，`streamingBehavior: "steer"`）。排队条在输入卡上方（`tab/QueueBar.tsx`）：标题「排队 N 条 · 当前步骤结束后送达」，每条一行预览，悬停出编辑 / 删除。广播里的排队文本被截成 512 字，编辑前先拉一次全文（`get_queue` 回 `{ text, attachments? }[]`：文字已剥掉标记行，附件单列）；编辑是 `RichInput`，文字与附件（可增删）整体替换该条排队消息的内容，图片以这次解析的为准，其余条目各自的图片不动；增删由服务端重排后经 `queue.updated` 广播回来，多端一致。
- 压缩进行中仍可发送：输入卡显示「正在压缩上下文…」，期间发的消息由服务端排在队列里（`pool.ts` 的 `held`，`queue.updated` 照常显示，可编辑、删除），压缩结束（成功或失败）后依次送给 agent：第一条起运行，其余等它开始后作为插话排进去。
- **停止**：输入卡里的方块按钮，只在运行中出现（`Composer.tsx`）。服务端（`pool.ts` 的 `stop()`）依次：目标先暂停（停下来的目标不会被自动拉起）、撤销所有待答弹窗（工具按「已取消，已拒绝」收场）、清掉排队的用户消息、abort。排队的系统通知（子代理结果、后台任务回调）不是用户输入，不在清除之列，清完会放回队列。**停止根 agent 不级联**：不中断运行中的子会话、不停它的后台任务；停止子代理（子代理标签里的停止）只停该子代理，并链式停止它名下的任务（[`subagent.md`](subagent.md) §1 S5、§9）。

## 5. 输入栏（`tab/Composer.tsx`）

**输入与发送**

- 文本框自适应 36–132px，占位字「输入消息，/ 调出命令，Enter 发送」，可访问名「给 {agent} 发消息」；桌面端 Enter 发送、Shift+Enter 换行（输入法组字中不触发），手机上回车是换行、发送靠按钮（`enterSends`）。附件行、引用行有内容才显示。
- **草稿**：同一会话的所有标签共用。文本另存 localStorage（键 `ys.chat.draft:<会话id>`，读写走 `app/localState`，跨浏览器标签同步，删会话时清掉）；**附件与引用只在内存**，刷新即丢（`store/hub.ts`、`store/draftStorage.ts`）。发送失败或断线时，文本、引用、附件放回草稿：草稿为空才放回原文，用户改过就不覆盖（引用与附件仍补回）。
- **命令分流**（`model/commands.ts`）：`/goal`（设定 / `edit` / `pause` / `resume` / `clear`，见 [`goal.md`](goal.md) §5）、`/compact` 走各自的会话命令；`/mcp`、`/reload` 是界面自己的动作，由输入框（`tab/Composer.tsx`）在发送前截下、不发给会话也不进历史（`/mcp` 打开 `tab/McpDialog.tsx`：本会话各 MCP 服务的状态、运行位置、失败原因与「重载」；`/reload` 调 `POST /sessions/:id/reload` 并弹提示；带参数都报错）。`/goal` 空文本提示用法，`/compact` 带参数报错。`/plan`、`/review`、`/<技能名>` 都是普通消息，原文发给模型，前端不展开；是否被 pi 展开成提示模板**未核实**。命令发出后只清文本，附件与引用留给下一条；设定 / 修改目标可带附件，用掉的附件一并清。
- **普通发送**：引用拼在问题前（`withQuotes`，每条是 `Quote <标签>` 加围栏块），附件只带上传后的 `path`。内容为空、附件未就绪时发送按钮禁用，附件上传中或失败会说明原因。模型不支持图片时，服务端拒绝带图的消息。
- **附件**：选文件、粘贴、整块对话标签拖入，都先上传到会话附件区，附件卡带缩略图 / 进度 / 重试 / 移除。**哪里都能带附件**：凡是「用户写点什么交给 agent」的文字框都是同一个 `input/RichInput`（文字 + 附件条 + 上传按钮 + 框内拖入）——提问回答（`ask_user` 的输入框带附件；插件的输入弹窗只收文字，服务端 `PromptData.input` 是 `rich` 还是 `text` 决定）、目标编辑与 `/goal`、排队消息编辑、执行体的补充要求；主输入卡自己持有文字框（斜杠菜单与引用），附件部分用同一套 `AttachmentBar` / `useFilePicker` / `useUploads`。附件存放处是 `AttachmentSink`（会话草稿或组件自己的本地存放），发出去只带 `{ path }`。服务端对应唯一入口 `session/user-content.ts` 的 `resolveUserContent`（校验、mime、读图压缩、追加 `[attach_file]` 标记行），`send_message / answer_prompt / set_goal / edit_goal / edit_queue` 都经它；`input/input.guard.test.ts` 守着对话区里不再直接冒出裸文字框。回退到某条用户消息时，`/navigate` 回 `editor: { text, attachments? }`（文字已剥掉标记行），文字放回草稿、附件作为已就绪的引用加回草稿，不用重传。从文件浏览器拖入的是 `file:<主机>:<路径>` 引用文本，不上传（`tab/useFileRefDrop.ts`）。验收 `scripts/verify-input.mjs`。
- **斜杠菜单**（`tab/useSlashMenu.ts`、`slash.ts`）：空输入框按 `/` 打开，输入过滤，↑↓ 选择，Enter / Tab 采用，Esc 关闭并清掉 `/xxx`。分三组：命令（`goal`、`compact`、`mcp`、`reload`、`plan`、`review`）、会话已加载的技能、会话的 MCP 状态（只读提示行，不进键盘选择）。点命令只是往输入框插入 `/cmd `，**包括 `compact`，要再按 Enter 才执行**。没有斜杠按钮。

**工具行**（`tab/Toolbar.tsx`）：自左向右 `+`、模式、审批 …… 模型与思考档位 · 末尾（运行中的停止、发送）。数据来自会话配置、供应商、全局默认模型、全局默认值、会话上下文，各自容错，取不到只是少一块；配置补丁串行提交并带版本号，被其他端改过时提示并刷新（`tab/useChatConfig.ts`）。

- **`+`**（`InsertMenus.tsx`）：上传文件、引用仓库文件（插入 `@`）、引用隐私变量（插入 `{{@}}`，光标落在花括号内）；触屏设备另有拍照与相册。
- **模式**（`ModePicker.tsx`）：按钮显示当前模式，点开从会话的可切换清单里选一个，或选「无模式」退出；运行中随时可切，静默生效：工具限制立即生效，模型在下一次运行开头收到状态通知（见 [`prompt.md`](prompt.md) §4、[`prompt-delivery.md`](prompt-delivery.md)）。会话没有可切换的模式时不显示。
- **审批**（`PermPicker.tsx`）：按钮「审批 · 档位」显示本会话**生效**的档位（规则 / 模型 / 通过），本会话自己覆盖了全局默认时着色；点开四项：「跟随全局 · X」（X 是全局默认现值，每次打开重读）、规则、模型、通过，立即生效，选「跟随全局」即清掉覆盖（交互标准 X02）。没配审批模型时「模型」档置灰并写明去「设置 · 默认值」配；逐工具细则在「设置 · 工具」里改。服务端档位解析：会话覆盖 > 全局默认（`pool.ts` 的 `sessionTier`，每次工具调用现读），见 [`prompt.md`](prompt.md) §3。
- **模型与思考**（`ModelPicker.tsx`、`models.ts`）：合成一个按钮「模型名 · 档位」。点开：顶部搜索（名称、id、供应商、认证方式），按供应商分组的模型列表（只列已配置凭据且最近一次测试没失败的供应商，每行带上下文窗口），底部一排档位（只列当前模型声明的档位）；↑↓ 循环、Enter 选中、Esc 关闭。选中写成会话的显式模型设置，思考档位保留意图：新模型支持就沿用，不支持落到声明里最近的一档（同距取低）。会话跟随默认模型时显示默认模型名；原先跟随默认时改档会落成显式指定，否则会被默认值盖回。

**页脚**（`tab/StatusFoot.tsx`、`model/metrics.ts`）：输入卡下面一条分割线，居中一行：工作位置（一枚主机色圆点）· 生成速度 · 上下文（读条 + 已用 / 窗口）· 缓存命中。对话视图与审计页共用，只读、不可点、不进审计；悬停各出一张小卡（速度与耗时：首 token、生成速度、模型用时、工具调用用时；上下文：占用、已用与总量、还剩；用量与缓存：命中、缓存读取、累计）。只给 token 与比率，不给成本；算不出的项不画，没有用量数据时整行写「暂无用量数据」。

- **工作位置**是 agent 现在工作的位置：**只画一枚主机色圆点**，地址太长不放文字；取会话的当前目录（壳经 `SessionMeta.place` 给），颜色与窗格头同一套主机色（`layoutContext` 的 `useHostTone`，窗格里没有这台主机时取它将分到的下一个颜色）；主机名与完整路径在悬停小卡里。
- 数据是会话累计用量（每轮结束后重取 `/usage`）与最近一次模型调用的 token 拆分；窗口大小来自模型元数据，**没有 200K 缺省**：未知时上下文只显示占用，不画读条比例。

## 6. 审批与提问

- **弹窗模型**：一个弹窗 = 问题 + 可选的**选项**（快捷回复）+ 可选的**输入框**；`PromptData.input` 缺省 = 没有输入框（只能选选项）、`text` = 文字、`rich` = 文字加附件，没有 `kind` / `needsText` / `rich` 了。答复 `answer_prompt { promptId, optionId?, text?, attachments? }` 是三者的任意组合、至少一样：点选项即答，输入框里写了字再点选项 = 选了这项并补一句话，只提交文字 = 用户自己的话（不必在选项里）。哪些弹窗有输入框：`ask_user`（有没有 `options` 都有，`rich`）、浏览器 handoff 的聊天卡片（`text`）、所有审批（`text`，写的是拒绝理由）；插件的 `select` / `confirm` 没有（pi 的返回值类型固定，自由文字放不进去），`input` / `editor` 是 `text`。服务端校验在 `session/prompts.ts` 的 `PromptTable.answer`；用户的话怎么交给 agent 各处自己定：`ask_user` 的结果区分「选了某项 / 自己写的 / 选项加补充」（英文，写在工具描述里：选项只是建议，不要假设答案在其中），审批拒绝时拒绝原因后追加「用户补充：…」，handoff 的 `done` 可带补充、只写文字等于拒绝并回话。
- **来源**：审批来自权限钩子（`permission/extension.ts`）；提问来自 agent 的 `ask_user` 工具（`session/tools.ts`：1–8 个可选的快捷选项，用户总能用自己的话回答，也能附文件）。两者都进会话的弹窗表（`session/prompts.ts`）。**子代理会话没有审批卡与提问卡**：要审批的直接拒绝，也没有 `ask_user`（见 [`subagent.md`](subagent.md) §7）。
- **广播与先答先赢**：`prompt.requested` 发给所有订阅者，谁先答谁生效；后到的得到 `prompt_resolved` 错误回执，本端撤回点选并记下原因；卡片随落定帧收成「已由其他端答复，或已超时 / 被撤销」。本端同一时刻只有一个在途答复。
- **结局**：服务端 `outcome` 有 `answered | timeout | cancelled`。超时 30 分钟（`PROMPT_TIMEOUT_MS`）；取消发生在停止与会话关闭时。agent 看到的是：审批「审批超时，已拒绝」「审批已取消，已拒绝」；`ask_user` 的 “The user did not answer (timed out).” “The question was cancelled.”。**前端不用 `outcome`**：他端答复、超时、取消都收成同一个「已由其他端答复，或已超时 / 被撤销」，卡片也没有倒计时。
- **审批卡**（`PromptCards.tsx`）：琥珀描边加点、不铺底，标题「需要你确认 · {标题}」，命令全文（`detail.summary`，展示有上限，超限直接拒绝）、原因 / 提示（越界原因、隐私变量说明等）、「其他已连接的端会同步收起」。按钮：批准（唯一实心）、拒绝、其余选项（如「批准并记住」，仅当这次调用能生成可记住的规则）依次弱化；另有「拒绝并说明」展开一行输入（`RichInput` 文字模式），理由随 `deny` 发出、转给 agent。批准不带话。答后收成一行：「已批准 · / 已拒绝 · / 已批准并记住 ·」+ 命令摘要，拒绝带「理由：…」，加时间。
- **提问卡**（`PromptCards.tsx`）：选项按钮 + 输入框（`input` 有就一直在，Enter 提交、Shift+Enter 换行），答后收成「已答复 · 选项 · 文字 · 附件 文件名」。`ask_user` 的输入框是 `RichInput`，可以带图片和文件（`attachments: [{path}]`，图片随工具结果交给模型，文字里带标记行；也可以只给附件不给文字）；插件的输入弹窗只有文字框；插件的选择 / 确认只有按钮。
- **位置**：待答卡固定在流底、typing 之前；落定后按发生时的消息序位挂进流里。
- **几个同时待答合成一处**（`tab/PromptPager.tsx`）：并行的 `ask_user`（或几个工具同时要审批）不摞成几张卡，而是一张卡，卡头右侧「‹ 1 / 3 ›」来回切换（首尾相接），每个问题单独作答，答完（离开待答列表）自动落到剩下的第一张；各卡保持挂载、只隐藏没在看的，切走再切回写了一半的回答还在；只有一个时没有切换器。
- **对会话状态的影响**：有待答弹窗时会话状态是 `blocked`，界面叫「待处理」（`session/library.ts`），左轨按它显示；「新结果 / 出错」未读标记存服务端，状态与未读规则见 [`workspace.md`](workspace.md) §5。
