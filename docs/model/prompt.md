## 1. 实体

| 实体 | 是什么 | 持有 |
|---|---|---|
| 卡片 | 可复用的文本片段 | 卡片库 |
| 段 | 加载顺序上的一个位置；段内是「已启用 + 候选」两个有序列表（§5） | 预设 |
| 预设 | 一组段。`kind`：`agent` / `mode` / `global-extra` / `global-agentsmd` / `project-agentsmd`（后两种只有一段、没有分组与条件，S2′） | 预设库 |
| Agent 定义（`kind=agent`） | 身份 + 基线提示词（各段）+ 基线能力集。**不带权限** | 预设库；会话**活引用** |
| 模式（`kind=mode`） | 提示词（含 user 通道段）+ 对能力的操作（§4）。**不带权限** | 预设库；会话持有可用清单 |
| 全局 AGENTS.md | 全局约定；运行时读的是文件 `~/.ys/AGENTS.md`（Server 本机），库里存多个**版本**（`kind=global-agentsmd`，卡片拼接），**同时只激活一个**，激活时写进这个文件；文件被手改过要覆盖先问（S2′） | 全局（预设库 + 文件） |
| 项目 AGENTS.md | 项目约定；运行时读的是主目录（逻辑 local）下的 `AGENTS.md`，**项目自己的文件**，框架只读；库里存**模板**（`kind=project-agentsmd`），**创建工作区时选一个**写进主目录作为起点，之后不再管（S2′） | 目录里的文件（模板在预设库） |
| 全局附加提示词（`kind=global-extra`） | 全局的、可按条件路由的提示词（例：某个模型上的部署限制）；预设库里可存多个版本，**激活**一个；**不是 AGENTS.md** | 预设库 |
| 会话设定 | 见 §6 | 会话 |

卡片库的约束：卡片是提示词的唯一来源；内置卡片只读，复制后才能编辑（副本标题带「（副本）」）；被预设引用的卡片拒绝删除（409 `in_use`，附引用清单），不会出现「卡片已删除」的悬空引用（`store/prompt-cards.ts`、`api/studio.ts`）。**卡片库的分组**：分组由卡片自己带的名字长出来，另外可以单独建**空分组**（名字存 `meta.card_groups`，`POST /studio/card-groups`，重名 409 `exists`）；删分组（`DELETE /studio/card-groups/:name`）**只有空分组能删**（里面还有卡片 409 `not_empty`，先在卡片编辑里改分组或删卡片）；内置分组因为有内置卡片所以删不掉；不做改名。卡片的分组可以在卡片编辑弹窗里改。

**默认行为构建**：卡片库没有种子，开箱只有一个内置分组「默认行为构建」，放默认 Agent `coder-full` 用到的全部卡片（pi 原生的身份、工具清单、工具使用规则，去掉 codemode 行；pi 的文档索引卡不要，之后换成我们自己的；pi 的卡原样不动，我们的调优叠加在它们之上：`k-paths` 路径与主机、`k-attachments` 附件、`k-showing` 向用户展示文件与图片，三张英文卡同在 `a1-hosts` 段 `<hosts-and-files>` 里，写法与 `session/address.ts`、附件标记行、前端 `imageRef.ts` 的 `file:` 引用一一对应，改一处要核对另几处），再加内置模式 `plan` 的一张卡。内置预设只有 `coder-full`、`plan` 与页面阅读 agent，全部只读（API 写操作 409 `builtin`）、卡片只能复制；调优自己的 Agent 时以它为参考基线。数据定义在 `prompt/baseline.ts`，启动时由 `ensureBuiltinAgents` 按代码覆盖；默认 agent = 第一张 agent 预设，所以 `coder-full` 先于 page-reader 写库（`presets.list` 同刻按 `rowid`）。

## 2. 能力求值

- **E1 顺序**：Agent 基线 → **会话自己的增减** → **模式的操作，压在最上面**。模式是上限。求值是**纯函数**，每次运行前现算，结果是 `tools` 槽的输入（送达见 delivery §3.3）。
- **E2 会话可以增也可以减**基线能力；会话存「引用哪个 Agent 定义」和**自己的增减**，不拷贝。（能力部分的现状见 §8。）
- **E3 活引用**：Agent 定义被改，所有绑定的会话（含已存在、含创建时是旧内容的）都要感知；**静默**，编辑当下不触发模型请求，随下一次运行带上。提示词部分已是活引用（每次运行现算、现比较）；能力部分见 §8。
- **E4 有会话引用的 Agent 定义不能删**：服务端拒绝（409 `agent_in_use`），界面置灰并写「被 N 个会话引用」。按字面，已归档的会话也算引用，会话被删后引用消失。
- **E5 运行中改能力即时生效**：下一次运行生效并走状态通知；**前提**是创建时让 pi 的工具注册表装全（delivery §6-2）。
- **E7 默认关闭的能力单元**：危险的开发 / 调试工具归进一个能力单元 `unit:devtools`（界面「开发调试」，工具目录里自成一组，`DEFAULT_OFF_UNITS`）。「不限制」（Agent 能力为 null）**不含**默认关闭的单元：要在 Agent 或会话的能力里明确勾选，或由模式「增加」才启用；开启的人自己知道风险，所以这组里的工具不再设防（不打码、不加白名单，只留高敏感站点的逐动作确认、私有变量遮罩，以及出网工具共有的站点授权）。组里现有 7 个浏览器工具：`browser_network`（请求与响应体）、`browser_exec`、`browser_storage`、`browser_request`、`browser_route`、`browser_emulate`、`browser_cdp`，设计见 [`browser.md`](browser.md)。服务端 `session/capabilities.ts` 的 `unlimitedTools` 在算「不限制」的工具集时去掉它们，web 端 `api/capabilities.ts` 的镜像带 `defaultOff`，「改为逐项勾选」展开 null 时同样不含。
- 模式「增加」的工具，即使会话里取消了勾选也会出现；会话勾了、但被模式限定或减少的工具，不生效。
- **E6 框架工具**：工具目录里标为框架工具的，是运行时的必需件，始终可用：不出现在可勾选能力里、不受模式的限定为 / 减少、自身权限放行（它包着的内层调用照常受约束），唯一例外是 `switch_mode`：默认每次人工批准，可在设置里改成放行（见下方「工具规则」），见 [`subagent.md`](subagent.md) §7。现有框架工具：`call_tool`、`ask_user`、`todo_write`、`get_goal` / `create_goal` / `update_goal`（见 [`goal.md`](goal.md)）、`deliver`、`switch_mode`、`job_start` / `job_list` / `job_stop` / `job_remind`、`post`（只有团队里的 lead 与成员才有，见 [`team.md`](team.md)）。**不为任何具体模式写放行表**：模式由用户定义，「plan」只是常见的一种。`switch_mode` 仅在会话有可用模式时声明，`deliver` 仅在子代理会话里声明。子代理的派发工具（`spawn_subagent`、`message_subagent`）作为**一个**能力单元「子代理」整体开关，不细分到单个工具，见 [`subagent.md`](subagent.md)。

## 3. 权限

- **P1 只有两层：全局默认 → 会话，持有覆盖**：会话只存自己覆盖过的字段，没覆盖的**活地跟随**全局。工作区**不带权限层**：它的「新会话默认配置」只在新建会话时把覆盖项写进会话（拷贝后互不影响）。**Agent 定义与模式都不带权限**，「权限跟着环境走，不跟着人设走」。目录上不设默认权限档或上限，只保存记住的规则。
- **P2 没有「禁止」档**（MCP 服务档同样没有）：禁止一个工具等于把这个能力去掉，不留两个入口；每格只剩放行 / 审批。**附件区「外部一律禁止」** 不是用户设置，而是该区域的固有约束：附件区是虚拟主机 `attachment`（不是可切进去的工作目录，也没有工具白名单），地址越出附件区根在 `session/address.ts` 解析处就报错，根内路径在 `judgeTarget` 里直接放行（见 [`workspace.md`](workspace.md) §3「多目录下的工具语义」）。
- **P3 档位沿用现有命名**：`rules / auto / full`（规则 / 模型 / 通过）；矩阵的「cwd 内 / 外」就是现有的 `inside / outside` 两格。
- **P4 敏感路径**：规则 / 模型档下命中仍是「必须人工、不可记住、不可交审核模型」；**「通过」档不受它约束**（选这个档就是自己承担风险）。清单是常量 `SENSITIVE_NAMES`（`paths.ts`），不开放设置，**收窄以减少误报**：排除 `.env.example` / `.sample` / `.template` / `.dist` / `.tpl` 这类固定后缀的模板名，规则只能尽量、无法穷举，**宁可漏排不要错排**（`.env.example.local` 可能真带密钥，不排）。排除要落在 `sensitiveName`，**同时同步 `globMaySensitive` 的 `SAMPLE_NAMES`（含 `.env.a`）**，否则 `cat .env.e*` 仍被判敏感，与直接写 `.env.example` 不一致。
- **工具规则**：设置 · 工具与能力页列出 Server 注册的**全部**内置工具（共 60 个，`GET /api/v1/tools`），按用途分六组（文件与命令 / 目录与传输 / 编排与委派 / 浏览器 / 开发调试 / 框架工具；分组在 `session/tool-catalog.ts` 的 `TOOL_GROUPS`，提示词与能力页的能力勾选共用同一份）。每个工具三选一（`kind`）：**path**（`read` `grep` `find` `ls` `write` `edit` `bash`）沿用「cwd 内 / cwd 外」两格；**flat** 一个开关（放行 / 审批，不分 cwd；存储仍用 `tool_rules` 的 inside / outside 两列、两列恒相等，`permission/tool-matrix.ts`）；**fixed** 只读展示（`transfer_files` 两端各按所在目录的读写规则，其余框架工具自身放行）。flat 工具出厂放行，例外是出厂审批的 `switch_directory`、`workflow_run`、`browser_open`（外部站点按工作区批准，本工作区文件与自起的服务免审批；放行 = 不再询问站点）、`browser_upload`、`switch_mode`；其余浏览器工具只作用于已打开的页面，高敏感站点的每个动作由工具自己确认。无人值守的子会话没人能批，设为「审批」的工具在那里被拒；`list_directories` / `switch_directory` 在子会话里照旧放行；`workflow_run` 与 `switch_mode` 设为「放行」时与通过档同位置放行（子会话也放行）。通过档对所有 flat 工具仍整体放行。设置在页面上进草稿、点保存一次落库（`PUT /api/v1/tools/rules` 原子写）；组头菜单可批量「全部放行 / 全部审批 / 全部恢复出厂」。`powershell`、`tool_search` 不在目录里。规则只管「路径落点」这一条轴；敏感路径、解释器前缀不可记住、root shell、sudo、隐私变量范围是不对等的约束，**不进规则、也不会被「放行」绕过**（`permission/decide.ts`）。MCP 服务自己的审批档（默认 `ask`，`store/mcp.ts`）同样只剩放行 / 审批两档。
- **P5 审批模型只在全局设置里配一个**，会话不单独指定；会话里只选档位，选了「模型」档却没配审批模型时，该档禁用并提示去全局设置配置。设置 · 默认值里有「默认权限档」与「审批模型」两节（`GET/PUT /api/v1/defaults` 的 `permissionTier`、`reviewModel`）；服务端 `session/reviewer.ts` 用它建无工具、不落盘的审核会话，每次审核现读配置；选「模型」档时服务端也校验（400 `review_model_missing`）；设置页里清掉审批模型时，若表单里的默认档是「模型」则一并退回「规则」（这一联动只在表单里做，服务端只校验请求带的档位）。
- **P5′ 审核提示词：头尾固定，只有「判别准则」可改**：审核会话的系统提示词 = 固定开头（角色、`{decision, risk, reason}` 的输出格式）+ **判别准则** + 固定结尾（用户消息与弹窗问答可信、助手与工具输出不可信、防注入）。头尾写在 `permission/review-policy.ts`、不开放修改，免得改坏格式让所有审核退化成「问你」；准则的默认文本也在那里。两层来源，**每次审核现读**（改了下一次就生效）：①全局：设置 · 提示词与能力 · 审核提示词（`GET/PUT /api/v1/review-prompt`，存 `DefaultsStore` 的 `review_criteria`，空 = 恢复默认；头尾只读展示）；②工作区：「编辑工作区 · 审核要求」，一段文字 + 模式 `append` 追加（接在全局准则后面）/ `override` 覆盖（只替换判别准则，头尾照旧），文字为空 = 跟随全局；存在 Server 的 `workspaces` 表（`review_mode` / `review_text`），不放项目目录里的文件：agent 能改项目文件，等于自己放宽自己的审核。长度上限 4000。项目差异在工作区层表达，会话不单独再设一层。
- 模式对工具的限制**仍靠 `tool_call` 钩子拦截**（依据是模式求出的能力集合，不是权限格子），要求与细节见 delivery §4。

## 4. 模式

- **M1 对能力的三种操作，只属于模式**：**限定为**（工具集限制为给定集合）、**增加**、**减少**（从现有工具集中去掉若干，没有则无事）。权限的其他任何地方都不用这套说法。
- **M2 同一时刻最多激活一个**；运行中**随时切换**，静默，下一次运行由状态通知带上。
- **M3 可用模式清单是会话级设定**：会话自己持有，**可增减**；不挂 Agent 定义，也不是「库里全部都可切」。会话存「可用清单」和「当前激活的模式」（可为空，即只有基线能力）。
- **M4 从可用清单里移除当前激活的模式 = 同时退出该模式**，下一次运行通知。
- **M5 模式 = 提示词 + 工具的集合，整体走 user 消息尾注，不进系统提示词、不进冻结物**：不合成系统提示词里的 `<mode>` 段，创建会话时也不与 Agent 的能力取交集。
  - **进入 X 模式**：模式设定（用户写的卡片按原文发，框架句英文）+ 工具变化 + 新增工具的签名（走占位通道）。**模式卡片里标成 user 通道的段，并入这条通知**，不单独发。
  - **退出 / 切换 / 移除**：写明已退出 X 并**说明还原了什么**（工具「已卸载」，限定「已解除」，减少「已恢复」）；切到 Y 则一条通知写完「退出 X、进入 Y」。
- **M6 内置模式只留 `plan`**（`prompt/baseline.ts`）：能力限定为只读工具集（`read` `grep` `find` `ls` `todo_write` `list_directories`），不带权限字段。
- **M7 切换入口是输入栏旁的模式胶囊**，而不只在设置里切：点开列出本会话的可用模式并带一项「无模式」，选一个即切，当前模式在栏上一直可见；可用清单为空时不显示。

## 5. 提示词形态

- **S1 去掉画布，改成「已启用 + 候选」列表**：每个段两个区，已启用（按顺序，可拖动排序）和候选（没启用的卡片），把候选拖进已启用区即选用。画布的连线只决定顺序与哪些卡片参与，不表达别的；路由提示词用 S3 的条件表达。因此没有卡片坐标、入口 / 出口锚点、连线，也没有「入口到出口没连通」「连线成环」这类只在画布上才有的错误。数据只有预设与段（`prompt_nodes`）两层。界面上：模式的能力页是「限定为 / 增加 / 减少」三选一；分组可拖动排序（拖分组头的手柄，或菜单「上移 / 下移」）；「编辑这张卡片」在原处开弹窗、保存后回到原处（不跳页签：页签面板切走会卸载，没保存的草稿会丢）。
- **S2 两份 AGENTS.md：运行时读的是文件**。理由：①项目级 AGENTS.md 绑的是项目性质，不适合挂需要路由计算的东西；②全局 AGENTS.md 应是稳定的约定与习惯，「harness 读取和修改全局约定」是各 harness 的事实标准与惯例，行为要稳定可预测；③动态的东西（按模型 / 供应商拼接）本来就该放在 agent 定义的组装通道（pi 原生的路由拼装也在 section 里），或者单独给一个全局入口（全局附加提示词，见 S3），不该混进标准文件里。**全局与项目两份约定冲突或重复时框架不处理**：由用户自己保证，框架不加优先级说明，不去重。
  - **全局 AGENTS.md**：`<ysHome>/AGENTS.md`，缺省 `~/.ys/AGENTS.md`（与命名流程的 `~/.ys/workflows` 同一个根，`config.ysHome`），**不用 pi 的 `~/.pi/agent/AGENTS.md`**，避免和 pi 自己的文件冲突。在 Server 所在机器上读写；设置页不直接编辑文件，激活预设版本时写入（S2′）。远程主机上不读、不镜像（`~/.ys` 与远程主机的关系未定，见 `workflow.md` §8）。
  - **项目 AGENTS.md**：只读会话**主目录**（逻辑 local，子代理是它自己清单的第 1 个）下的 `AGENTS.md`，经该目录所在主机的环境读取，所以 SSH 主目录也读得到；**不往上级目录找，不认 `CLAUDE.md`**。没有就算没有。文件创建之后框架只读不写（创建工作区时按所选模板写一次，见 S2′）。
  - **何时读**：和预设一样属于「提示词基线」，在**建会话、重启后装载、压缩 / 换模型 / 手动同步重建基线 / 刷新上下文（`/reload`，原地）**时读（这几个时刻基线本来就要重新拼，前缀缓存本来就失效）；运行中改文件不会立刻带上，下一次重建带上；要立刻生效用「刷新上下文」。决定：重建点重读，而不是创建时读一次冻结到会话结束；理由：冻结要把文件内容再存一份进会话，代价大于收益，而重建点重读恰好能让 agent 自己改过的约定在压缩后生效。
  - **段与顺序**：系统提示词里依次是 agent 定义的各段、`<global_agentsmd>`（全局文件原文）、`<global_extra>`（全局附加提示词渲染结果）、`<project_agentsmd>`（项目文件原文）；三段都不进状态映射（改动只在重建时带上）。文件原文送进去（只去掉首尾空白），不加工、不求值；没有文件、读不了、内容只有空白都当作没有，不报错、不出段。
- **S2′ 两份 AGENTS.md 的内容由预设生成**（服务端 `session/agents-md-presets.ts`、`api/studio.ts` 的激活与保存、`api/agents-md.ts` 的导入、`api/workspaces.ts` 的 `POST /:id/agents-md`；界面见 skill `ys-ui-design` 的 X07）：运行时读的是文件（S2），编辑方式仍是卡片拼接，结果落盘成文件。设置页「提示词与能力」里有「全局 AGENTS.md」「项目 AGENTS.md」**两个页签**，和 Agent、模式并列——卡片库 + 拼接编辑；与 Agent 预设的区别只有两点：**没有分组、没有按模型路由**（这两份没有条件，拼出来是固定文本）。「全局附加提示词」页签**带分组与模型路由**（S3）。
  - **全局**：库里可存多个版本，**同时只能激活一个**；激活的那个落到 `~/.ys/AGENTS.md`，是全局唯一生效的稳定约定。
  - **项目**：只有库，**没有全局激活**；**创建工作区时选一个**作为项目 AGENTS.md 的起点，落到主目录的 `AGENTS.md`，之后这个文件归项目自己，框架只读。
  - **运行时读的是文件，预设是生成它的工具**：文件被人或 agent 手改过，再激活 / 再写入预设会覆盖它时，**先提示，覆盖还是保留由用户决定**（项目那份：主目录已有文件时问追加 / 覆盖 / 不写）。
  - **落地细节**：两种预设 kind 为 `global-agentsmd`、`project-agentsmd`；保存校验 `flat`（只一段、无段名、`custom` 段、无分组）；拼文本 = 各卡片正文 trim 后空行连接、末尾一个换行；「文件被手改过」= 磁盘内容的 sha256 与最近一次写入的记账（`meta.global_agentsmd_hash`）不同（从没写过且有内容也算）；激活、保存生效版本时检查，被改过且没带 `overwrite` 就 409 `disk_modified`，什么都不动；删生效版本 409；导入 = 把磁盘原文建成卡片与新版本并设为生效、同时记账；项目模板写入由 `POST /workspaces/:id/agents-md {presetId, mode?}`，已有非空文件无 `mode` 给 409 `file_exists`，`append` = 原文去尾空白 + 空行 + 模板，`overwrite` 整体替换，创建工作区时才用。
- **S3 提示词路由 = 「分组」里按条件选其一**。决定：不做表达式求值，那对「按模型选一张」这个场景过重，要的就是 switch case。
  - **分组是一个 switch**：段里的卡片可以直接挂在段下面（一律注入），也可以放进「分组」。分组由用户单独创建，卡片**拖进去**才归它（不是点卡片再设分组）；分组里每张卡片带一个**条件**（`when`），写成「如果 ⟨条件⟩ 则用这张」，**自上而下取第一张条件成立的**；条件为空（`null`）的那张是「否则」保底，放在最后。都不成立且没有保底 = 这个分组什么也不注入。要「只有如果没有否则」，就建一个只放一张卡片的分组。
  - **条件现在只有一种：`model`**，值是 `{ providers: string[], models: string[] }`，在界面上从「供应商与模型」设置里**勾选**，不手填；勾整个供应商 = 它下面的全部模型（含以后新增的），`models` 里存 `"供应商id/模型名"`。条件对象带 `kind` 字段，**留好点位**：以后别的条件加成新的 `kind`，界面上是条件弹窗顶部的「条件类型」下拉（现在只有「模型」一项）。**不做表达式、不做 `&&` / `||` 组合**；真遇到组合需求再加新 `kind`，不预先支持。
  - **不需要沙箱求值**：条件是结构化数据，匹配是纯函数，没有语法错误、超时、内存超限这些失败模式。`quickjs-wasi` 沙箱只用于工作流脚本（`workflow.md` W2）。
  - **数据上**：每个段（`prompt_nodes`）多一列 `items`，存一棵 JSON：直接挂的卡片 `{kind:"card", cardId}` 与分组 `{kind:"group", id, name, cards:[{cardId, when}]}`，数组顺序就是顺序。条件挂在卡片**在预设里的位置**上，不挂卡片本体（同一张库卡片在不同预设里可有不同条件）。**没有另建分组表、也没有 `group_id` 列**：分组只属于一份预设的一个段，整树随「保存」一次整份替换（`PUT /api/v1/studio/presets/:id/nodes`），一列 JSON 比三张关联表少一半代码，也不会出现半截状态；代价是「某张卡片被哪些预设引用」要扫全部段（`cardUsage()`），预设只有几十份，可以接受。同一张卡片在一份预设里只能出现一次（服务端校验）。
  - **按条件选出的结果何时算**：Agent / 模式（进系统提示词）与全局附加提示词在**创建会话**时按当时的供应商与模型求值，结果写进冻结物；**换模型 = 完整重建**（delivery §3.2）。实现上没有单独往冻结物里记条件输入：每次运行前的比较拿的是「按会话此刻模型现渲染」的文本（`pool.liveRender` 带 `modelRefOf`），与冻结物里的不同就重建，所以条件输入的变化自然被发现；`syncModel` 换模型后也立刻 `rebase`。目前没有「不触发重建、却会让结果变化」的条件，所以不需要尾注（若将来出现，见 §8）。**OS 不作条件**：会话可以跨多台主机，OS 是主机属性不是会话属性。
  - **全局附加提示词**（`kind=global-extra`）：保留预设机制（卡片、分组、条件、多版本、**激活一个**、按会话此刻的模型求值），内容是全局的、按条件路由的补充规则；**它不叫 AGENTS.md，也不写进任何 AGENTS.md 文件**。与 agent 定义里的路由并列存在：agent 里的路由是「这个角色在这种模型上怎么说」，这里是「不管哪个角色、在这个模型上都要加的规则」。两处都能写路由，放错或重复由用户自己保证，框架不去重。
- **S4 内置「环境信息」段**（`session/environment.ts`；**不做成可编辑卡片**，由服务端求值）：我们生成（英文），内容：**会话创建时间**（日期时间加时区偏移，附一句「这是会话开始时的真实日期，可能远晚于训练数据，别凭记忆推年份；要当前时间自己跑 `date`」，用意是让模型对真实时间有认知）；**每台涉及的主机**（会话目录所在的主机；名字就是工具里 `host` 参数的取值，目录写作 `<host>:<name>`，见 `workspace.md` §3「多目录下的工具语义」）一行，其下列出这台主机上登记的目录（名称与路径，不标当前目录，免得每次切换都改这段文本；表头一句说明地址写法）：内核、版本、架构（本机取 node 的 `os`，ssh 取激活时探测并缓存在 `EnvHub` 里，没探测到写 `system not detected yet`）；用户**主动断开**的主机留在清单里并标 `DISCONNECTED by the user`、让模型请用户去「设置 · 远程连接」激活、别重试。**不放**：git 分支（模型自己探）、shell 种类、日期时间的持续更新（创建时间不变，所以不进状态差异）。它是状态映射里的 `prompt.environment` 槽：每次运行前现算，接入新主机 / 移除目录 / 断开 / 重新激活 / 探测到系统信息，都会让文本变化，由状态通知（文本差异）告诉模型，不重建会话；目录清单就在这一段里，所以目录变更通知只写新增 / 移除 / 当前目录，完整清单靠这一段的文本差异带给模型。网络闪断自动重连的瞬时掉线不标（只有用户主动断开才标）。对已断开主机调工具，报错是英文并点名主机、让模型转告用户去激活（`env/hub.ts`）。会话中途把目录挂到另一台主机上做联合调试，或减掉一台主机，是这段设计要覆盖的真实使用场景。

## 6. 会话设定与默认配置

- **F1 默认配置是一份**（全局默认 → 工作区稀疏覆盖，建会话时拷贝；多模板即多个 Agent 定义），**默认 Agent 定义是其中一个字段**，新建时自动选中，用户可改。
- **F2 新建会话两个入口**：①左轨「+ 新对话」**直接用默认配置建好并进入**，不弹窗；②「带配置新建」打开创建弹窗，**打开时已预填默认值**，逐项改后点「创建」才建。创建弹窗与编辑是同一个组件（`workspace/dialogs/SessionDialog.tsx`，靠 `mode` 区分 create / edit / from），不存在「两个界面」。
- **F3 Agent 定义创建后不可更换**：它决定身份，换 Agent 等于换了一个会话。用「+ 新对话」直建时没有选 Agent 的机会，想用别的 Agent 走「带配置新建」。
- **F4 字段表**：

| 字段 | 存法 | 默认配置里 | 创建后可改 |
|---|---|---|---|
| Agent 定义 | 活引用 | 是 | 否 |
| 能力增减 | 相对基线的增 / 减 | **否**（能力由所选 Agent 决定；要别的能力集就建另一个 Agent） | 是 |
| 可用模式清单 / 当前模式 | 清单 + 当前（可为空） | 清单是，当前不是 | 是 |
| 可派发的子代理清单 | 清单（Agent 定义的引用） | 是 | 是（详见 [`subagent.md`](subagent.md) §7） |
| 模型、思考强度 | 值 | 是 | 是（换模型触发重建） |
| 权限覆盖 | 稀疏，没覆盖的跟随全局 | 是 | 是 |

- **F5 能力的显示：会话自己的增减与模式的影响分开**。**常态列表**：每个工具显示是否启用（复选框）与来源标记（来自 Agent 基线 / 你增加的 / 你去掉的），勾选即写会话自己的增减，改过的项可「恢复为 Agent 基线」（逐项与整体，X02）；复选框始终只反映会话自己的设定，**不因模式变灰或改值**。**模式影响单独一块**：激活模式时另起一处写明「当前处于 X 模式：限定为 / 增加了 / 减少了 哪些工具」，没有激活模式就不显示；「勾了却不生效」的解释由这一块承担。（现状：只有复选框与整体「恢复 Agent 基线」，其余见 §8。）
- **F6 Agent 定义可带默认模型与思考强度（均可空）**，沿用 `agent.modelId` / `thinkingLevel` 的叫法。优先级：创建时手选的 > Agent 带的 > 工作区 / 全局默认配置；派发子代理时：`spawn_subagent` 的 `model` 参数 > 子代理 Agent 带的 > 调用方的模型。用途：探索类 Agent 固定用小模型省成本。创建弹窗里模型字段按 X02 显示值的来源（跟随 Agent / 跟随默认 / 已覆盖）。（未实现，见 §8。）
