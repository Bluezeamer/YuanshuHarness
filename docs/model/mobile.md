# 手机端

Author: bluezeamer
Status: 现行（真机才能验的项在 §12）
Date: 2026-11-19
Verified: 2026-11-19（对着代码核对：`packages/web/src/mobile/`、`m/index.html`、`public/sw.js`、`public/m/`、`src/api/foreground.ts`、`features/workspace/model/tabKinds.ts`，`packages/server/src/devices/`、`push/`、`store/devices.ts`、`api/devices.ts`、`api/lib/ws.ts`、`api/sessions.ts`）

本文是手机端的现行设计。**手机端只是同一个 Server 的一个访问通道**：不新增服务端能力，也不叠加复杂度，所以没有 ntfy 之类的兜底通知通道（§9），也不在 Server 里内置证书管理（§7）。写手机端代码的约定在 skill `ys-mobile`。

## 1. 范围

- **目标**：人不在电脑前时，能看到电脑上能看到的信息（观测对等），能回一句话、批准一个动作。
- **做**：会话列表、对话、审批与提问、发文字与附件、所有标签类型的只读查看（§5）、浏览器画面观察（§6）。
- **不做**：分屏与窗格布局、供应商 / 提示词 / MCP 等设置页（只留手机自己的设置，§8）、浏览器接管（§13）、agent 步骤回放。
- 手机上好不好用是另一回事，底线是看得到、点得到。

## 2. 入口与代码组织

- **同仓库、同前端包的第二个入口 `/m/`**：独立 HTML（`m/index.html`）、独立构建产物（Vite 多页），有自己的 manifest 与 viewport 设置，不加载桌面外壳、窗格与各标签的重依赖。**不自动跳转**（平板、窄窗口会误判）；登录页放一个「手机版」入口。
- **复用**：chat 对话视图（`ChatView` 是纯属性驱动，绑着窗格的只有外面包的 `ChatTab`）、chat 状态层、`api/`、`ui/` 与设计令牌、markdown 渲染。**不共用**：桌面 Shell、平铺窗格、各标签的窗格外壳、设置页。
- **手机版布局 store**：实现 `LayoutStore` 里「打开某个东西」的那一批意图级操作（`openPreview`、`openFilePreview`、`openDiff`、`openTeamDiff`、`openInBrowser`、`openTab` 等），语义是**往导航栈推一页**；各标签类型的注册渲染器拿到「单标签的假窗格」，内容不重写。chat 里碰布局的地方（`TurnChangesCard`、`StatusFoot`、文件链接等）经它接上；`Markdown`、`TurnFooter` 已按「没有布局也能用」写成可选。
- 窄屏样式要在真浏览器里逐项量：悬停卡、左缘导航线、右侧状态栏在手机上去掉或换形态。

## 3. 导航

- **根页面是会话列表**，不是聊天加抽屉：并发会话多，「哪个在等我」要一眼看到；通知点进对话时栈底是列表，返回键不会直接退出。
- 栈：列表 → 对话 → 详情层（审批、附件选择、产物预览、浏览器画面、各标签页）；**每层各占一条历史**，系统返回键与页面返回按钮走同一个 `back()`，关闭弹层就是返回一层；URL 与 `history.state` 是唯一真相。
- 不做自定义手势（不加边缘侧滑）。

## 4. 会话列表

- 最上面一个**「需要你」区**（跨工作区）：待处理（有审批或提问）排前，其次出错；「新结果」不进来。没有这些会话时整区不出现。数据是会话列表 store 的一次筛选，不需要新的服务端能力；分组、排序、汇总的纯函数直接复用左轨的。
- 下面与桌面同样的分组 → 工作区 → 会话。行：标题、一行副标题（「需要你」区写工作区名，分组里写相对时间）、一个状态点；行高 ≥ 48px。行操作（归档、置顶）长按弹出。
- 右上角：新建会话、设置入口；每个工作区头上一个「工具」入口（§5）。

## 5. 标签类型与对话页

- **所有标签类型都能在手机上打开**，都是同级的跳转页。新建入口只有四种（文件、终端、浏览器、画布），在「工具」菜单里（对话页顶部、列表里每个工作区头上），对当前工作区生效；终端、文件要选主机（只有一台时跳过）。手机不保存窗格布局。
- **`chat`、`preview` 不能从「+」新建（桌面手机一起改，`TAB_KINDS.creatable = false`）**：新建出来的空标签没有任何后续路径会往里填内容（单击会话只换临时标签，单击文件只换同主机的临时预览）。对话从会话列表进，预览从文件管理器、文件链接、改动对比进，执行体与后台任务从对话卡片进。
- **对话页顶栏**：返回、标题、浏览器（该工作区有页面时才出现，agent 在操作时带小点）、状态（底部抽屉，内容是桌面右栏：目标、计划、团队、工作流、子代理、已加载能力；有东西在跑时带小点）、工具菜单。去掉：左缘导航线、悬停详情卡；审计入口收进工具菜单。
- **输入栏**：回车换行、发送靠按钮（不传 `onEnter`，提示文字不写「Enter 发送」，不做设置项）；「+」出抽屉：拍照（`capture`）、相册、文件；语音靠输入法听写，不做麦克风按钮；审批档位与模型选择保留；排队气泡、停止钮沿用。
- **键盘**：整页 `100dvh` 的 flex 布局，输入框在文档流里（不用 `position: fixed`），viewport 加 `interactive-widget=resizes-content`，`visualViewport` 兜底（监听 `resize` 与 `scroll`）。
- **审批卡**沿用桌面的，按钮 ≥ 48px、间距 ≥ 8px。

## 6. 浏览器画面（只读观察）

- 入口：对话页顶栏图标；agent 用 `browser_show` 展示页面时手机也弹「查看」。独立一层：顶部页面标题与只读地址、页面切换（同工作区页面的简单列表）；画面默认适应宽度，**双指缩放与单指平移**（只在查看器上 `touch-action: none`，Pointer Events 自己算），带「适应宽度」「100%」两个按钮；横屏不锁。
- **只读**：画面上的点按不发给页面，界面写明「只读观察」。画面仍是固定 1280×800，不为手机另设视口。
- 只在这一层打开时接画面流，离开或切后台就断，回来按 §10 恢复。**Wake Lock**：这一层打开时保持屏幕常亮，仅 HTTPS 下生效，明文下静默没有。
- agent 请你接管（人机验证）是一个阻塞提问，走「需要你」与通知；点开后顶部写「请到电脑上操作」（手机上的接管见 §13）。

## 7. 访问与能力分层

- 手机端的所有核心功能都按**明文局域网**设计和验证（走非 HTTPS 即视为受信任网络，可明文传输）；HTTPS 是可选加成。分界用 `window.isSecureContext`，不看 UA。依据：明文局域网地址不是安全上下文，Service Worker、Web Push、WebAPK 安装、Wake Lock、`crypto.subtle`、`crypto.randomUUID()` 在上面都不可用，而 WebSocket、fetch、`localStorage`、`<input type=file capture>` 不受限；`localhost` 算安全上下文。
- 基础层（任何访问方式）：登录、列表、对话、审批与提问、发文字、拍照 / 相册附件、看产物、看浏览器画面，页面开着时实时。增强层（仅 HTTPS）：安装成独立应用、后台通知、屏幕常亮。
- 不依赖安全上下文专属接口：不用 `randomUUID`、`crypto.subtle`，剪贴板有退路（`ui/clipboard.ts`）。
- **不在 Server 里内置证书管理**。部署文档只写一小段：明文下少哪几样；要 HTTPS 的办法（域名加 DNS 证书、Tailscale、Caddy 本地 CA；Caddy 要关 HTTP/3、`/data` 卷要持久化）。设置页只放一行状态说明，不弹窗。

## 8. 登录与设备

- **设备令牌**：每台手机一个独立令牌（随机 32 位以上，库里只存哈希），全局令牌不动。流程：桌面设置「手机设备」页点「添加手机」→ 弹窗显示二维码与链接（地址框默认当前浏览器地址，是 `localhost` 时提示改成局域网地址；5 分钟有效、一次性）→ 手机扫码打开 `/m/`，用配对码换设备令牌，存 `localStorage`（冷启动不丢）；配对页有一个预填（按 UA 生成）可改的设备名输入框。
- 校验认两种凭据（全局令牌、设备令牌），走原有的 `Authorization` 与 WebSocket 子协议。**只有全局令牌登录的桌面能添加设备**；配对码校验走现有失败限流。
- 桌面「手机设备」页：列表（设备名、创建时间、最近使用）、撤销（二次确认组件）。**撤销**：该设备请求立刻 401，已开的连接断开（等当次响应发完再断，手机「退出此设备」才收得到 204），订阅一并删除。没配令牌的回环模式里，没有身份的请求一律视作全局，配对码照常能建。
- **手机设置页**（列表页右上角入口）：本机设备名与访问方式一行说明；通知（§9，仅 HTTPS 显示，明文下换成一行「当前是明文访问，没有通知」）；添加到主屏幕（有 `beforeinstallprompt` 给按钮，否则图文步骤，已在独立窗口则隐藏）；退出此设备（二次确认，服务端删设备并清本地令牌）。

## 9. 通知

- **只做 Web Push，只在 HTTPS 下有**；明文下没有后台通知，只有页面开着时的实时状态。不做 ntfy 等其他通道。
- 事件三类：待处理（审批、提问）、出错、跑完了，各自可开关。**策略三选一**：总是通知；有人在看这个会话就不发（默认）；延迟 N 秒再发（N 默认 30），期间被处理或有人在看就不发。已发出的通知，事后在别处处理了就**替换**成低调文案（同 `tag`、静默；Chrome 要求每条推送都显示通知，不能静默关掉）。同一会话新通知替换旧的，不叠加。
- 订阅绑定设备令牌；**通知偏好存服务端、跟设备绑定**（什么时候推由服务端决定），在手机设置页改。「有人在看」用现有的列表流 `viewing` 上报。
- 内容只有会话标题与类型，不带命令与输出；点开进该会话（栈底是列表）；**通知上不放批准按钮**。载荷控制在 2 KB 内。
- 服务端：VAPID 密钥生成一次存库、不轮换，`subject` 用 `mailto:`；订阅表；推送返回 404 / 410 立即删订阅；`Urgency: high`、TTL 取小时级；**不硬编码推送服务白名单**。
- **已知边界，接受**：Web Push 经 Google 的 FCM 投递，无 Google 服务的设备、服务端连不上 FCM 的部署收不到，与「没法 PWA 就不通知」同类。

## 10. 断线重连

- 会话流连上先发一份有上限的**快照**（最近消息、是否在跑、在用的工具、挂着的审批与提问、队列），之后是带序号的增量，序号对不上就 `resync` 重拿快照。所以**重连就是拿新快照，不需要服务端事件日志与按游标补发**。
- **回前台**：`api/foreground.ts` 把页面可见、从缓存恢复、网络恢复这几个信号合并成一个（`onForeground`），各条流订阅后自己决定：已断（在退避里等着、或已放弃）就立即重连并清零失败计数；连着就发 `ping` 当探针，3 秒内没有任何消息回来就当死连接、关掉重连；首次连接还在路上的不打断；任一时刻只留一次在途的重试。探针用 `ping` 而不是 `resync`：`resync` 会让会话流每次回前台都重拉一遍历史。服务端四条流各认一个 `ping`（会话流回一个 ack，其余回 `pong`）。**四条流（会话、列表、浏览器事件、浏览器画面）共用这一处，桌面一起受益**，不做手机特例；重连期间不清屏。
- **服务端心跳**：连接另有协议层心跳，Server 每 30 秒发一次 Ping，10 秒内没回 Pong 就断开（`api/lib/ws.ts` 的 `startHeartbeat`，默认值在 `api/sessions.ts` 的 `DEFAULTS`），用来清掉僵死连接；浏览器脚本看不到协议层心跳，所以回前台探活用的是上面应用层的 `ping`。

## 11. PWA 壳

- manifest 单独一份：`id`、`scope`、`start_url` 都是 `/m/`，`display: standalone`，不锁方向，不放 `screenshots`，主题色取界面底色（近白）。图标：192 / 512 PNG、512 maskable PNG、180 apple-touch-icon（用 Chromium 把品牌 SVG 渲染出来，产物入库）。
- **共用现有 `/sw.js`**：加 `push`、`notificationclick`，外壳缓存里把 `/m/` 也预缓存；原规则不变（不缓存 `/api`、不缓存带令牌的请求）；每条 push 都必须显示通知。
- 入口页加载早期捕获 `beforeinstallprompt`；`/m/index.html` 写 `apple-touch-icon` 与 `apple-mobile-web-app-title`（给 iOS 留的）。服务端静态托管给 `/m`、`/m/*` 回退到 `m/index.html`（不能挡住 `/m/` 下的静态文件）。
- 不开 `viewport-fit=cover`（沉浸式要同时处理安全区，见 §13）。

## 12. 验证

- 单测与突变：设备令牌只存哈希、配对码一次性与过期、撤销断连、「有人在看不发」、service worker 不缓存 `/api`、回前台恢复。
- 真浏览器脚本（手机设备描述：触控、390×844、2 倍屏）：列表、对话、返回栈、配对登录、撤销、回前台恢复、明文与 HTTPS 两档（回环地址算安全上下文；测明文档用 Chromium 的 `--host-resolver-rules` 把一个假域名映射到 127.0.0.1，非回环主机名就是明文来源，同时要 `--no-proxy-server`）。推送拆开验：服务端用本地假推送端点核对 VAPID、TTL、紧急度与加密载荷；service worker 用 CDP 的 `ServiceWorker.deliverPushMessage` 验显示与替换。
- **只有真机能验**：软键盘与输入框、WebAPK 安装、有 Google 服务手机上的真实推送、双指缩放手感、屏幕常亮、国产 ROM 浏览器；iOS 一律留给有设备的人。给 HTTPS 档测试用 `adb reverse`（手机用 `localhost` 访问开发机，算安全上下文）。

## 13. 未实现与未决

- **手机上接管浏览器**（设想）：现在只能观察（§6）。要做的话，浏览器画面那一层是入口，触点坐标换算要能处理缩放与平移后的变换（复用桌面 `inputs.ts` 的换算）。
- **沉浸式布局**（设想）：现在不开 `viewport-fit=cover`；要做需要同时处理安全区。
- **iOS 真机**：§12 的真机项里 iOS 没有结论，留给有设备的人验。
