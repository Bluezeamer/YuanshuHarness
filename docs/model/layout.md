本文讲工作区里「窗口 → 窗格树 → 标签」这一层（代码里叫 `l2`：`model/l2.ts`、`layout/L2View.tsx`）的现行规则，以及全局壳：会话总览、命令面板、快捷键。术语「目录」「工作区」见 [`workspace.md`](workspace.md) §1。代码在 `packages/web/src/features/workspace/{model,layout,tabs,store,sidebar}/` 与 `app/shell/`。一屏一个工作区，布局按工作区存，没有「分叉克隆布局」。终端、文件、预览标签见 [`terminal.md`](terminal.md)、[`files.md`](files.md)；对话标签见 [`chat-tab.md`](chat-tab.md)、[`chat-render.md`](chat-render.md)，审计见 [`audit.md`](audit.md)。

## 1. 结构与规则

- 层级：`WindowState{list, active}` → `Window{root, focus}` → 窗格树（分支 `{dir, sizes, children}`，叶子 `Pane{pid, host, tabs, active}`）→ `Tab`（`model/types.ts`）。每个工作区一份（§7），会话不再有自己的布局。
- 上限与关闭：一个窗口至多 6 个窗格（`MAX_PANES`）；窗口数与每格标签数没有上限（mod+1…6 只够到前六个窗口）。关掉窗格里最后一个标签：窗格数 >1 就摘掉窗格，分支只剩一个孩子时折叠；窗口里只剩一个窗格时，改放一个新对话标签并解绑主机。最后一个窗格、最后一个窗口都不可关。关闭标签、窗格、窗口前，里面的终端先统一确认（`tabs/terminal/wiring.tsx`，规则见 terminal.md R8）。
- **外层框架的版式**：通用部分在 `ui/tiling/`——`TilingLayout`（分割树渲染 + 拖动分隔条）、`PaneFrame`（窗格框：头 + 内容 + 六个落点叠层）、`WindowBar`（窗口条）、`zones.ts`（落点几何）、`tree.ts`（分割树纯函数）；样式在 `ui/styles/tiling.css`。它们不认识标签类型与主机，工作区这边（`layout/{L2View,PaneView}.tsx`）接上主机隔离、会话拖入、关闭确认与 F6。类名保留 `ws-` 前缀作语义钩子（测试与脚本用），通用样式用 `u-tile-* / u-pane / u-dz / u-wbar-*`。
- 平铺：窗格之间只有一条 1px 细线（分隔条热区 7px，悬停显蓝），没有外框、圆角与卡片；外壳 `.sh-app` 没有外缝，左轨与工作区平铺（`verify-visual` 的 VR22）。窗口条与窗格头是两种不同的形：窗口条是一排浅灰胶囊（28 高，当前窗口 `--active` 底），窗格头是方的标签条（36 高）。
- 窗口条（`ui/tiling/WindowBar.tsx`，`layout/L2View.tsx` 接线）：胶囊显示「窗口 N」（不显示窗格数、不带序号），`+` 新建，× 仅在窗口数 >1 时出现，←/→ 切换；右端平时没有提示，拖窗格时才出现「拖到窗口标签上，移到该窗口」（胶囊是落点）；窗格区 F6 / Shift+F6 轮转焦点窗格。只有一个窗口时窗口条也不收。
- 窗格头（`layout/PaneView.tsx`，版式是 `ui/TabStrip` 的）：标签条、`+`，右端依次是当前标签的小入口（`headAction`）、**主机标识**、窗格菜单：「移到新窗口」（窗格数 >1）、「移到窗口 N」（其余每个窗口）、「关闭窗格」（窗格数 >1）。没有单独的抓手：窗格头的空白处就是拖整个窗格的手柄。**主机标识 = 色点 + 主机名 + 窗格头底边一道主机色线**（`--tone`，窗格窄于 440px 名字收起只留色点；未绑定主机的窗格什么都不显示）。焦点窗格的当前标签顶线是墨色，其余窗格退成灰色。
- 标签条（`tabs/TabBar.tsx`，类名复用 `ui/TabStrip` 的 `u-strip-*`）：←/→/Home/End 切换，Delete 与中键关闭，拖动排序，**双击临时标签 = 固定**；标题区固定宽度、超出省略（规则在 skill `ys-ui-design` 的 visual-language §4）。**标题只写名字，不带类型前缀**（图标已表示类型：文件标签是目录名，终端标签是 cwd 末段，预览是文件名，对话是会话标题），类型名放在悬停提示与读屏名称里（「文件 · w」）。分隔条单格最小 120px，相邻两格权重各夹在两者之和的 2%–98%，拖动中只改本地，松手才写回文档。
- 容器窄（`ui/tiling` 自己的容器查询，看工作区宽度而不是视口）：宽度 ≤780px 时左右分栏改成上下堆叠，每个窗格保底 260px，整体纵向滚动，分隔条不再可拖。
- 默认窗口（`l2.defaultWindow`）：对话窗格（带出最近的会话时，那个对话标签是**临时**标签，§3）+ 主目录所在主机的一个窗格（files、term）+ 目录清单里**每台其他主机**一个窗格（term、files）；窗格不混主机，总数不超过 6，没有目录时只有对话窗格。新建窗口套用同一规则（对话标签为空）。接线在 `LayoutBridge.tsx`：工作区的目录清单与会话列表到齐后，文档里还没有窗口才补默认窗口。

## 2. 主机隔离（W4）

- 主机档位在 `model/tabKinds.ts` 的 `TAB_KINDS` 里一处声明（`host` 字段），隔离、落点、`+` 菜单选主机、载入兜底都从它派生，没有第二套规则：
  - `none`：没有主机，放进任何窗格（`chat`、`sub`、`job`、`web`）；
  - `data`：带 `tab.host`，但只是内容所在地，不参与隔离，放进任何窗格（`canvas`：画布目录在哪台主机）；
  - `pane`：带 `tab.host`，窗格按主机隔离（`term`、`files`、`preview`，即 `isHostTab`）。
  - 新类型默认选 `none`；内容靠主机定位才选 `data`；只有「这个窗格就是那台机器的工作面」才选 `pane`。
- 窗格的 `host` 取第一个 `pane` 档标签的主机；窗格里没有 `pane` 档标签后回到 `null`（关标签、移走标签时重算）。只装 `none` / `data` 档标签的窗格不绑主机，之后任何主机的 `pane` 档标签都能并进来。
- 并入被拒（`hostConflict`）：落到窗格中心或标签条，主机不同就拒绝，toast 点名两台主机并提示「拖到窗格边缘可贴靠拆分」。拖拽时落点显示「主机不同 · 不可并入」，但仍接受 drop，由 store 弹出提示（`PaneView.tsx`）。
- 四边拆分一律放行，拆出的新窗格属于该标签自己的主机。拖整个窗格到别处的中心或标签条，是把全部标签并入，主机不同同样拒绝。新建跨主机标签自动在窗格右侧开新窗格（`l2.addTab`），已满 6 格提示「最多 6 个窗格」。
- 载入时兜底：文档里同一窗格混了主机，只保留第一个（或声明的）主机的标签，其余丢弃（`persist.parsePane`）。窗格主机色（1…6）按窗口内窗格出现顺序分配，用尽循环（`hostTones`）。

落点由窗格统一判定（`ui/tiling/zones.dropZoneAt`）：标签条（顶部 36px，与窗格头同高）优先于四边，四边取距边 24% 以内（角上并列时左 > 右 > 上 > 下），其余为中心。

| 落点 | 拖标签 | 拖窗格 |
|---|---|---|
| 标签条 | 同窗格内重排；跨窗格并入并插到指针处 | 全部标签并入目标窗格 |
| 四边 | 拆出新窗格，总数不得超过 6；源窗格只剩它时源窗格消失，拖到自己窗格的边缘则拒绝 | 摘下后在目标旁重新插入，总数不变、不受上限 |
| 中心 | 并入目标窗格；拖到自己所在窗格的中心不接受 | 全部标签并入目标窗格 |

标签只能在**同一窗口内**移动：跨窗口、跨会话容器都被拒（`l2move.sameWindow`）。窗格可整体搬到别的窗口：拖到窗口胶囊，或菜单「移到窗口 N」，落在目标窗口焦点窗格右侧并切过去；目标已满 6 格则拒绝；源窗口只剩这一格时，搬走后源窗口随之消失；「移到新窗口」在窗口里只剩一格时拒绝。

## 3. 标签类型

| 类型 | 说明 | 绑定 |
|---|---|---|
| `chat` | `sid` 显式绑会话；没有 `sid` 的是**空对话标签**；`temp` 标记**临时**标签；`ctab` 切对话 / 审计；同会话可在多个窗格里开 | 会话 |
| `sub` | `sid` + `sub`；只能从右栏执行体清单点开，不在 `+` 菜单里；同一窗口内同一执行体只开一个（`chat/exec/useOpenExecution.ts`） | 会话 |
| `job` | `sid` + `job`（后台任务 id，任务属于那个会话）；只能从对话流里的回调卡或右栏「后台任务」块点开，不在 `+` 菜单里；同一窗口内同一任务只开一个（`chat/job/useOpenJob.ts`）；内容是任务头（状态、种类、用时、退出码、复制命令、停止）+ 完整命令 + 实时输出（`chat/job/JobView.tsx`）。子代理 / 团队成员的任务不走这个标签，点开去它们的 `sub` 标签 | 会话 |
| `term` / `files` | 主机 + cwd / path，见 terminal.md、files.md；`term` 另存 `termId`（服务端终端 id，随该工作区的文档存）。**没有「所在会话」**：审计归属传 `null`；文件监听要一条会话流，用「锚点会话」（正在显示的会话 → 窗口里任一对话标签的会话 → 最近的未归档会话；都没有就不监听） | 工作区 |
| `preview` | 主机 + path，或 `diff` 形态（轮末 diff 带 `sid`）。打开路由（`l2.openPreview` 等）：已开同主机同路径就激活；窗口里有同主机预览窗格就并进去；否则在来源窗格右侧新开窗格 | 工作区 |
| `web` | 工作区级的「虚拟浏览器窗口」（`tabs/web/WebTab.tsx`）：页面由 Server 持有，标签只记当前显示哪一页（`tab.page`，没有或页面已关就取最近用过的）；同工作区的所有 web 标签共用 `features/workspace/browser/` 里的一条事件流与一份页面表，每个标签各自开一条该页的画面流。观察态（agent 在用）只读旁观，手动态（你接管，或你自己开的页面）收键鼠、有后退 / 前进 / 刷新与可编辑地址栏。agent 一用浏览器工具就自动出标签（`useBrowserAutoTab` → `revealBrowser`：没有→新开窗格、在后台→切过去、在前台→标签自己在工具条上提示「有新页面」，都不抢焦点）。工具条按窗格宽度分四档（`tabs/web/web.css`，阈值实测）：宽 > 640 次要按钮带文字；≤ 640 只剩图标；≤ 500 保存登录 / 回放 / 控制台收进「…」菜单；≤ 400 后退 / 前进 / 刷新与「有新页面」小条也收进去、「页面 N」只留数字、地址栏锁图标去掉（默认三窗格里浏览器窗格约 350px 就是这一档）；菜单永远是完整清单，400–500 这档里导航在条上和菜单里都有。工具条上的「回放」按钮（`tabs/web/ReplayView.tsx`）把画面区换成回放播放器：按时间线翻看 agent 每个改变页面的动作之后的一张画面（会话下拉、上一步 / 播放 / 下一步、滑块、当前步的说明），开着时实时画面流断开、关掉后接回，开关随标签保存（`useTabView`）；窄窗格（≤520px）控制行分两行。`web` 标签不带 `sid`，也没有主机（`none` 档，放进任何窗格）；`tab.page` 是 Server 的页面 id | 工作区（设计见 [`browser.md`](browser.md)） |
| `canvas` | 主机 + `path`（目录，画布在它的 `.canvas/` 下）+ `canvas`（打开的画布名）；`data` 档：`host` 只是画布目录所在地，不参与窗格隔离（可放进任何窗格，不改窗格的主机），文件监听借锚点会话。组件库按需加载。设计与界面见 [`canvas.md`](canvas.md) §8 | 工作区 |

**各标签内容区的版式**（通则在 skill `ys-ui-design` 的 visual-language §6）：文件与预览见 [`files.md`](files.md) §5；**终端**平时没有任何条，屏幕占满窗格，连接中 / 重连时顶上浮一行提示（不占位），已结束 / 断开 / 打不开是下方的一张说明卡（带重试 / 重新打开 / 终端管理）；**浏览器**工具条永远一行（36 高）：观察态 = 「页面 N」入口（点开悬浮列表：「我的」置顶、其后按最后使用的会话分组、底部打开地址）+ 只读地址与标题 + 控制台开关 + 「手动操作」；手动态 = 同一行换成后退 / 前进 / 刷新 + 可编辑地址 + 控制台 + 「交还 agent」（你自己开的页面是「交给 agent」）；agent 请求接管时工具条上方多一行横幅（「我已操作完成」「拒绝」，与聊天里的提问卡片先到先得）；画面区 16:10 居中，手动态画面外圈描一道强调色线，控制台是画面下方的抽屉（默认收起）；**执行体**头一行：状态点、名称（悬停卡片：角色、模型、工具数、上下文）、角色标记、状态与已运行时长、上下文读条（窗格 ≤400 藏读条），输入栏与主对话同形。**标签悬停提示**写「类型 · 完整信息」：`TabDef.tip` 给目录或路径（终端、文件、预览），没有就用标题。

- 每个标签的视图状态 `afx`（右栏宽度、审计分栏与筛选、工作流浮层等，白名单字段）跟标签一起存（`persist.parseAfx`）。标签类型的事实在一张表里：`model/tabKinds.ts` 的 `TAB_KINDS`，一行 = 类型名、主机档位（`host`：`none` / `data` / `pane`，见 §2）、能否带会话 id（`sid`，会话没了标签随之关闭）、`+` 菜单能否新建（`creatable`；对话、执行体、后台任务与预览为 `false`——建出来的空标签之后没有任何路径会往里填内容：单击会话只换临时对话标签，单击文件只换同主机的临时预览，所以对话从会话行进、预览从文件点进、执行体与后台任务从右栏进）；`TabType`、`isHostTab`、`hasHost`、持久化解析、`CREATABLE_TABS` 都从它派生。**新增一种标签类型**：在这张表加一行；所在 feature 用 `registerTab(type, {icon, title, tip?, render})`（`tabs/registry.tsx`）接上图标、标题与渲染，并在 `registry.tsx` 的占位图标表里补一个图标；类型专属的字段在 `l2.newTab` 与 `persist.parseTab` 各加一处。组件库自带色值的类型（如画布的 `@xyflow/react`）要按需加载，否则构建产物的色值守卫会拦。插件界面（iframe）这类还没做的标签类型见 [`plugin.md`](plugin.md) §4。

**标签的内容缩放**（`tabs/tabZoom.tsx` + `layout/TabBody.tsx`）：对话 / 执行体 / 后台任务 / 预览 / 终端标签里 Ctrl+滚轮放大缩小内容（`TAB_KINDS[t].zoom`；外壳字、图标与间距不动，和界面字号设置同一个思路），70%–200%、每格 10%。**四种乘法**：①文字——对话正文、代码、预览的文字：`ui/type.css` 的内容族字号乘上标签上的 `--tab-zoom`；②预览里的**图片与 SVG**——显示宽度的基准（图片 = 窗格宽与原尺寸里较小的，不放大小图；SVG = 窗格宽、高度按比例）乘 `--tab-zoom`，放大后溢出的部分可滚动（用 auto 边距居中，别用 `place-items: center`，它会把左边裁掉），样式里要写 `max-width: none`（全局的 `img { max-width: 100% }` 会把放大的图封回窗格宽度，用 CSS `zoom` 也无效）；③**HTML 内嵌预览**——iframe 用 CSS `zoom: var(--tab-zoom)`，盒子仍是 100% 铺满（百分比尺寸不受 zoom 影响，别写成 `calc(100% / 比例)`），页面视口按比例变窄；鼠标在页面里面时的 Ctrl+滚轮是页面自己的，不触发标签缩放；④**终端**——xterm 画在 canvas 上不认 CSS 变量，`TerminalTab` 读 `useTabZoomScale()`（`TabBody` 用 context 提供当前比例），把代码档字号乘上比例（取到半像素）再 fit。非 100% 时窗格右上角有比例角标，点一下回 100%；每个标签各存各的（浏览器本地，键 `tab.zoom`，关标签随视图状态一起清）。画布、浏览器、文件管理器不接：它们要么自己管缩放（画布 xyflow、PDF / 富文档预览的 `useWheelZoom`），要么没有可缩放的内容。真机验收见 `scripts/verify-tab-zoom.mjs`（图片 / SVG / 终端）、`verify-html-preview.mjs`（HTML iframe）与 `verify-chat.mjs`（正文字号）。

**标签的状态放哪**：窗格只渲染当前标签，`PaneView` 里按 `active.id` 做 key，**切走组件就卸载、切回来是新实例**，所以只在 `useState` 里的界面状态一定会丢。能保留的有四条路，**该存的地方和键都不同**（不做服务端持有）：①**标签身份**（指着哪：路径、目录、当前画布等）写进标签记录（`patchTab`，字段 `path / cwd / url / termId / termEnded / temp`，画布还有 `canvas`），随布局存服务端、各设备共享、刷新也在；②**轻量视图状态**写进 `afx`（`patchAfx`，白名单字段，`persist.parseAfx` 逐项校验；画布的浏览历史 `cv`、右栏宽度、审计筛选等）；③**放组件外的 store**（画布的 `useCanvasStore`，**按标签 id 各一份**，不能按「主机 + 目录」共用，否则同目录的两个标签互相带着换），没有标签在用且没有未保存改动时才丢；④**设备相关的视图状态存浏览器本地**：`tabs/tabView.ts` + `useTabView`（键 `ys.tab.view:<工作区 id>:<标签 id>`，值带 `savedAt`，防抖写）。它设备相关、丢了无害，所以不进布局：滚动一动就写布局，还会和别的设备抢版本号。标签组件挂载时读一次、之后每次变化存一次，记录里带「属于哪个文件 / 目录」，对不上不恢复。已接入：文件管理器（版本视图、显示隐藏文件、多选、列表滚动位置，选中与滚动按目录对得上才恢复；`files/viewState.ts`）、预览（预览 / 编辑模式、编辑器光标与滚动位置；`preview/viewState.ts`）、浏览器（控制台与回放开关）。**标签 id 会复用**（`idGenFrom` 每个工作区各自从 1 数、只避开当前还在的 id，关掉的标签 id 会被新标签拿走），所以视图状态的键必须带工作区 id、关标签时删：`LayoutProvider` 里 `watchLiveTabs` 订阅布局，载入完成、或有标签 id 从文档里消失时，扫掉这个工作区里不在文档里的记录（关标签、关窗格、关窗口、别处同步来的新布局都走这一处）；启动时 `sweepStaleTabViews` 清掉 30 天没动的与坏记录。没接入的：终端靠 `termId` 重连；对话流与对比页的滚动位置没做。新标签类型要保留什么状态，先决定它属于哪一类。

**浏览器本地存储的统一方法与草稿**：浏览器本地的状态一律走 `app/localState.ts`：值一律 JSON，键统一 `ys.<命名空间>[:<分段>…]`（`localKey` / `localPrefix`，分段 URI 编码所以按前缀清理不串）；`readLocal(key, parse)`（校验不过当没有）、`writeLocal`（超过容量上限或写失败就**删掉旧值**，免得恢复出过期内容）、`writeLocalSoon`（防抖，读同一键 / 页面隐藏 / 关闭时先落下）、`removeLocal`、`sweepLocal(prefix, drop)`（按前缀清理）；单条默认上限 100 万字符。走这套方法的有：输入框草稿 `ys.chat.draft:<sid>`、文件草稿 `ys.file.draft:<主机>:<路径>`、画布暂存 `ys.canvas.unsaved:…`、树栏偏好 `ys.canvas.tree` 与浏览状态 `ys.canvas.treeview:…`、技能 / MCP 检查更新时间 `ys.tools.updateCheckedAt:<kind>`；字号与当前工作区（带 sessionStorage 的特殊语义）、令牌不走它。**未保存草稿**（文件编辑文本；输入框与画布暂存同理）的键 = 被编辑的东西（文件 = 主机 + 路径，不按标签 id，所以标签 id 复用不影响草稿），连同「开始编辑时的磁盘基线」（mtime + sha256）一起存：恢复后磁盘变过，保存时走现有的冲突合并，不另做机制。**关掉带未保存修改的标签**不拦截、不弹确认：留着草稿，下次打开这个文件时恢复并提示「已恢复上次没保存的改动」；草稿太大（约 1MB 以上）不暂存，超过 30 天的启动时扫掉。**敏感路径**（`.env*`、私钥、`.ssh` 下）的草稿不落本地，只做最小的短名单排除：不是安全功能，界面也不承诺。**草稿只在输入它的那个浏览器里有**，换设备看不到（与画布暂存一致）。

**预览标签的临时 / 固定**（`l2.openPreview`，与对话标签的临时 / 固定对齐）：只有**文件管理器点文件**会开临时预览，其余入口（对话里点文件链接、轮末 / 团队 / git 的对比标签、`+` 新建）都是固定的。单击（或空格）= 临时预览：同主机已有临时预览就**就地换成**新文件（位置不变、换新标签 id，预览按 id 重建）；没有就在该主机的预览窗格里新开一个（也没有预览窗格就在右侧拆出一个）。双击行 / Enter = 固定：已开着这个文件的临时预览就去掉临时标记，否则开固定标签；固定的标签留着，之后的单击另开一个临时的。已开同主机同路径的预览（不论临时或固定）只激活。每台主机每个窗口至多一个临时预览。临时标签标题斜体；**双击标签固定**；**在里面开始编辑（出现未保存改动）自动固定**，免得下一次单击顶掉用户的改动。`temp` 随标签存进布局文档（`persist` 对 chat 与 preview 保留）。

**对话标签的三种状态与左轨的关系**（`model/layoutOps.ts`）：

- 固定（有 `sid`）：常驻，标签条里正常字体；临时（`sid` + `temp`）：斜体，单击左轨里别的会话时就地换成那个会话；空（无 `sid`）：显示空状态与「新对话」。
- 单击会话 = `showSession`：已在窗口里显示就激活；否则换掉临时标签；都没有就新增一个临时标签。双击 = `pinSession`（去掉临时标记）。把会话行拖进窗格 = `placeSession`：落在边缘新开窗格、落在中部或标签条并入；已显示的会话是移动并固定；只接受**当前工作区**的会话（别的工作区的拖拽窗格不接受，否则下次载入会被当作失效标签关掉）。
- 「我在看」= 当前窗口各窗格当前选中的对话标签；`viewingReport.ts` 把它上报给服务端用来清未读，页面不在前台时报空。
- 会话被删后它的 chat / sub 标签被关；归档的会话标签保留（只读）。窗口里没有任何存活会话的对话标签时，空对话标签自动绑成最近的未归档会话（临时）——只在「刚载入的第一次收敛」与「这个窗口刚关掉过失效标签」时做，免得用户自己新开的空对话标签被下一次列表推送顶掉。

## 4. 新建标签菜单

窗格头的 `+`（`tabs/NewTabMenu.tsx`）先选类型：终端、文件、浏览器、画布（`CREATABLE_TABS`，见 §3）。`pane` 档类型（终端、文件）再选主机，候选只有一台时跳过这一步；浏览器直接建，画布跟着工作区主目录。候选 = 本窗格主机（标「本窗格」）在前，其余是**当前工作区目录清单里的主机**，去重；**没有「全部主机」**。选定主机后，终端的 cwd、文件管理器的 path 取该主机上的第一个目录路径。第二步有「返回类型」（← 键同效），底部写「其他主机在右侧新建窗格 · 一个窗格只装一台主机」。

## 5. 文件拖拽

- 同主机是移动，跨主机是传输（`tabs/files/{verdict,move,transfer,retarget,dnd}.ts`）。落点优先级：目录行 > 面包屑项 > 列表空白（当前目录）。拒绝：落在文件行「文件不能作为目标」；目录移入自身或子目录「不能移入自身」；同主机且已在目标目录「已在目标目录」。
- 跨主机传输**源保留、目标新增，实际是复制**（`transfer.ts` 文件头；拖拽时 `dropEffect` 为 `copy`）。幽灵条区分「移动到 host:/dir」与「→ host:/dir」，跨主机用目标窗格的主机色。只处理被拖的那一行：多选时的 `paths` 只被「拖进对话插入引用」用（`chat/tab/useFileRefDrop.ts`，每行一条），移动与传输不带上其他选中项。
- 重名不覆盖：文件改成 `name (2)`、`name (3)`，同名目录按 `cp -r` 合并；完成 toast 附「N 项重名已改名」。传输同一时刻只允许一次（模块级 `busy`），再发起提示「前一次传输还没结束」，不排队；进度卡片与上传共用，运行中有「取消」，失败卡片带原因、需手动关闭，没有重试。
- 移动后，已开的预览标签跟到新路径（`retarget.ts`）：只改同主机、路径等于或位于被移动项之下的预览标签，且只限该会话的**当前窗口**；跨主机传输不改写（源还在）。拖放动作不记入会话审计时间线；Esc 取消拖拽（`dndStore.ts`）。

## 6. 全局壳

**会话总览**：并进了命令面板——左轨页脚的「总览 N」与 mod+Shift+O 打开命令面板，并把「工作区」一类排在最前（Ctrl+K 打开则是命令在前）。不搜索时只列最近有动静的 6 个未归档工作区（看名下会话的最近更新，右侧写对话数），选中就切过去；搜索时全部工作区（按名字与目录路径匹配）和全部会话（右侧写所属工作区）都搜得到，选中会话时连工作区一起切过去（`openSession.ts`：先切工作区、等那份布局载入后再打开）。

## 7. 持久化

- 服务端 `GET / PUT /api/v1/workspaces/:id/layout`（`packages/server/src/api/workspaces.ts`）：每个工作区一份不透明 JSON，服务端只校验是对象，用 `baseRevision` 做乐观锁（冲突返回 409 与当前版本），请求体上限 256KB。文档是 `LayoutDoc = {version: 4, windows}`（`model/layoutDoc.ts`），`windows` 即 `WindowState`（含 `afx`、`temp`、终端 id）。**不是** localStorage。
- 「当前看哪个工作区」存浏览器本地（`library/currentWorkspace.ts`）：本页签的值放 sessionStorage，另写一份 localStorage 当「上次用的」，新页签先继承它，多个浏览器窗口互不覆盖。
- 客户端与冲突（`store/layoutStore.ts`）：变更后去抖 800ms 保存；`pagehide` 与页面转入后台时立即 keepalive 保存；超过 256KB 不保存并提示「布局超过 256KB，未保存。请关闭一些窗口或标签页」；保存失败提示一次，下次变更重试。服务端回 409（别处已更新）时，客户端直接采用服务端版本并提示「布局已在别处更新，已载入最新版本」，本地未保存的改动丢弃。切换工作区时先把当前文档存到当前工作区的 id 下、再载入新的；目录清单与会话列表都按工作区 id 打标记，只对「文档所在的那个工作区」生效（否则新工作区的会话列表会把旧文档的对话标签当作失效标签关掉，再存回旧工作区）。
- 载入（`layoutDoc.loadLayout` → `persist.parseWindowState`）：版本 <4 视为空文档重建（原型期约定）；版本比客户端新则只读（`status=blocked`）；其余经修复（id 去重、窗格超过 6 个截尾、主机隔离、焦点与 active 指向存在的对象）。空文档（含刚建的工作区）在目录清单与会话列表到齐后补默认窗口并保存。载入失败（`status=error`）没有专门界面。
- 分叉会话不克隆布局：分叉出的会话在左轨挂在父会话下，单击或双击打开。
