# ADR-0031: 自动模式的审核方：接入契约、判定输出与失败口径

状态：已定稿
日期：2026-10-18
可逆性：难逆
取代：无
被取代：——
引用入口：ARCHITECTURE「边界与约定」；ROADMAP 第 5 条

## 背景
[ADR-0006](0006-permission-tiers.md) 要求二档把规则外的动作交模型审：放行执行、拒绝回理由、拿不准/超时/出错则弹给用户。模型接入向导属于第 7 条（[ADR-0015](0015-model-management.md)），目前 Server 连会话后端都是注入的。审核的输入输出口径与会话级策略覆盖会写进用户数据（会话字段），所以难逆。

## 候选方案
### 审核方如何取得模型
- A. 现在就定模型配置格式。越界进第 7 条。
- B. 注入式：`ServerOptions.reviewerFactory`，返回一个独立的审核会话；真实模型待第 7 条接入（本期选）。未注入时二档退化为一档。

### 审核输入
- A. 完整对话。代价：不可信内容（工具输出）进入审核提示词，易被注入。
- B. 拆成“可信证据”（用户消息、项目约定、用户对弹窗的回答）与“不可信上下文”（助手与工具输出摘要，标注不可信）两段，总量设上限，超出截断并留标记（本期选）。

## 决定
接入选 B，输入选 B。

**审核会话**：每次审核新开一个独立会话（不带工具），系统消息放策略，用户消息放待审内容；用完即弃，不写入用户会话、不占 `seq`。审核提示词 = 内置通用策略 + 该会话的覆盖文本（可空）。覆盖只能让审核方在规则外动作上更严或更松，不进规则层，不能越过 [ADR-0030](0030-permission-rules.md) 的不可记住/敏感路径硬边界——敏感路径与 `sudo` 类动作**不交审核模型，始终弹给用户**。
**输出**：严格 JSON `{ "decision": "allow" | "deny" | "ask", "risk": "low" | "medium" | "high", "reason": string }`。
- `allow`：执行。`deny`：工具以 `block` 返回，`reason` 回给 agent。
- `ask`、JSON 不合法、`decision` 取值非法、审核会话报错、超过 60 秒（Server 常量）：一律弹给用户（降级为一档），绝不默认放行。
- 审核方不见密码值，输入只含工具名、参数摘要与上述证据。写类工具（`write`/`edit`）只送路径与各内容字段的长度，`content`、新旧文本不送；bash 送命令摘要。审核会话在超时后才建好时，直接销毁。

**会话级覆盖**：`sessions.review_policy TEXT`（迁移 v5，可空）；`PATCH /api/v1/sessions/:id` 增加 `reviewPolicy`（字符串，去空白后 0–4000 字符，空串清除）。全局版本即内置模板；用户对全局模板的追加待第 7 条的配置体系。
**可信证据的取法**：从该会话 JSONL 当前分支取用户消息；弹窗回答来自本会话内存中已解决弹窗的记录（选项与问题文字）；AGENTS.md 本期不读取（待第 7 条）。

## 理由
- 注入式把模型选择留给第 7 条，本期仍可端到端验证审核链路（测试用 stub 提供者）。
- 把不可信内容隔离并标注，是 Codex guardian 的做法；加上“拿不准一律弹给用户”，审核方被骗的上限是多弹一次窗，而不是放行。
- 敏感路径与 sudo 不交模型，保持硬边界不依赖模型判断。

## 影响
- 迁移 v5 给 `sessions` 加 `review_policy`。
- 审核会话的调用成本与延迟由使用者承担；60 秒超时避免卡住工具调用。
- 排除：全局策略追加；审核方使用工具补查上下文；模型配置格式。
