# ADR-0016: 开源协议：MIT

状态：已定稿
日期：2026-10-16
可逆性：难逆
取代：无
被取代：——
引用入口：VISION「约束」；ARCHITECTURE「技术选型」许可一行

## 背景
仓库从一开始即公开（ADR-0014）。没有许可证的公开代码，别人可以看但没有使用授权。
项目会移植 Codex 的部分代码（Apache-2.0，ADR-0006），并依赖 pi SDK 和其他开源库。

## 候选方案
### 方案 A：MIT
简单宽松，广泛使用。代价：没有明示的专利授权条款。
### 方案 B：Apache-2.0
有专利授权和 NOTICE 机制，与移植的 Codex 代码同协议。代价：文本更长，对使用者的要求更多。
### 方案 C：暂不加许可证
把决定推迟。代价：公开仓库没有使用授权，别人无法合法使用或贡献。

## 决定
方案 A。仓库根放 `LICENSE`（MIT），版权人 bluezeamer，年份 2026。
- 移植自 Codex 的文件仍受 Apache-2.0 约束：附 Apache-2.0 许可证副本，NOTICE 注明来源，
  标注修改过的文件（ADR-0006）。其余部分为 MIT。
- 引入的依赖其许可证须与 MIT 分发兼容，在引入依赖时核对。

## 理由
- 个人项目、希望别人少受限制地使用，MIT 最简单直接。
- Apache-2.0 的代码可以放进 MIT 项目，前提是这部分保留 Apache-2.0 的条款（一般性理解，不是法律意见）。

## 影响
- 骨架 intent 要带上 `LICENSE`，包配置里声明 `MIT`。
- 移植 Codex 代码时同步建 `NOTICE` 并保留 Apache-2.0 文本。
- 外部贡献默认按 MIT 授权，不设 CLA。
- pi SDK 的许可证这次没有核对，引入依赖时核对。
- 排除：闭源发布；要求使用者开源衍生作品的协议（如 GPL）。
