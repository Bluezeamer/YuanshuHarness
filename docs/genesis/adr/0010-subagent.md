# ADR-0010: subagent：独立会话加父子关系

状态：已定稿
日期：2026-10-16
可逆性：难逆
取代：无
被取代：——
引用入口：VISION「做什么」第 6 条；ARCHITECTURE「系统组成」与「数据流」

## 背景
pi 原生没有 subagent。调研与审计这类任务需要独立的上下文，也可能用不同的模型。
参考了 Codex、opencode、pi-subagents 三个实现：它们都以"声明式定义加由模型调用的发起工具"
为主体，子 agent 独立成会话，父只收到最终结果。pi-subagents 在进程内改写全局环境变量、
有模块级共享状态、界面强依赖 TUI，放进多会话共处一进程的持久 Server 会互相干扰，只借鉴思路。

## 候选方案
### 方案 A：进程内子任务
子循环不独立持久化，只返回结果。代价：无法介入、无法续聊、没有拓扑。
### 方案 B：独立会话加父子关系
子是用某个 agent 定义新开的普通会话。代价：要管理关系、存储和生命周期。
### 方案 C：另起 pi 进程
隔离最强。代价：事件难统一，管理复杂，与统一会话池相悖。

## 决定
方案 B。
- 子会话是普通会话，记录双向父子关系，可链式（子再派子）。关系记在 SQLite，
  子会话的 JSONL 放在专门目录（ADR-0004）。
- WebUI 展示调用拓扑图，可聚焦到任一节点对话并介入，介入消息照常排队，不打断当前步骤。
- **发起**：父 agent 调用 `spawn`，参数含 agent 定义、任务、环境子集、是否继承能力、
  是否带上父历史、可选覆盖模型、可选更严的档位。默认从空白上下文开始。
  异步返回子会话 id，可连续发起多个并行。
- **等待**：`wait` 等一个或多个子。可设超时也可不设，不设则一直等到子完成，纯队列阻塞；
  超时只是父停止等待，子继续跑。
- **中断**：`interrupt` 中断某个子。父被中断时，其子一并被中断。
- **返回**：子完成后，只把最终结果以一条排队消息发给父；父若空闲，这条消息唤醒父开始新一轮。
- **环境**：由父指定，必须是父已挂载 workspace 的子集；新增 workspace 仍只有用户可做。
- **能力**：子 agent 自己的定义，加可选继承。MCP 的继承是按同样配置自己起一份，
  所以只有子的 local-workspace 与父相同时才继承，远程不继承。
- **权限**：子不能比父更宽。子的档位取父档位与自动模式中较严的，父派发时可再收紧；
  按 workspace 存的规则父子共用。子会话没有弹窗：自动模式里拿不准的直接按拒绝处理；
  需要人工的动作（`sudo -s`、要求人工审批的密码等）一律拒绝，并要求子把缺少的权限
  写进最终结果，由父决定自己做还是换办法。所以子 agent 做不了 sudo 这类事。
  子会话不产生新的"记住"规则。拓扑图节点上标出被拒绝的次数与原因。
- Server 重启时，子与父一样被中断；重启后父收到"某子会话被中断"的提示，自行决定是否重派。
- 深度上限与并发上限先给保守默认值，实现时调整。

## 理由
- 子会话就是普通会话，存储、恢复、客户端协议全部复用，不引入新机制。
- 把分配任务、选择模型与环境的主动权交给父 agent，调研与审计的差异化模型自然落在 agent 定义上。
- 权限只收窄不放宽，与 Codex 的做法一致，也避免子会话成为绕过审批的口子。
- 双向父子关系和独立定义，为以后的图管理与编排打基础。

## 影响
- 需要：spawn、wait、interrupt 三个工具，拓扑图，父子关系存储，被拒记录。
- 默认深度和并发上限待定。
- agent teams 与 workflow 不在基建内，留到后续。
- 排除：进程内子任务；另起 pi 进程；子会话弹窗。
