# ADR-0026: 访问令牌、来源网段与启动时的暴露检查

状态：已定稿
日期：2026-10-17
可逆性：难逆
取代：无（仅接替 [ADR-0018](0018-startup-params-and-health-endpoint.md) 中"监听非回环地址只警告"一项，该项原文即声明由认证步骤重新评估）
被取代：——
引用入口：ARCHITECTURE「技术选型」；ROADMAP 第 3 条

## 背景
[ADR-0011](0011-auth-and-im-routing.md) 定了方向（受限网段加令牌，失败多次后限制），[ADR-0012](0012-delivery-form.md) 列了两类启动参数，[ADR-0018](0018-startup-params-and-health-endpoint.md) 把定名推迟到本步骤。
参数名、令牌的携带方式、启动检查一旦被脚本、容器配置和客户端引用就成了对外契约，所以难逆。
浏览器的 WebSocket 不能加自定义请求头，携带方式必须在头之外选。

## 候选方案
### 令牌来源
- A. 用户给定单个令牌。代价：要用户自己生成。
- B. 首次启动生成并存进数据目录。代价：令牌落盘，丢失后要有找回流程。

### WebSocket 升级时的携带
- A. `Sec-WebSocket-Protocol` 子协议。令牌不进 URL。代价：令牌字符集受 HTTP token 限制。
- B. 查询参数。代价：进访问日志、代理日志、浏览器历史。
- C. 连接后首条消息认证。代价：多出未认证连接状态，且要改 [ADR-0021](0021-session-wire-protocol.md) 的"首条必须是 snapshot"。

### 来源网段未配时
- A. 不限制，只校验令牌。
- B. 默认只放行回环与私网。代价：Docker 端口映射下对端是网桥网关，Tailscale 等场景容易误拒。

## 决定
令牌选 A，携带选 A，网段选 A。

**参数**（命令行 > 环境变量 > 无默认值，沿用 [ADR-0018](0018-startup-params-and-health-endpoint.md) 的解析规则）

| 含义 | 命令行 | 环境变量 |
|---|---|---|
| 访问令牌 | `--token` | `YUANSHU_TOKEN` |
| 允许的来源网段 | `--allow-cidr` | `YUANSHU_ALLOW_CIDR` |

- 令牌：单个；字符限 `A-Za-z0-9._~-`（以便放进子协议）；至少 32 个字符，不足则启动失败。Server 不生成、不落盘。
- 网段：逗号分隔的 CIDR 列表，IPv4 与 IPv6 均可；格式非法启动失败。
- 命令行上的令牌会出现在进程列表中，文档推荐用环境变量；这是已知取舍，不再增加第三种给法。

**启动检查**
- 监听地址不是回环，且未配置令牌：拒绝启动，退出码非零，信息说明需要配置 `--token` 或 `YUANSHU_TOKEN`。取代 ADR-0018 的"只警告"。
- 监听回环且未配置令牌：放行，认证不启用；启动日志注明"认证未启用"。
- 配置了令牌：无论监听地址，认证一律启用。
- 回环的判定范围（`127.0.0.0/8`、`::1`、`localhost`）留给 spec。

**认证范围与携带**
- `/api/v1` 下的 REST 与 WebSocket 升级都要求令牌；`/healthz` 与静态资源不需要（[ADR-0018](0018-startup-params-and-health-endpoint.md)）。
- REST：`Authorization: Bearer <令牌>`。
- WebSocket：客户端在 `Sec-WebSocket-Protocol` 里提供 `yuanshu.v1` 与 `bearer.<令牌>` 两个子协议；Server 校验后只选定 `yuanshu.v1` 回显，不回显令牌。校验在升级之前完成，失败返回普通 HTTP 响应，不建立 WebSocket。
- 令牌比较用常量时间。令牌不得出现在日志、错误响应、健康端点中。

**拒绝响应**（体沿用 `{ "error": "<代码>" }`）
- 来源不在允许网段：403 `forbidden_source`。
- 缺令牌或令牌错：401 `unauthorized`，带 `WWW-Authenticate: Bearer`。
- 被限流：429 `too_many_attempts`，带 `Retry-After`。
- 网段检查先于令牌检查，网段外的请求不会得到"令牌对不对"的信息。

**来源判定与限流**
- 来源取 TCP 对端地址，不信任 `X-Forwarded-For` 等任何转发头；反向代理后的真实来源识别不在本期。
- 同一来源连续令牌错误达到上限后，在一段时间内拒绝其所有 `/api/v1` 请求。次数、窗口、状态存放与清理细节留给 spec；状态只在内存，重启清零。

## 理由
- 用户给定令牌不引入新的落盘秘密，也不需要找回流程；单用户场景下一个令牌够用。
- 子协议不进 URL，浏览器与 Node 的 WebSocket 都能用，也不改 ADR-0021 的连接后语义。
- 非回环无令牌拒绝启动，避免"认证已落地却仍裸奔"的静默错误，与 ADR-0018 选择"未知参数就失败"是同一思路。
- 网段默认不限制，因为容器与组网场景下对端地址不可预期；需要时由用户显式收紧。
- 先查网段再查令牌，减少对外泄露的信息。

## 影响
- 容器镜像已设 `YUANSHU_HOST=0.0.0.0`，今后运行容器必须同时提供 `YUANSHU_TOKEN`，否则启动失败；文档与镜像说明要同步。
- 既有测试客户端与集成测试要改为带令牌；需要一组不带令牌的回环用例确认放行路径。
- 未知参数检查（含 `YUANSHU_` 前缀环境变量）要把两个新名字加入已知集合；旧版本遇到新参数会失败，升级路径文档要提示。
- 令牌无轮换与吊销机制：换令牌就是改配置后重启。
- 无 TLS：令牌在受信网络内明文传输，依赖 [ADR-0011](0011-auth-and-im-routing.md) 的部署前提。
- 排除：服务端生成令牌；URL 携带令牌；信任转发头；多令牌与角色；账号口令。
