# ADR-0024: 会话管理与历史拉取的 REST 契约

状态：已定稿
日期：2026-10-17
可逆性：难逆
取代：无
被取代：——
引用入口：ARCHITECTURE「技术选型」会话线上协议一行；ROADMAP 第 3 条

## 背景
[ADR-0021](0021-session-wire-protocol.md) 的端点只增不改，并把窗口之外的历史拉取推迟到持久化。事件与快照里被截断的内容（spec R16）也需要取全文的途径。
这些端点是所有客户端依赖的对外契约，所以难逆。会话管理的最小单位是整条会话；会话内部的状态调整（回退、fork 等）不在本契约内。

## 决定
均在 `/api/v1` 内，只增不改既有字段（[ADR-0021](0021-session-wire-protocol.md)）。

- `PATCH /api/v1/sessions/:id`，请求体 `{ "name": "<字符串>" }`，返回更新后的会话条目。名称非空、长度有上限（具体值留给 spec）。
- `DELETE /api/v1/sessions/:id`，成功返回 204，同时删除 JSONL 与索引行。会话正在运行时拒绝，返回 409，不隐式停止。
- `GET /api/v1/sessions/:id/messages?before=<游标>&limit=<n>`，向更早的方向分页。游标是不透明字符串；默认 50 条，上限 200 条；返回 `{ messages: [...], nextBefore: <游标或 null> }`。消息给出完整文本，不做事件流里的截断。
- `GET /api/v1/sessions/:id/messages/:index` 取单条消息全文，`index` 是该会话内的消息序位，用于被截断内容的按需拉取。
- 会话条目增加 `name`、`updatedAt`；列表按 `updatedAt` 倒序。
- 不存在的会话返回 404；错误体沿用 `{ "error": "<代码>" }`。

## 理由
- 分页加游标避免偏移量在新消息到达时错位。
- 单条全文与分页历史分开，让客户端可以只为被截断的那一条付出代价。
- 运行中拒绝删除比隐式停止更可预期，客户端可显式先 `stop` 再删。

## 影响
- 分页接口读取 JSONL，不经会话池；会话未加载时也能读（按需加载，[ADR-0023](0023-data-dir-layout-and-versioning.md)）。
- 全文接口返回的消息大小没有截断上限，受 SDK 与模型输出大小约束。
- 工具结果等非文本内容的返回形状留给 spec。
- 排除：偏移量分页；删除时隐式停止运行。
