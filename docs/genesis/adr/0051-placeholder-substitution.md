# ADR-0051: 占位符替换：环境变量传值，命令文本里没有值

状态：实施中  
日期：2026-10-20  
可逆性：中  
取代：无  
被取代：——  
引用入口：[ADR-0007](0007-private-variables.md)；[ADR-0034](0034-env-tool-routing.md)；[ADR-0050](0050-private-variables-impl.md)

## 背景
agent 在命令里写 `@var_name`。审批与会话记录看到的是带占位符的原文；真值只在 bash 工具启动进程前才进场，且不能出现在进程命令行（`ps` 可见）、不能留在会话环境。本机与 ssh 两条路径都要成立。

## 决定

### 识别边界
正则 `(?<![\w@.\\$/-])@name(?![\w/]|[.-][A-Za-z0-9])`，名字取最长匹配，再按已登记名字精确查表：
- 前面是单词字符、`@ . \ $ / -` 的不算：邮箱 `me@x.com`、`git@host`、转义 `\@tok`、`$@tok`。
- 后面接 `/` 或 `.x`、`-x` 的不算：`@scope/pkg`、`@a.example.com`、`@tok-extra`。
- 未登记的 `@xxx` 原样不动，不报错。
- `=`、引号、`(`、`:`、空白之后都算，`https://oauth2:@tok@host` 可用。
- 注释里的占位符不替换。

### 改写：值不进命令文本
命令里的 `@name` 改写成对环境变量 `YUANSHU_VAR_<name>` 的引用，值经进程环境传入。按 tree-sitter-bash 判断所处引号环境：

| 环境 | 改写为 |
|---|---|
| 无引号 | `"${YUANSHU_VAR_name}"` |
| 双引号内 | `${YUANSHU_VAR_name}` |
| 单引号内 | `'"${YUANSHU_VAR_name}"'`（临时跳出） |
| heredoc 内 | `${YUANSHU_VAR_name}` |
| `$(...)` 内 | 重新按外层规则判断 |

值从不拼进命令文本，所以值里的引号、`$`、反引号、换行既不能注入命令，也不会破坏命令；引号环境判断错最多是分词或通配展开，不是注入。已知局限：带引号分隔符的 heredoc（`<<'EOF'`）内不展开，得到字面 `${...}`。

### 本机
SDK 的 `spawnHook` 只对这一次调用给进程环境追加 `YUANSHU_VAR_*`。每次调用新建工具定义，不改会话环境，后续命令看不到。`/proc/<pid>/cmdline` 里只有 `${YUANSHU_VAR_name}`；`environ` 权限 0400，仅同用户与 root 可读，与 Server 进程自身同一边界。

### ssh
ssh2 的 `exec(command)` 会让远端 shell 的 `-c` 参数在 `ps` 里可见，所以带变量时不把内容放命令行：
- 远端命令行固定为 `eval "$(cat)"`；
- 标准输入写入 `export YUANSHU_VAR_x='…'`（POSIX 单引号转义）+ `cd … && { 命令 }`，随即关闭输入。
- 无变量时保持原来的整串命令行路径，行为不变。
- SDK 传来的整个本机 env 仍不转发，只转发 `YUANSHU_VAR_*`。

副作用：带变量的命令标准输入是 EOF 而不是挂起。

### 验证
测试在命令里扫描所有进程的 `/proc/*/cmdline`（本机与真实 sshd 各一份），输出里除命令自己打印的那一行外不含真值；后续不带占位符的调用里 `YUANSHU_VAR_*` 为空。

## 已知局限
- 命令自己回显变量（`echo`、`env`、`printenv`）会进输出，由输出遮罩处理（ADR-0053）。
- 输出过长时 SDK 把全文落在 Server 本机临时文件；bash 输出在进入 SDK 前已遮罩，所以该文件里也没有真值。
