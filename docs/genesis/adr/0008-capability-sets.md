# ADR-0008: 能力集：Server 集中管理 skill 与 MCP

状态：已定稿
日期：2026-10-16
可逆性：难逆
取代：无
被取代：——
引用入口：VISION「痛点」第 1 条、「做什么」第 5 条；ARCHITECTURE「系统组成」与「边界与约定」

## 背景
现状的痛点：skill 与 MCP 跟着环境走，每个环境各配一遍，换环境重配，
工具更新后还要逐台同步。现有的管理工具只能解决单个环境内的统一，
解决不了多主机之间的管理与更新。
MCP 在行为上是个黑盒：是否并行、是否有状态，实现各异。

## 候选方案
### 方案 A：能力跟着环境走
各环境各自配置，Server 不管。代价：就是现在的痛点。
### 方案 B：Server 集中管理，按需分发到环境
能力库在 Server，分配给 agent 与 workspace，挂载时同步到环境。
代价：Server 要管理同步，并处理环境里已有内容的识别。

MCP 的运行位置另有候选：
### 全部在 Server 侧运行
代价：文件类 MCP 看到的是 Server 的文件系统，与项目所在环境不一致。
### 每个环境各起一份
代价：要在每个环境里有运行时，密钥要交给远程。
### 全局的在 Server 侧、非全局的在 local-workspace 所在环境
代价：agent 在远程环境时，文件类 MCP 仍操作 local-workspace，需要明确告知。

## 决定
方案 B。
- **能力是有名字、可勾选的单元**，类型为工具、skill、MCP 服务，带元数据：
  名称、类型、作用域（agent 级或 workspace 级）、是否只读。
  预设就是 agent，不另设"预设"概念；agent 即提示词、能力清单与模型的组合。
- **分配只有两处**：建 agent 时勾选；建 workspace 时为 workspace 勾选项目级的能力。
  **只有 skill 与 MCP 可以在 workspace 级分配**，因为只有它们可以做项目级定义；
  工具不参与。
- 能力库归 Server，不属于任何环境。Server 启动时检测并纳入各环境里已有的 skill、MCP、AGENTS.md，
  此后的管理、更新、分发由 Server 负责。底层管理优先复用现成方案（如 npx skills），不自造。
- **skill**：
  - 分全局与项目两级。workspace 挂载（或首次激活）时，把分配给该 agent 与该 workspace 的 skill
    同步到环境里对应的现成约定目录（以 pi 实际扫描的为准，S0 核对）；对比文件哈希，库更新则覆盖。
  - 环境里原本就有的项目 skill 只识别，不复制。同步到项目目录的内容是否进 git，
    由各项目自己的 `.gitignore` 决定，Server 不处理；团队想保持一致的项目 skill 可以提交。
  - skill 的依赖由环境自备。
  - 切到某个环境时，状态通知中带上该环境新增 skill 的名称、精简描述、目录，并标注环境，
    由 agent 自己决定是否去读。
- **MCP**：
  - 分两类。**全局 MCP** 只放 SaaS 类，由 Server 侧连接，所有会话共用，与环境无关。
    **非全局 MCP**（项目级或个人级）只在 local-workspace 所在的环境里运行，每个会话独立一个实例，
    不随 `switch_workspace` 改变。
  - 不提供复制 MCP 的能力。远程 workspace 自带的项目级 MCP 一律不加载。
  - 每个 MCP 工具的描述里用一句话声明作用域：非全局的写"仅运行在 local-workspace"，
    全局的写"全局服务，与环境无关"。agent 在远程环境中调用文件类 MCP 时，
    操作的是 local-workspace，这是预期内的行为。
- **会话中途的能力增减**（skill、MCP、工具，如模式限制、挂载变化）统一走 ADR-0009 的注入机制：
  有原生延迟加载就用，否则在末尾附加说明，并通过预先注册的冻结入口访问。
  MCP 工具须在描述中声明作用域，使 agent 能感知。MCP 实例失效仍走工具调用报错。

## 理由
- 把"有哪些能力、分给谁"从环境里抽出来，换环境不用重配，更新一处即可。
- MCP 是黑盒，不假设它能并行或无状态，所以非全局的每会话独立，全局的只放 SaaS 类。
- 作用域用一句话讲清，让 agent 对能力的作用范围有感知，而不是靠环境隐式决定。

## 影响
- 需要：能力库、能力元数据、同步器（含哈希对比）、环境内已有能力的识别。
- 非全局 MCP 需要 local-workspace 所在环境自备运行时，启动失败要报给用户与 agent。
- 模式限制某些 skill 与 MCP 工具时，属于会话中途的变化，由 ADR-0009 的模式通知承载；
  工具与 MCP 在执行层可彻底拦截，skill 只能做到提示加拦截读取。
- MCP 工具调用走哪一档审批，待定；MCP 所需密钥的注入方式，待定。
- 排除：能力跟着环境走；Server 侧统一运行所有 MCP；agent 间复制 MCP。
