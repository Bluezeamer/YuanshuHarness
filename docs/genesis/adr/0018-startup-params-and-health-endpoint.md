# ADR-0018: 启动参数与健康端点的契约

状态：已定稿
日期：2026-10-17
可逆性：难逆
取代：无
被取代：——
引用入口：ARCHITECTURE「技术选型」启动参数与健康端点一行；ROADMAP 第 1 条

## 背景
[ADR-0012](0012-delivery-form.md) 规定启动参数只有数据目录、监听地址、访问令牌、允许的来源网段四类，
可用命令行或环境变量给出，但没有定参数名、默认值和优先级，也没有定健康端点。
部署骨架（ROADMAP 第 1 条）要做出可启动、可探测的空壳 Server，这些名字一旦被用户的脚本、
Docker 配置和探针引用，就成了对外契约，改名要连带所有使用方，所以难逆。

约束：
- 认证到 ROADMAP 第 3 条才落地（[ADR-0011](0011-auth-and-im-routing.md)）。在此之前，访问令牌与来源网段没有任何东西可保护。
- 容器里必须能监听 `0.0.0.0`；宿主机上的默认值应当是最保守的。
- 只服务一个人，不面向公网（[ADR-0011](0011-auth-and-im-routing.md)）。

## 候选方案
### 方案 A：第 1 条就接受 ADR-0012 的全部四类参数
令牌与网段参数提前出现，但认证未落地，参数被接受却不生效。
代价：使用者设置了令牌会以为已受保护，实际没有，属于静默错误。
### 方案 B：第 1 条只接受监听地址（拆成 host 与 port）与数据目录，令牌与网段随认证一起加
代价：ADR-0012 的"四类"要分两步到位；第 1 条的参数集比目标形态小。
启动时遇到未知参数就失败，所以使用者传入尚未支持的 `--token` 会立刻看到错误，而不是被忽略。

数据目录默认位置的备选：
- `~/.yuanshu`：整个目录一起备份，符合 ADR-0012 的"复制这个目录即备份"。
- XDG 的 `~/.local/share/yuanshu`：符合 Linux 惯例，但配置、数据、缓存会被拆到不同目录，与 ADR-0012 的单一数据目录冲突。
- 相对当前目录：换个目录启动会悄悄用到另一份数据，不采用。

健康端点路径的备选：`/healthz`、`/health`、`/api/health`。

## 决定
方案 B。

**参数**（命令行 > 环境变量 > 默认值）：

| 含义 | 命令行 | 环境变量 | 默认值 |
|---|---|---|---|
| 监听地址 | `--host` | `YUANSHU_HOST` | `127.0.0.1` |
| 监听端口 | `--port` | `YUANSHU_PORT` | `7420` |
| 数据目录 | `--data-dir` | `YUANSHU_DATA_DIR` | `~/.yuanshu` |

- 未知的命令行参数、非法的端口值，启动失败并以非零状态退出，不静默回退到默认值。
- 数据目录不存在时创建，权限 0700；已存在但不可写时启动失败。
- 默认端口 7420 是任意选定的，只避开了常见的开发服务器端口（3000、5173、8080、8787 等），未核对其是否被其他知名软件占用。
- Docker 镜像里设 `YUANSHU_HOST=0.0.0.0`、`YUANSHU_DATA_DIR=/data`，端口保持 7420。数据目录挂卷的具体写法属于镜像形态，在后续决定。
- ADR-0012 的"监听地址"在这里拆成 host 与 port 两个参数，仍属于它列出的参数范围。
- 令牌与来源网段两个参数不在本 ADR 内，随 ROADMAP 第 3 条的认证一起加，届时在认证的 ADR 里定名。

**监听非回环地址**：启动时打一条警告，说明认证尚未生效；不拒绝启动。
当前除健康端点外没有任何功能，暴露面等于零，容器里也必须能监听 `0.0.0.0`。
认证落地后这一行为要重新评估，由第 3 条决定。

**健康端点**：`GET /healthz`，返回 200 与 `{"status":"ok","version":"<版本号>"}`。
- 无需认证。响应只含状态与版本，不暴露路径、配置、数据目录位置或会话信息。
- 路径放在 `/api` 之外：认证以后大概率统一加在 API 路径上，探针放外面就不必为它单开豁免。
- 探针只应依赖 HTTP 状态码；响应体字段只增不减。

**数据目录的结构版本号**不在本变更内：现在没有任何持久化数据，设计出来的版本格式无法被验证，
随 ROADMAP 第 3 条第一份持久化数据一起定。这是对 ADR-0012「影响」一节的推迟，不是取消。

## 理由
- 方案 A 制造"接受却不生效"的静默错误，方案 B 用"未知参数就失败"让缺失的能力立刻可见。
- 默认监听回环地址是最保守的值，需要对外时用户显式改，容器里由镜像显式改。
- 非回环地址只警告不拒绝：拒绝会让容器里的标准用法无法启动，而此刻没有东西可暴露。
- `~/.yuanshu` 让备份和迁移保持"复制一个目录"；固定的默认位置也避免了相对路径带来的错数据目录。
- `/healthz` 是容器与编排工具里的通用写法，放在 `/api` 之外让探针与认证解耦。

## 影响
- spec 要明确：未知的 `YUANSHU_` 前缀环境变量是否同样报错（拼错环境变量与拼错命令行参数是同一类静默错误）；回环地址的判定范围；`HEAD /healthz` 是否支持。
- 版本号对未认证者可见，这是接受的取舍：服务不面向公网、预期运行在受限网段内（[ADR-0011](0011-auth-and-im-routing.md)）。
- 第 3 条加认证参数时，要处理"旧版本不认识新参数就失败"这一点对升级路径的影响，并重新评估非回环监听的行为。
- 参数名、环境变量名、默认端口与默认数据目录一旦被使用方引用，更改就是破坏性变更。
- 排除：本变更内的令牌与网段参数；XDG 目录布局；相对路径的数据目录默认值。
