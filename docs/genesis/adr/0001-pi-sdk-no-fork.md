# ADR-0001: 以 pi SDK 为内核，不 fork

状态：已定稿
日期：2026-10-16
可逆性：难逆
取代：无
被取代：——
引用入口：VISION「不做什么」第 1 条；ARCHITECTURE「技术选型」内核一行

## 背景
需要一个会话、工具、压缩、模型适配齐全的 agent 内核，在其外层做常驻 Server。

pi 的 coding-agent 在 1.2.0 移除了 pi-server/client/protocol，官方不再提供服务化外壳；
SDK 本身无事件序号与回放、界面交互只有单槽位、会话 JSONL 追加写无锁、没有 resume API。

pi 的 extension hook 系统提供从 prompt 构造、tool 执行到 turn 延续/终止的全链路介入点，
可在很大程度上影响和扩展 agent 的运行行为，包括控制循环是否继续。
但核心 loop 的控制流由 pi 自身拥有，extension 通过 hook 与之交互，而非替换它。

## 候选方案
### 方案 A：fork pi
可以改内核去补上述缺口。代价：永久背负合并上游的成本，pi 迭代快，分叉会越拉越远。
### 方案 B：依赖 SDK，精确锁版本，经 hook 介入，其余缺口在外层补
内核升级可跟进；行为经 hook 影响，服务化缺口由 Server 层承担。
代价：受制于 SDK 与 hook 暴露的接口，上游破坏性变更时要适配。
### 方案 C：采用已有的 pi 衍生物（如 omp 一类）
能力更多。代价：追随另一个分叉的节奏，本项目的差异化点（原生远程、权限、能力集）仍要自己做。

## 决定
方案 B。`@earendil-works/*` 精确锁定版本，升级须先过契约测试。

**兼容性边界**：只依赖 SDK 的公开接口，不追求与 pi 命令行、第三方 pi 扩展生态的兼容，
也不以特性可单独发布为 pi 扩展为目标。hook 属于 SDK，可以使用，但作为 Server 内部代码。
Server 不读取机器上已有的 pi 配置目录，所有状态都在自己的数据目录里（ADR-0012）。

## 理由
服务化外壳本来就是本项目要做的价值部分；序号、单写入者、界面分发等缺口都可以在外层补，
行为上的定制可以经 hook 完成，不需要改内核。fork 的长期成本高于适配成本。

## 影响
- 需要一组契约测试固化对 SDK 与 hook 行为的假设，升级版本时必须通过（路线 S0）。
- 核心循环的控制流不可替换，只能经 hook 介入；凡需要超出 hook 能力的内核配合，先在 S0 验证能否做到。
- 本机已有的 pi 模型、扩展配置不会自动带入，需要在 Server 里重新配置。
- 排除：自研 agent 循环、跟随任何分叉、兼容 pi 命令行与第三方 pi 扩展。
