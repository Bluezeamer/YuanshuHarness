# ADR-0012: 交付形态：npm 包与 Docker 镜像，单一数据目录

状态：已定稿
日期：2026-10-16
可逆性：难逆
取代：无
被取代：——
引用入口：ARCHITECTURE「技术选型」交付一行；ROADMAP 第 1 条与末条；VISION「约束」

## 背景
部署位置不固定：可能在宿主机上，也可能在容器里。只有一个用户，一个部署，没有预发环境。
项目开源，需要别人也能方便地安装。

## 候选方案
### 方案 A：只发 npm 包
宿主机上一条命令。代价：容器部署要自己写镜像。
### 方案 B：只发 Docker 镜像
环境一致。代价：宿主机直接部署不方便，且 Server 需要访问宿主文件时要挂载。
### 方案 C：npm 包加 Docker 镜像
两种部署位置都覆盖。代价：多维护一种发布物，用同一份构建产出可控制成本。

## 决定
方案 C。
- **交付物**：一个 Node 服务，一条命令启动；WebUI 打包进 Server，一个进程一个端口。
- **数据**：所有状态（SQLite、会话 JSONL、规则、密码库、配置）放进一个数据目录，
  备份或迁移就是复制这个目录；Docker 里把它挂成卷。
- **启动参数**：只有数据目录、监听地址、访问令牌、允许的来源网段，
  可以用命令行或环境变量。
- **升级**：换包或换镜像，Server 启动时检查并自动迁移数据目录里的结构版本。
- **发布**：开发期只在本地构建；首次发布时推送到 npm 与镜像仓库，以打 tag 触发发布物构建。
- **不做 CD**：Server 部署在用户自己的机器上，升级由用户手动完成。
  环境数量只有一个，没有独立预发环境。

## 理由
- 部署位置不定，两种发布物覆盖两类位置。
- 单一数据目录让备份、迁移、容器挂卷都简单。
- 单用户、单部署，自动部署流水线的收益不抵维护成本。

## 影响
- ROADMAP 第 1 条是"部署骨架"：空壳 Server，健康端点可探测，两种发布物可构建。
- 数据目录需要带结构版本号，并提供迁移机制。
- 首次发布排在 ROADMAP 末尾，作为条件式条目："用户确认有可用版本后"。
- Server 本身以 Linux 为目标（宿主机、容器或 WSL）。Windows 原生运行 Server 不在本期承诺范围；
  Windows 机器作为被操作的环境是必须支持的，见 ADR-0002。macOS 作为 Server 主机未专门验证。
- 排除：自动部署；多环境流水线。
