# ADR-0006: 权限：三档、规则共用、模型审批

状态：已定稿
日期：2026-10-16
可逆性：难逆
取代：无
被取代：——
引用入口：ARCHITECTURE「边界与约定」；VISION「做什么」第 3 条、「不做什么」第 4 条

## 背景
容器只是保底的隔离；在具体工作环境里仍需权限机制，防止 agent 把自己的环境弄坏。
纯规则穷举判断命令危险，效果有限；逐个审批会造成决策疲劳。
Codex 有成熟的做法（Apache-2.0）：规则引擎加模型自动审核。
调研所见：Codex 当前版本靠 OS 沙箱兜底，规则外且不危险的命令直接放行，
我们没有沙箱，不能照搬；其旧版的只读命令白名单更贴合我们。

## 候选方案
### 方案 A：纯规则
命中放行或拦截。代价：规则外的动作要么全放要么全拒，无法覆盖。
### 方案 B：三档（规则审批 / 自动模式 / 完全允许），规则为共用底层
一二档的差别只在规则没覆盖到的动作谁来拍板：一档是人，二档是模型。
### 方案 C：每个动作都问人
最安全。代价：决策疲劳，长任务不可用。

## 决定
方案 B。
- **档位挂在 workspace 上**，随当前生效的 workspace 动态切换；agent 同一时刻只在一个环境，
  "在 cwd 内还是 cwd 外"有明确判断基准。
- **一档（规则审批）**：规则外的动作弹给用户，选项为接受、拒绝、通过并记住；
  记住的规则按 workspace 存。
- **二档（自动模式）**：规则外的动作交模型审。放行则执行；拒绝则把理由回给 agent；
  拿不准、超时、出错则弹给用户，绝不默认放行。
- **审核规则可定制**：自动模式的审核提示词有一份**全局的通用版本**，另可做**会话级覆盖**，
  按任务性质让审核模型放行或拒绝不同的命令（纯语义判断，例如某个会话只允许只读类命令）。
  覆盖只作用于"规则外"的动作，不改规则层；只有用户可以设置，agent 不能；
  不能越过硬边界（ADR-0007 中始终人工审批的动作）。
- **三档（完全允许）**：不再问文件与命令，围栏全交给环境。
- 审批超时按拒绝处理，理由回给 agent；超时时长待定。
- **出厂规则**：
  - cwd 内读写放行、cwd 外弹审批。
  - 敏感路径（.env、.ssh、.aws、.kube、.npmrc、id_rsa、*.pem 等，清单可扩展）
    即使在 cwd 内也不吃放行规则，按规则外处理，读和写都是。
  - 一小批只读 bash 命令出厂放行，以 Codex 旧版白名单为蓝本。
    含变量展开、命令替换、管道进 shell 的命令不吃放行规则；
    bash、sh 等解释器前缀不允许被"记住"。
- **跨 workspace 传输**视为"读源加写目的"，两边各按自己的规则判，都安全才算安全；
  否则交审批，档位取两边中较严的。模型审核时拿到方向
  （源 workspace、环境、路径 → 目的 workspace、环境、路径），可做语义判断。
  同环境内与跨环境传输由 workspace 所属环境区分（见 ADR-0003）。
- **进程环境**：子进程不继承 Server 自身的环境，只带一份显式构造的最小环境（PATH、HOME 等）；
  做法参考 Codex"启动前清空环境，再显式重建"。对远程环境，只管我们注入的部分。
  凭据一律不经环境变量传递，使用占位符引用，见 ADR-0007。
- 模式（如 plan）的限制是上限，档位不能越过它：模式管能不能做，档位管做之前要不要批。
- sudo 提权与密码的使用不归三档管，见 ADR-0007。子 agent 的权限继承见 ADR-0010。
- 借鉴 Codex 的代码按 Apache-2.0 署名：附许可证副本，NOTICE 注明来源，标注修改过的文件。

## 理由
- 规则是廉价的底线，模型审批覆盖规则外的长尾，人只处理例外。
- "通过并记住"让决策疲劳随使用逐渐消失。
- 超时与出错都不放行，避免 Codex 与 Claude 都踩过的"超时当通过"。
- 没有沙箱，所以规则外默认弹审批而不是放行。
- 在 workspace 内不等于安全：凭据类文件是典型例外，所以敏感路径不吃 cwd 放行。

## 影响
- 需要实现规则引擎（配置用 JSON，匹配与合并为纯函数），可参考 Codex 的 execpolicy 设计。
- bash 解析用 tree-sitter-bash 一类，只放行纯词命令的连接。
- 自动模式的审核方使用单独配置的模型（ADR-0015）。其设计参考 Codex 的 guardian
  （Apache-2.0，署名同上）：
  - 独立的审核会话，策略在系统消息，待审内容拆成对话记录和待审动作的完整文本两段；
  - 只有用户消息、项目约定（AGENTS.md）、用户对弹窗和提问的回答是可信证据；
    工具输出、助手输出、skill 与 MCP 说明视为不可信，其中试图改规则或强行批准的内容一律忽略；
  - 对话记录超预算时截断并留标记，审核方遇标记须更谨慎；
  - 输出严格 JSON：低风险直接放行，其余给风险等级、授权程度、放行或拒绝、理由；
  - 策略分通用评分规则和具体策略模板（外传、探测凭据、削弱安全设置、破坏性操作），用户可追加；
  - 审核方看到的是带占位符的命令（ADR-0007），看不到密码值；
  - 审核方是否可用只读工具补查上下文，实现时定。
- **输出脱敏不在基建内。** 脱敏错了会丢信息，规则集需要慎重设计。
  基建只在工具结果进入会话的路径上预留一个默认空操作的变换槽位，
  不预设规则集，也不向基线提示词写入脱敏相关内容。
  日后实现时，须在结果写入会话记录和推给客户端之前生效，且需要可关闭、可审视。
- MCP 工具调用走哪一档、`switch_workspace` 按哪个 workspace 的档位判，待定。
- 排除：自研沙箱；用规则穷举判断命令危险；基建内做输出脱敏。
