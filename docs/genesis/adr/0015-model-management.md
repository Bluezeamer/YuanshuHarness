# ADR-0015: 模型管理：跟随 agent 定义，会话内手动切换

状态：已定稿
日期：2026-10-16
可逆性：易逆
取代：无
被取代：——
引用入口：VISION「做什么」第 7 条、「不做什么」第 8 条；ARCHITECTURE「系统组成」

## 背景
调研、审计等任务希望用不同的模型，甚至不同的供应商，在效率和质量之间取平衡。
非主流供应商的模型接入，现在要手写配置文件，过于繁琐。
主流接口协议只有三种：openai、openai-responses、anthropic-messages。

## 候选方案
### 方案 A：会话内虚拟模型路由
同一个会话里按任务类型临时换模型。代价：缓存前缀被打断，不同供应商之间的上下文格式需要转换。
### 方案 B：模型跟随 agent 定义，任务分派靠 subagent
不同任务交给不同的 agent，各自带模型。代价：需要预先定义这些 agent。

## 决定
方案 B。
- **模型是 agent 定义的一部分**：供应商、模型、默认推理强度。
- 调研、审计这类任务用不同模型，靠 spawn 另一个 agent 实现（ADR-0010），父可覆盖模型。
- **会话内可手动切换模型与推理强度**，只在空闲时，只影响当前会话，不写回 agent 定义；
  新会话始终用 agent 定义的默认值。切换只能由用户做，agent 不能自行切换。
- **调用失败不自动降级**：瞬时错误交给 pi 自带的重试；重试仍失败，任务暂停，
  所有客户端收到明确的错误提示，由用户决定换模型继续还是放弃，会话本身不丢。
- **自动模式使用的审核模型单独配置**（供应商、模型、推理强度），不与会话模型绑定，
  可选用较小较便宜的模型（审核的设计见 ADR-0006）。
- **接入向导**：WebUI 里选协议（三种主流协议），填地址、密钥、模型 ID 与能力项
  （上下文长度、是否支持图片与推理等），带"测试连接"，保存前先发一次真实请求。
  产物是 pi SDK 能直接读的配置，不另造格式。API key 存进密码库（ADR-0007），配置里只引用。
  配置放在 Server 的数据目录，不读取机器上已有的 pi 配置（ADR-0001）。

## 理由
- 模型跟着 agent 走，完全落在已有概念上，没有新机制。
- 调研、审计本来就是边界清晰的独立任务，适合单独 agent，上下文也不会污染主对话。
- 自动换模型会悄悄改变质量和成本，不同供应商间的上下文格式也有转换风险。
- 自造配置格式会让我们永远追着 SDK 的配置变更跑。
- 审核是高频、结构固定的小任务，单独配置便宜的模型，可以降低自动模式的成本和延迟。

## 影响
- 切换模型时缓存前缀失效（不同模型各自独立缓存），无法避免，不做特殊处理。
- S0 需验证：配置能否引用密码库而不是写明文 key；SDK 能否指定配置路径。
- 以后真有需要，可在 agent 定义里加"备用模型"，现在不预留。
- 排除：会话内模型路由；自动降级；自造模型配置格式。
