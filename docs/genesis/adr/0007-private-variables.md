# ADR-0007: 隐私变量：占位符引用，Server 持有并替换

状态：已定稿
日期：2026-10-16
可逆性：难逆
取代：无
被取代：——
引用入口：ARCHITECTURE「边界与约定」；VISION「做什么」第 4 条

## 背景
agent 需要用到密码、token、ssh 密钥，但这些值不应让模型看到。
环境变量可以被直接打印，所以"放进环境变量再要求 agent 自觉"不构成围栏。
sudo 的使用既涉及密码，也涉及"拿到全部权限"这类风险。

## 候选方案
### 方案 A：环境变量注入
把凭据放进子进程环境。代价：能被 env 或 printenv 直接读出，Codex 的做法是按变量名过滤，
名字不规范就漏。
### 方案 B：占位符引用，Server 替换
命令里写 `@var_name`，Server 在审批通过之后、启动进程之前替换为真值。
agent 的上下文、会话记录、环境里都没有真值。
### 方案 C：出口网关补凭据
子进程拿假值，出站流量经 Server 自带的代理，按目的地址换成真值。最强，
但需要自带网络代理，本项目不做。

## 决定
方案 B。
- **提示词里列出可用的隐私变量**：名字、用途、适用范围，不含值。
- **替换发生在审批之后**：审批看到的是带占位符的命令，批准的就是这条文本，
  替换只是启动进程前的最后一步。
- **单命令注入**：真值只在启动那一条命令的进程时给它，不放进会话环境，用完即走。
- **授权级别挂在每个密码上**，与 workspace 的档位无关。登记时设两样：
  适用范围（如 GitLab token 只用于访问某个域名，sudo 密码只用于 sudo），
  和档位（规则审批 / 自动模式 / 完全允许，默认规则审批）。
  命令用到某个密码，就按这个密码的档位走，包括 workspace 是"完全允许"的情况。
  自动模式下，模型只看得到密码名字、适用范围和完整命令，永远看不到值。
- 带密码的命令"通过并记住"，规则必须带上目标地址或参数，不能只记命令前缀；
  解释器前缀照旧不允许被记住。
- **输出回显**：工具结果（命令输出、读出的文件内容）中出现的密码库已知真值，
  在写入会话记录和推给 agent 与客户端之前，精确替换回占位符。
  只匹配库里已有的值，是确定性匹配，不是启发式脱敏，不属于 ADR-0006 排除的"输出脱敏"。
- **录入密码是输入类弹窗**，只在 WebUI 进行。
- **sudo**：
  - 优先走免密配置：由 agent 提议一批相对安全的命令，经人工审批后写入
    `/etc/sudoers.d/` 下的单独文件，并用 `visudo -c` 校验；模型不能批这一步；
    弹窗展示完整内容，警惕 vi、find、tar、docker 这类能开 shell 的程序。
  - 拦截器用 `sudo -n -l <命令>` 向 sudo 查询是免密可用、需要密码还是不允许，
    不自己穷举；认不出的复杂写法当需要人工审批。
  - 免密命令按 workspace 档位走；需要密码的按那个密码的档位走。
  - `sudo -s`、`su`、`sudo bash` 这类直接开 root shell 的，始终人工审批，任何档位下都一样。
- 密码库是 Server 级加密存储，ssh 连接用的凭据也放在同一个库。

## 理由
- 物理围栏：真值只在 Server 手里，不靠 agent 自觉。
- 密码是有限、可穷举的，按密码设授权，比按命令猜测风险可靠。
- 免密配置把"用密码"的问题变成"配一次、批一次"，之后不再涉及密码。

## 影响
- 需要：隐私变量库、占位符解析、授权档位与适用范围、单进程注入、输出回显替换。
- 加密方式、密钥存放、占位符语法，留给实现设计。
- 真值经 ssh 到远程进程时，避免出现在命令行（`ps` 可见），优先走标准输入或仅对该进程的临时环境，
  细节留给实现。
- 输出回显替换与 ADR-0006 预留的变换槽位在同一位置，但属于隐私变量机制，不是脱敏规则集。
- 保证的是"已知真值的原文不出现"，不是"信息不泄露"：编码后回显（base64、URL 编码等）匹配不到，
  是已知局限。登记时对过短的值校验最小长度，避免误伤普通文本，
  Codex 的凭据代理用的最小长度是 16，可参考。
- `sudo -n -l` 的缓存与跨系统输出差异，需要在 Linux 与 macOS 上实测。
- MCP 所需的密钥怎么注入，待定。
- 排除：把凭据放进会话环境；出口网关补凭据（本期不做）。
