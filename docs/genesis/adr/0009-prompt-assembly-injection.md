# ADR-0009: 提示词组装与会话中途注入

状态：已定稿
日期：2026-10-16
可逆性：难逆
取代：无
被取代：——
引用入口：VISION「做什么」第 5 条；ARCHITECTURE「数据流」与「边界与约定」

## 背景
模型看到的提示词由多个来源拼成：角色定义、全局约定、项目约定。
会话中途还会发生模型需要感知的变化：切换 workspace、切换模式、能力增减。
多数供应商按前缀命中缓存，随意改动前面的内容会让缓存失效。

## 候选方案
### 方案 A：每次请求重新组装整段提示词
实现直观。代价：任何变化都改变前缀，缓存频繁失效。
### 方案 B：创建时组装一次，中途变化在末尾附加，compaction 时重建基线
前缀稳定。代价：需要明确的通知格式，且依赖 pi 允许在压缩后追加系统提示词。
### 方案 C：靠增删工具定义传达变化
代价：工具定义通常在缓存前缀里，且各供应商支持不一。

## 决定
方案 B。

**组装：**
- 提示词按**分组**拼接，至少三组，可加自定义分组：
  角色定义（块，Server 管理）、全局约定（Server 级 AGENTS.md）、
  项目约定（workspace 里的 AGENTS.md，建 workspace 时选择是否注入）。
- 项目级 AGENTS.md 保持通用格式，Server 只读不改；远程 workspace 经环境的读文件原语读取。
- 块带"维度"标签；agent 定义是块的有序引用列表。**本期只做列表组合**，不做节点连线图；
  拼装是 Server 上的纯函数，可实时预览。
- 块被 agent 引用，不复制。会话创建时记下拼好的版本；块更新后，已有会话在下一次 compaction
  时才换新版本。另提供"立即同步"，可选全部会话或单个会话，代价是破坏前缀缓存，只在会话空闲时生效。

**中途注入：**
- 会话中途 agent 需要感知的变化，**统一走一条路径**：有原生延迟加载就用，否则在上下文末尾附加
  通知，不改前面的内容。工具列表保持稳定，能力经预先注册的冻结入口访问；
  具体走哪条由模型的能力标志位决定。
- 新会话的基线直接写进上下文；compaction 之后，是重新注入的好时机：把环境、模式、能力的完整
  当前状态写在系统提示词末尾、压缩摘要之前，仍可享受前缀命中。
- 尾部通知覆盖：切换 workspace（含该 workspace 新增的 skill 清单）、切换模式
  （列出被限制或新增的能力）、其他能力增减。通知有固定格式，客户端识别后显示为一条系统行。
- 切换模型不需要通知。"立即同步"不发通知，直接重建基线。

**模式：**
- 模式是会话里叠加的临时状态，等于"模式提示词 + 能力范围的限定（可减可加）"。
  预设 build 与 plan 两个，允许用户自定义。
- 实现：尾部注入当前状态提示，**工具定义不动**，不允许的调用在执行层拦截并告知
  "当前模式下不可用"。opencode 的 plan 模式源码印证了这一做法。
- 模式只在空闲时由用户切换，agent 不能自行切换。模式限制是上限，权限档位不能越过它（ADR-0006）。

## 理由
- 保护前缀缓存：长会话里缓存命中直接决定成本与速度。
- 工具与 MCP 的限制放在执行层，才能保证"物理上不可调用"，不依赖模型自觉。
- 块被引用而非复制，才能"改一处、处处生效"，与能力集的集中管理同一思路。

## 影响
- S0 需验证：压缩后能否在系统提示词末尾追加；`supportsMidConvoSystemMessages` 与
  `supportsMidConvoToolChanges` 的实际行为；pi 自身读取 AGENTS.md 时如何接管、避免重复注入。
- skill 无法在执行层彻底拦截，只能做到提示加拦截读取。
- 子 agent 用同一套组装规则（ADR-0010）。
- 排除：每次请求重建提示词；agent 自行切换模式；本期的节点连线编辑。
