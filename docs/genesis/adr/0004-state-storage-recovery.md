# ADR-0004: 状态存储与恢复边界

状态：已定稿
日期：2026-10-16
可逆性：难逆
取代：无
被取代：——
引用入口：ARCHITECTURE「技术选型」存储一行与「边界与约定」；VISION「不做什么」第 6 条

## 背景
Server 要持久化两类东西：对话记录，以及自己的状态（会话索引、环境与 workspace 登记、
规则、待处理审批队列、密码库、能力清单、父子关系）。
pi 的会话记录是 JSONL，每条消息结束时追加写，没有文件锁；其压缩、分支、导出都建立在该格式上。
还要界定 Server 重启或崩溃后能恢复到什么程度。
调研得知 pi 的 Durable 为实验性质，缺审批机制与网络层，与现有扩展不兼容（未实测）。

## 候选方案
### 方案 A：全部进 SQLite
统一存储。代价：对话记录脱离 pi 的 JSONL，压缩、分支、导出等能力要自己重做。
### 方案 B：对话记录沿用 JSONL，Server 状态放 SQLite
各取所长。代价：两种存储，需要在应用层保持一致。
### 方案 C：全部文件化
无需数据库。代价：没有事务，父子关系的双向查询和规则索引难做。

恢复边界的候选：
### 边界 1：只保证对话历史不丢
被打断的工具调用由 agent 自己感知后决定是否重做。
### 边界 2：任务级续跑
借助 Durable 一类组件让任务接着跑。代价：复杂，依赖实验性组件，与审批和扩展不兼容。

## 决定
方案 B 加边界 1。
- 对话记录沿用 pi 的 JSONL；Server 状态放一个 SQLite 文件。
- 只有 Server 一个进程写会话文件，不允许同时用 pi 命令行操作同一会话。
- 子会话的 JSONL 放在专门目录，与用户级会话分开；父子关系记在 SQLite，双向可查。
- Server 重启时被打断的工具调用，agent 收到"上次被中断"的提示，自行决定是否重做。
- 所有状态集中在一个数据目录。

## 理由
- pi 的功能建立在 JSONL 之上，保留格式就保留了这些能力。
- SQLite 单文件、事务可靠，单用户的规模绰绰有余。
- pi 追加写无锁，靠"唯一写入者"规避写坏。
- 由 agent 自己感知并恢复，比框架替它续跑更稳健，也不依赖实验性组件。

## 影响
- S0 需验证：从 JSONL 加载会话的接口；压缩后能否在系统提示词末尾追加内容。
- pi 命令行不能与 Server 同时操作同一会话。
- 会话列表默认只列用户级会话，子会话只出现在拓扑图里。
- 排除：以 Durable 为核心依赖；任务级 checkpoint；多写入者集群。
