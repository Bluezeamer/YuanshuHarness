# ADR-0080：Web 预览 Pane 直接嵌 iframe，不做反向代理

**作者**：bluezeamer
**状态**：Accepted
**日期**：2026-10-20

## 背景

ROADMAP 第 12 条要求 WebUI 有「内置浏览器」。最直接的做法是 `<iframe>`，但对方可以用 `X-Frame-Options` 或 CSP `frame-ancestors` 拒绝被嵌入。调研（`tmp/pi/browser-embed.md`）给了两条路：Server 端反向代理剥掉这两个响应头，或者用无头浏览器截屏流。本条决定预览 pane 走哪条，截屏流单独见 ADR-0081。

## 决策

**直接嵌 iframe，不做 Server 端反向代理。** 被拒绝时给明确提示和「在新标签打开」兜底。

不做代理的理由：

- 代理要改写响应头、转发 WebSocket 升级、处理路径前缀或子域名，并且按调研只对 SSH 环境好用。Server 本机的页面和 `localhost` 服务它帮不上。
- 代理是个以 Server 身份发请求的出口。单用户令牌能挡住外人，但挡不住「令牌内的人让它去探测 Server 所在内网」，要防就得自己写一套回环、内网地址过滤，而这类过滤有 DNS 重绑定、重定向、IPv6 等绕法，维护成本远高于这个 pane 的价值。
- 预览是「看一眼」的场景。要让 agent 在页面里操作，走侧边浏览器。

**失败如何呈现**。跨源 iframe 读不到加载结果，所以不假装能判定「被拒绝」，只展示两类可观察的信号：

- 页面 `load` 之后常驻一条淡提示：页面空白或提示拒绝连接，可能是对方禁止被嵌入。
- 超过 `SLOW_MS`（8 秒）还没 `load`，提示升级为警告色：地址可能连不上，或对方禁止嵌入。
- 两条提示和地址栏旁的图标都带「在新标签打开」，用 `noopener noreferrer`。

**外壳**。地址栏、后退、前进、刷新、加载中的滑动细条。后退和前进只记地址栏发起的跳转，跨源页面内部的点击在外层看不到，不假装能回退。地址被外部改掉（恢复布局、别处打开）时历史从新地址重新开始。

**划选提问接口位**。pane 接受可选的 `onSelection({text, url})`。同源页面能读到选区时才回调，跨源读不到，不会触发。m2-interact 分支接这个口，本条不实现提问本身。

## 后果

- 被拒绝嵌入的站点会显示空白，用户靠提示一键跳到新标签，没有静默失败。
- 不新增依赖，Server 不多出一个出口。
- 划选提问对跨源页面不可用，这是浏览器同源策略的限制。要在任意页面上选取内容，只能经侧边浏览器的快照。
